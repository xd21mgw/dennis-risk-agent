# KIM_ROUTING_GUARD_V1

This patch is intended for one of the following runtime-loaded locations:

- main agent route prompt
- `sessions_spawn` task prefix
- gateway `runtimePrompt`
- equivalent KIM / Dennis internal Agent startup prompt

It must be loaded before the agent decides whether to call tools.

## 1. ATO Expansion Must Be Plan Mode Only

Trigger phrases include:

- 有没有类似受害者
- 同类攻击是否批量发生
- 怎么扩展排查
- 举一返三
- 同一攻击模板是否还有更多账号
- 基于已确认 ATO case 找同类攻击链路或黑产基础设施

Required behavior:

- route: `plan_mode_only`
- execution_mode: false
- tools_called: false
- sso_session_runner_called: false
- DataAgent_called: false
- query_more_user_id: false
- auto_expand: false

Allowed output only:

- expansion anchors
- DataAgent / Hive query plan
- scope control
- manual review boundary
- `offline_hive_required=true`
- `DataAgent_plan_needed=true`

Forbidden:

- Do not call login logs.
- Do not call Archives Center.
- Do not call Weapon.
- Do not call Tianshi.
- Do not call frontend activity tools.
- Do not call browser tools.
- Do not call DataAgent or Hive.
- Do not query more users.
- Do not expand automatically.

## 3. Mixed Request Orchestration

If the user asks for multiple things in one prompt:

- ATO single-case judgement
- ATO expansion / similar victims / same attack batch check
- black_market_account_matrix follow-up

Do not treat the whole request as one execution task.
Do not pass the full mixed prompt to Dennis as one spawned execution task.
The main agent / KIM route layer must decompose the request before spawning.

Required output order:

### Step 1: Routing Summary

- ATO single case: execution mode, readonly only.
- ATO expansion: plan_mode_only, no tools.
- black_market_account_matrix: fast_ack / lightweight closure, no deep dive.

### Step 2: Main Agent Emits Plan / Fast-ack Before Execution

Output these before any long-running execution:

- ATO expansion concise DataAgent / Hive query plan.
- black_market_account_matrix lightweight closure / async acknowledgement.

These two parts must be generated by the main agent or injected as pre-output.
They must not depend on Dennis execution finishing.

### Step 3: Spawn Only ATO Single-case Concise Execution

- readonly only.
- concise evidence card.
- key chain summary only.
- Do not expand all logs in KIM response.
- Large log details stay internal observation.
- If time budget is tight, preserve Step 1 and Step 2 before execution details.

The spawned Dennis task prompt must include only the ATO single-case judgement slice.
It must not include the ATO expansion request or black_market_account_matrix follow-up.

## 4. Output Field Guard

Use `field_output_classification_policy_v1.md`:

- token / cookie / session / password / authorization / browser_storage_state_marker / auth header plaintext is P0 credential leakage and must never be output.
- IP / UID / DID / deviceId are risk entity fields, not credential secrets by default.
- KIM semi-open should avoid large raw detail export; use safe_ref / partial mask / count / distribution when audience scope is broad.
- `tokenId` is an event reference unless it exposes a reusable credential secret; default to `token_id_ref` or partial mask.

For KIM B/E/F validation, avoid outputting full IP in final user-facing text. Prefer subnet / masked / derived features.
