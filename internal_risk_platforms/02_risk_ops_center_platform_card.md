# 风险运营中心（风险分析平台 RAP）

## 1. 平台一句话定位

风险运营中心是风控深度分析平台，用于快速判断用户风险、查看风控数据摘要、举报分析、案例留存，并通过关联用户关系图谱做账号、设备、手机号、第三方登录、实名注册和 IP 的滚雪球扩量。

## 2. 平台能力边界

### 2.1 能查什么

- 用户基础数据、登录信息、设备信息、安装 APP 信息。
- 风控数据：判罚记录、当前负向、处置详情、策略详情、解封详情。
- 评论词云、搜索热词、社交数据、涨粉趋势、消费数据。
- 举报分析：举报量、举报类型分布、举报明细、举报人画像。
- 关联用户 Tab / 关系图谱：围绕目标用户展示设备、手机号、第三方登录、实名注册、IP 等多类型关联节点，并支持按字段明细继续筛选扩量。
- 关联账号：同设备、同手机号、同 IP、昵称/简介相似、社交关系、举报关系滚雪球。
- 案例留存和案例库。

### 2.2 不能查什么

- 不适合查登录 token、OAuth、扫码、高危接口等原始日志明细。
- 不适合查设备底层指纹、模拟器、刷机、APK 风险。
- 不适合配置、上线或熔断策略。
- 不适合替代 Hive 离线大盘。

### 2.3 应转向哪些平台

| 需求 | 应转向平台 |
|---|---|
| 全端登录 / token / OAuth / 高危接口 | 用户登录统一日志 |
| 设备底层、安装路径、硬件可信、设备关系图谱、用户扩散/设备扩散 | 设备攻防基建平台 |
| 策略配置、策略条件、特征值、熔断 | 天狮策略引擎 |
| 用户/内容原始档案和审核明细 | 档案中心 |
| 离线趋势、批量聚合 | DataAgent / Hive |

## 3. 典型查询对象

| 查询对象 | 输入方式 | 适用问题 | 注意事项 |
|---|---|---|---|
| 用户ID | 信息速查-用户 | 单用户综合风险研判 | 最常用入口 |
| 评论关键词 | 信息素材-评论 | 评论风险、导流、骚扰 | 需结合上下文 |
| 批量用户ID/视频ID | 批量负向检索 | 批量状态核验 | 结果是状态摘要 |
| 举报人/被举报人ID | 举报分析 | 举报归因、恶意举报、社交骚扰 | 举报不等于事实 |
| 相关用户ID | 关联用户 Tab | 从多个用户出发看共同设备、手机号、第三方登录、实名注册、IP | 支持多个 ID；关系强弱和口径需结合字段明细解释 |
| 设备ID | 关联账号-同设备 | 群控/号商/假量扩量 | 深度设备风险转设备攻防 |
| 手机号 | 关联账号-同手机号 | 号商、批量注册 | 权限和合规需确认 |
| IP地址 | 关联账号-同IP | IP 聚集、代理池、批量行为 | 噪声大，需反证 |

## 5. 核心字段字典

| 字段名 | 页面展示名 | 含义 | 风控解释 | 适用场景 | 可信度/注意事项 |
|---|---|---|---|---|---|
| user_id | 用户ID | 用户唯一标识 | 主锚点 | 全场景 | 高可信 |
| installed_apps | 安装APP列表 | 设备安装应用 | 灰产 APP、境外 APP、群控工具线索 | 账号安全、群控、协议上号 | APP 名称需包名校验 |
| punish_history | 判罚记录 | 历史处罚 | 惯犯、重复风险 | 全场景 | 处罚不等于最终事实 |
| current_risk_status | 当前负向 | 当前处罚状态 | 是否处置中 | 全场景 | 需看处置原因 |
| punish_detail | 处置详情 | 单次处罚明细 | 精细分析处罚原因 | 策略误伤、内容风险 | 需与天狮核对 |
| strategy_detail | 策略详情 | 命中策略摘要 | 回溯策略命中原因 | 策略归因、误伤 | 摘要不等于完整策略配置 |
| unseal_detail | 解封详情 | 解封记录 | 反复解封、误伤线索 | 策略误伤、账号安全 | 需看解封原因 |
| comment_word_cloud | 评论词云 | 高频评论关键词 | 导流、骚扰、内容风险模式 | 内容风险、社交骚扰 | 词云只能作线索 |
| search_hot_words | 搜索热词 | 高频搜索关键词 | 敏感词、意图线索 | 内容风险 | 不能单独定性 |
| fans_trend | 涨粉趋势 | 粉丝变化曲线 | 假量、裂变、刷粉 | 假量/裂变、流量反作弊 | 需后验质量 |
| report_count | 被举报量 | 举报次数 | 大量举报提示风险或争议 | 内容风险、社交骚扰 | 举报可被操纵 |
| report_type_distribution | 举报类型分布 | 举报类型占比 | 集中类型提示风险方向 | 内容风险 | 需明细证据 |
| relation_node_type | 关系图谱节点类型 | 设备、手机号、第三方登录、实名注册、IP 等节点类型 | 解释关联来源和关系强弱 | 群控、号商、账号安全、设备扩量 | 节点类型不是同伙结论 |
| related_user_id | 关联用户 | 与目标用户存在某类节点关系的用户 | 扩量和核验候选 | 群控、号商、假量、社交骚扰 | 需看关联路径和风险标签 |
| related_user_count | 关联用户数 | 某设备/手机号/IP等节点关联的用户数量 | 大量关联提示设备/资源复用 | 群控、号商、假量 | 大数量可能来自公共资源或口径噪声 |
| user_label_aggregation | 用户标签聚合 | 关联用户风险/业务标签聚合 | 判断关联用户群体画像 | 群控、号商、账号安全、内容风险 | 标签聚合只能作为画像线索 |
| device_label | 设备标签 | 设备状态或风险标签，如正常/封禁等页面展示 | 解释设备节点风险 | 设备风险、群控、账号安全 | 标签口径需确认 |
| last_relation_time | 最后一次关联时间 | 关联关系最近出现时间 | 判断关系是否近期有效 | 扩量、复盘、误伤核验 | 时间口径需确认 |
| related_accounts | 关联账号 | 设备/IP/手机号等关联列表 | 滚雪球扩量 | 群控、号商、假量 | 关联不等于同伙 |
| mark_code | 风控标注 | 风险分类编码 | 风险分类线索 | 全场景 | 需字典解释 |

## 6. 通用适用场景

- ATO / 账号安全：适用。查安装 APP、历史判罚、策略摘要、解封和关联用户关系图谱，ATO 是账号安全典型用例之一。
- 群控 / 号商：适用。通过关联用户关系图谱和字段明细做同设备/手机号/IP/第三方登录/实名注册扩量，再转设备平台看设备图谱。
- 协议上号：部分适用。看安装 APP、判罚、策略摘要；原始登录链路转用户登录统一日志。
- 反爬 / 资产抓取：部分适用。可看账号画像和关联扩量；资产访问链路需其他平台或 DataAgent/Hive。
- 内容风险：适用。评论、搜索、举报、处置详情。
- 假量 / 裂变：适用。涨粉趋势、社交数据、关联账号、后验线索。
- 社交骚扰：适用。举报、评论、社交数据。
- 策略误伤 / 策略归因：部分适用。可看策略摘要和解封，完整归因转天狮。

## 8. 典型查询路径

### 8.1 单用户综合风险研判

- 输入：user_id
- 查询模块：信息速查-用户 → 基础数据 → 风控数据 → 社交数据
- 关键字段：installed_apps, punish_history, current_risk_status, strategy_detail, fans_trend
- 输出结论：用户是否有历史风险、当前负向、策略摘要、社交异常
- 下一步平台：天狮查策略条件；档案中心查原始审核事实；用户登录统一日志查登录链路

### 8.2 群控 / 号商扩量

- 输入：user_id / device_id / phone_number / ip
- 查询模块：关联用户 → 关系图谱 → 字段明细（设备 / 手机号 / 第三方登录 / 实名注册 / IP）
- 关键字段：relation_node_type, related_user_count, user_label_aggregation, device_label, last_relation_time
- 输出结论：关联来源、关联规模、负向标签聚合、可疑扩量候选
- 下一步平台：设备攻防查设备关系图谱、用户扩散和设备扩散；档案中心批量核验账号事实

### 8.3 举报 / 社交骚扰分析

- 输入：被举报 user_id 或举报人 user_id
- 查询模块：举报分析 → 举报概览 → 举报明细 → 举报人画像
- 关键字段：report_count, report_type_distribution, report_detail
- 输出结论：被举报风险方向、是否存在恶意举报或批量举报
- 下一步平台：档案中心查内容/评论事实；天狮查处置策略

### 8.4 关联网络 → 设备平台图谱联动

- 输入：RAP 关联用户图谱中的高关联设备 / 设备ID / 高风险用户簇
- 查询模块：关联用户关系图谱 → 字段明细筛选 → 设备攻防基建平台关联图谱
- 关键字段：device_label, related_user_count, user_label_aggregation, last_relation_time
- 输出结论：RAP 给出用户侧扩量候选，设备平台进一步验证设备可信、用户扩散、设备扩散和网络扩散
- 下一步平台：设备攻防基建平台；必要时 DataAgent/Hive 做批量聚合验证

## 9. Agent 路由规则

- 需要“比档案中心更深”的用户风险画像、关联扩量、举报分析时，路由到风险运营中心。
- 问题包含“滚雪球 / 关联用户 / 关系图谱 / 关联账号 / 举报分析 / 策略详情摘要 / 解封详情 / 安装 APP”时优先查 RAP。
- 问题包含“用户扩散 / 设备扩散 / 设备图谱 / 设备可信”时，RAP 可先看用户侧关联网络，但必须转设备攻防基建平台做设备侧图谱核验。
- 如果用户问“策略条件是什么 / 特征值是多少”，RAP 只能做摘要，应转天狮。
- 如果用户问“登录 token / OAuth / 扫码”，应转用户登录统一日志。

## 10. Agent 解释规则

- 安装灰产 APP 是风险线索，不等于用户一定作恶；需结合操作链路和行为。
- 策略详情摘要只能说明命中过某类策略，不能替代完整策略归因。
- 关联用户关系图谱用于扩量和解释关联来源，不应把所有关联用户直接判为同伙。
- 关系图谱中的设备、手机号、第三方登录、实名注册、IP 节点代表关联路径；节点越多不等于风险越高，仍需看关联用户标签聚合、最后关联时间、设备可信和行为事实。
- `设备标签=封禁` 或关联用户中有大量负向标签，是扩量优先级线索，不是单独定性依据。
- 高举报量可能来自真实风险，也可能来自恶意举报，需要看举报人画像和证据。
- 涨粉异常需结合来源、后验质量和内容链路，不能单独定性假量。
