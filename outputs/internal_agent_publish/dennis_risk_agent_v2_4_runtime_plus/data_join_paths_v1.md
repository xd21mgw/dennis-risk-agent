# Data Join Paths v1

## 0. 目标

本文件定义 Dennis 风控 Agent 常用的抽象 join 路径。这里不写真实表名、真实字段名、真实 join key，只描述实体关系、使用目的和误读风险。

真实 join key、表名、字段名、权限和性能由未来内部平台补充。

## 1. frontend_backend_chain_join

- 关联目标：前端行为域 ↔ 后端数据域
- 关联实体：用户、设备、会话、业务动作、时间窗口
- 主要用途：前后端链路一致性、协议排查、埋点缺失排查
- 期望输出：前端事件是否能解释后端请求、请求前是否有合理页面/事件链路
- 质量风险：前端丢点、延迟、埋点缺失、session 口径不一致
- 不能直接下结论：前端无日志不等于协议

## 2. request_device_environment_join

- 关联目标：后端数据域 ↔ 设备信息域
- 关联实体：请求、设备、IP、UA、实时指纹、SDK 信号
- 主要用途：协议、token 复用、破解包、设备风险
- 期望输出：请求环境是否和设备/SDK/指纹一致
- 质量风险：实时指纹和异步 SDK 时效不同，设备画像可能延迟
- 不能直接下结论：设备环境异常不能单独证明作恶

## 3. account_lifecycle_device_join

- 关联目标：用户信息域 ↔ 设备信息域
- 关联实体：账号、登录、设备、IP、UA、换绑/找回/改密
- 主要用途：ATO、token 泄露、账号接管、交易号、小号
- 期望输出：账号控制权变化前后是否发生设备/环境突变
- 质量风险：正常换机、漫游、企业网络、多设备登录
- 不能直接下结论：生命周期变化需结合敏感动作和验证链路

## 4. token_session_environment_join

- 关联目标：用户信息域 ↔ 后端数据域 ↔ 设备信息域
- 关联实体：token、session、设备、IP、UA、登录事件、请求
- 主要用途：token 泄露、登录态复用、协议请求
- 期望输出：token 使用环境是否与登录迁移/验证链路一致
- 质量风险：token 生命周期、刷新机制、多端登录策略差异
- 不能直接下结论：IP/UA 变化不等于 token 泄露

## 5. activity_participation_device_reward_join

- 关联目标：活动信息域 ↔ 设备信息域 ↔ 用户信息域
- 关联实体：活动、用户、账号、设备、任务、奖励、提现
- 主要用途：活动黑产、活动低质、真人众包、群控抢奖励
- 期望输出：活动参与路径、设备/账号团组、奖励/提现聚集、后验质量
- 质量风险：活动规则导致路径相似，低钱效不等于黑产
- 不能直接下结论：奖励多或低质不能单独定黑产

## 6. invite_relation_network_join

- 关联目标：活动信息域 ↔ 关联网络域
- 关联实体：邀请人、被邀请人、账号、设备、关系边
- 主要用途：邀请作弊、裂变作弊、小号团组、活动套利
- 期望输出：邀请关系是否形成异常团组或收益聚集
- 质量风险：正常社交邀请、达人传播、活动自然裂变
- 不能直接下结论：邀请关系异常需结合设备、收益和后验质量

## 7. channel_click_activation_user_join

- 关联目标：渠道信息域 ↔ 用户信息域 ↔ 设备信息域
- 关联实体：曝光、点击、激活、新客、设备、渠道、媒体
- 主要用途：渠道抢量、点击注入、归因劫持、老客冒充新客
- 期望输出：曝光-点击-激活链路、CTIT、新客真实性、老设备/老账号
- 质量风险：预算、活动、版本、归因窗口、媒体策略变化
- 不能直接下结论：CTIT 异常不能单独判渠道作弊

## 8. channel_quality_aftereffect_join

- 关联目标：渠道信息域 ↔ 用户信息域 ↔ 活动信息域
- 关联实体：渠道、新客、回流、留存、付费、复访、活动
- 主要用途：渠道质量评估、抢量反证、低质治理
- 期望输出：渠道用户后验质量和业务价值
- 质量风险：新客培育周期、活动目标、冷启动策略
- 不能直接下结论：后验质量差不等于渠道作弊

## 9. asset_access_device_network_join

- 关联目标：前端行为域 ↔ 后端数据域 ↔ 设备信息域 ↔ 关联网络域
- 关联实体：资产、接口、页面、设备、账号、IP、团组
- 主要用途：反爬资产泄漏、真机爬取、内容/价格/库存访问异常
- 期望输出：资产访问路径、访问主体聚集、设备/账号/IP 团组
- 质量风险：前端公开信息、缓存、合作方同步、内部导出
- 不能直接下结论：外网跟价不等于内部接口被爬

## 10. diversion_exposure_touch_offsite_join

- 关联目标：前端行为域 ↔ 用户信息域 ↔ 关联网络域 ↔ 风险画像域
- 关联实体：目标用户、信息暴露入口、搜索、关注、私信、触达账号、站外承接线索
- 主要用途：直播间截流、站外添加、私信导流、账号矩阵
- 期望输出：目标获取 -> 触达 -> 站外承接链路
- 质量风险：正常社交、普通关注、用户主动外联、授权运营触达
- 不能直接下结论：私信/关注异常不等于导流黑产

## 11. strategy_decision_outcome_join

- 关联目标：策略引擎域 ↔ 用户信息域 ↔ 前端行为域 ↔ 后端数据域
- 关联实体：策略命中、决策、处置、用户行为、业务结果
- 主要用途：策略效果评估、误伤复盘、灰度验证、回滚判断
- 期望输出：策略命中与处置后风险/业务结果的关系
- 质量风险：策略命中不等于风险事实，灰度/对照口径需确认
- 不能直接下结论：只有策略命中量不能证明策略有效

## 12. risk_profile_behavior_outcome_join

- 关联目标：风险画像域 ↔ 前端行为域 ↔ 后端数据域 ↔ 活动信息域
- 关联实体：风险标签、账号/设备、人群、行为、活动结果、后验质量
- 主要用途：风险分层、样本筛选、策略解释、低质/黑产区分
- 期望输出：风险画像与实际行为/后验结果是否一致
- 质量风险：风险画像可能是模型推断或策略结果
- 不能直接下结论：风险画像不等于事实标签

## 13. batch_case_resource_reuse_join

- 关联目标：case 样本 ↔ 用户信息域 ↔ 设备信息域 ↔ 关联网络域
- 关联实体：case、账号、设备、IP、UA、token、客户端包、团组
- 主要用途：批量 case 找资源共性、同源判断
- 期望输出：跨 case 资源复用图、团组稳定性
- 质量风险：公共网络、企业网络、合法矩阵、同版本发布
- 不能直接下结论：资源共性需结合行为/链路/收益共性

## 14. batch_case_business_context_join

- 关联目标：case 样本 ↔ 活动信息域 ↔ 渠道信息域 ↔ 策略引擎域
- 关联实体：case、活动、渠道、实验、版本、策略、业务日历
- 主要用途：批量 case 反证排除，判断是否不同源同机制
- 期望输出：同一活动、版本、实验、渠道或策略变更是否解释多个 case
- 质量风险：业务上下文缺失时容易误判同源
- 不能直接下结论：业务共性更强时应降级为同机制问题

## 15. legal_operation_matrix_authorization_join

- 关联目标：用户信息域 ↔ 后端数据域 ↔ 策略引擎域 ↔ 关联网络域 ↔ 风险画像域
- 关联实体：授权主体、账号范围、工具来源、操作人、调用接口、敏感动作、收益主体、历史违规、审计链路
- 主要用途：合法矩阵、商家/达人/MCN/机构批量运营、授权工具、客服/运营代管、局部超范围违规判断
- 期望输出：批量行为是否在授权主体、账号范围、工具来源、操作目的和敏感动作边界内；若超范围，定位局部账号、工具、接口、操作人或收益主体
- 质量风险：授权信息缺失、操作人不可追溯、工具来源不明、收益主体不清、历史违规口径不完整
- 不能直接下结论：只有批量登录、批量接口调用或多账号代管，不能直接判群控/协议；有授权也不能放过导流、欺诈、支付、结算等局部风险

## 16. metric_anomaly_business_context_join

- join 目标：metric_timeseries ↔ business_event ↔ channel_change ↔ experiment_change ↔ strategy_change ↔ product_release ↔ data_quality_issue ↔ user_segment ↔ traffic_source
- 适用风险：DAU/DNU 异常、转化率异常、留存异常、支付异常、活动效果异常、策略效果异常、渠道质量异常、指标口径异常、疑似流量作弊但缺攻击证据的场景
- 需要的数据域：用户信息域、前端行为域、后端数据域、活动信息域、渠道信息域、策略引擎域；可选设备信息域、风险画像域、关联网络域
- 常见 join key 类型：指标语义、时间窗口、业务场景、用户分群、流量来源、渠道语义、活动语义、实验语义、策略语义、版本/发布语义、数据质量问题语义
- 推荐时间窗口：至少包含异常观测窗口、异常前历史基线窗口、业务事件发生窗口、策略/实验/版本变更窗口；单日波动应补充周同比、环比或同类业务对照窗口
- 可能的 join 风险：指标口径变化、数据延迟、SLA 异常、采样变化、前后端统计口径不一致、渠道归因窗口变化、实验分流不均、版本发布灰度、活动目标变化、策略处置影响、用户分群漂移
- 不能直接下结论的情况：单日 DAU/DNU 波动不能直接等同作弊；转化率、留存、支付或活动效果异常不能直接等同黑产；只有策略命中量或风险画像变化不能证明风险真实发生；缺少业务上下文时，不能直接定性黑产或作弊
- 数据缺失时的降级规则：业务上下文缺失时，只能输出“指标异常待归因”；若渠道、活动、实验、版本、策略、数据质量、用户分群和流量来源均无法解释，再进入风险证据补证路径，如 `channel_attribution_hijacking_check`、`activity_black_industry_or_low_quality_check`、`protocol_frontend_backend_join`、`group_control_dispatch_check` 或 `strategy_effect_and_false_positive_review`

## 17. 使用规则

- query_intent 至少应选择一个 join path。
- 涉及强结论时，应至少包含一个风险链路 join 和一个反证 join。
- 涉及批量 case 时，应同时考虑 `batch_case_resource_reuse_join` 和 `batch_case_business_context_join`。
- 涉及商家、达人、MCN、机构、客服、授权工具或接口化运营时，应优先使用 `legal_operation_matrix_authorization_join`。
- 涉及策略效果时，必须使用 `strategy_decision_outcome_join` 或同等语义。
- 涉及 DAU/DNU、转化率、留存、支付、活动效果、策略效果等指标异常时，应优先使用 `metric_anomaly_business_context_join` 排查渠道、活动、实验、版本、策略、数据质量、用户分群和流量来源变化；业务上下文无法解释时，再进入具体风险证据补证。
- 任何 join path 都不能替代最终风险结论。
