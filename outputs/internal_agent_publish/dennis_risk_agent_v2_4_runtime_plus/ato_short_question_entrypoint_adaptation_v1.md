# ATO 短问入口适配说明 v1

## 1. 目的

真实策略同学常只给 1-3 句话。本文件用于验证 ATO 入口层能否在短问、信息不全、意图混合时稳定工作，而不是要求用户先写完整 Prompt。

目标是：

- 识别短问意图；
- 判断信息是否足够；
- 不强行下结论；
- 给出最小补证路径；
- 必要时生成低成本 Data Agent 问题；
- 输出简短、可执行的下一步。

## 2. 短问类型归纳

### 2.1 单 case 判断

典型问法：

- 这个用户是不是被盗？
- 这个能不能认盗号？
- 用户说扫码后被盗，咋看？

### 2.2 批量样本分层

典型问法：

- 这批扫码 case 帮我看下。
- 这批有没有共性？
- 这批样本怎么分层？

### 2.3 Data Agent 问题生成

典型问法：

- 帮我查下这批有没有问题。
- 怎么问 DataAgent？
- 帮我生成取证问题。

### 2.4 Data Agent 返回解释

典型问法：

- DataAgent 说有异步登录，这能不能认？
- 这个结果够不够？
- partial / no_permission 怎么看？

### 2.5 下游作恶边界

典型问法：

- 这批没发布，是不是就不是盗号？
- 有违规发布，是不是就是盗号？
- 只有评论点赞私信，算不算？

### 2.6 回捞 / 策略

典型问法：

- 这个能不能回捞？
- 这个要不要打？
- 哪些特征能用？

### 2.7 治理建议

典型问法：

- 这类怎么处理？
- 要踢 token 还是封号？
- 应该先验证还是先拦？

## 3. 短问处理顺序

1. 先识别 intent。
2. 判断信息是否足够。
3. 如果不足，优先追问关键字段。
4. 如果可以给方向，先给阶段性判断。
5. 如果需要 Data Agent，生成低成本最小取证问题。
6. 不默认跑长周期、不默认大样本、不默认多表复杂 join。

## 4. 缺信息追问规则

### 4.1 单 case

最少需要：

- `user_id` / `case_id`
- 异常时间
- 用户自述或异常行为
- 是否已有 Data Agent 返回

如果缺 `user_id` 或时间窗：

- 不进入取证；
- 先返回 missing_input_request；
- 明确告诉用户还缺什么。

### 4.2 批量 case

最少需要：

- 样本列表
- 时间窗口
- 当前标签或来源
- 期望目标：分层 / 回捞 / 复盘 / 查共性

### 4.3 Data Agent 返回解释

最少需要：

- Data Agent 原始返回
- 查询状态：`success / SQL-only / partial / no_permission / timeout`
- 查询时间窗

## 5. 默认最小取证策略

当用户只说“帮我查是不是盗号”时，默认推荐：

- 单 `user_id`
- 单日或 1 小时时间窗，优先用户给的异常时间
- 先查登录 / 授权 / 设备 / IP / UA / 地区 / 账号安全风险命中
- 暂不查长周期历史画像
- 暂不查大样本回捞
- 暂不查高成本下游全链路，除非用户确认

## 6. 短问响应格式

### 6.1 当前能不能判断

### 6.2 为什么

### 6.3 还缺什么

### 6.4 下一步建议

### 6.5 是否需要 Data Agent

### 6.6 如果需要，给最小取证问题或告诉用户需要补什么字段

要求：

- 默认先短答，不直接输出长报告。
- 能给阶段性判断就先给阶段性判断，但保留边界。
- 不默认长周期扩窗、不默认大样本、不默认多表复杂 join。

## 7. 边界规则

- 用户自述 / 人工备注不是事实。
- 无发布不能排除 ATO。
- 有发布不能直接确认 ATO。
- Data Agent 是 evidence provider。
- Dennis final judgement 由 Dennis Agent 输出。
- SQL-only / partial / timeout 不能强结论。
- 高风险处置动作需要人工确认。
- 具体策略名不能作为本质特征。

## 8. 12 个短问回归样例

### Case 1

- 用户短问：这个用户是不是被盗？
- 识别 intent：单 case 判断
- 信息是否足够：不足
- 是否需要追问：需要
- 是否需要 DataAgent：视补齐情况而定
- 默认最小动作：补 `user_id` / 异常时间 / 已有线索
- 预期简短回答：先说不能强判，补最小字段后再判断
- 是否存在误判风险：高

### Case 2

- 用户短问：这批扫码 case 帮我看下。
- 识别 intent：批量样本分层
- 信息是否足够：部分足够
- 是否需要追问：需要补样本列表和时间窗
- 是否需要 DataAgent：需要
- 默认最小动作：先分层，再给低成本取证问题
- 预期简短回答：先分扫码 / 钓鱼 / 不确定，再决定查数
- 是否存在误判风险：中

### Case 3

- 用户短问：DataAgent 说有异步登录，这能不能认？
- 识别 intent：Data Agent 返回解释
- 信息是否足够：不足
- 是否需要追问：需要原始返回和时间窗
- 是否需要 DataAgent：已返回则不需要，先解释
- 默认最小动作：区分 data_findings 和 provider hint
- 预期简短回答：不能直接认，需要看是否闭合登录链路和反证
- 是否存在误判风险：高

### Case 4

- 用户短问：这批没发布，是不是就不是盗号？
- 识别 intent：下游作恶边界
- 信息是否足够：足够给原则
- 是否需要追问：不一定
- 是否需要 DataAgent：若要查证据，则需要
- 默认最小动作：说明无发布不能反向排除 ATO
- 预期简短回答：不能，因为 ATO 不以发布为必要条件
- 是否存在误判风险：高

### Case 5

- 用户短问：有违规发布，是不是就是盗号？
- 识别 intent：下游作恶边界
- 信息是否足够：足够给原则
- 是否需要追问：不一定
- 是否需要 DataAgent：若要验证链路，则需要
- 默认最小动作：要求登录 / 授权 / 设备 / token 链路
- 预期简短回答：不是，发布只能是下游证据，不能单独定 ATO
- 是否存在误判风险：高

### Case 6

- 用户短问：这个能不能回捞？
- 识别 intent：回捞 / 策略
- 信息是否足够：不足
- 是否需要追问：需要目标和样本范围
- 是否需要 DataAgent：可能需要
- 默认最小动作：先给候选特征和误伤风险
- 预期简短回答：先看能否形成稳定机制特征，再决定回捞
- 是否存在误判风险：中

### Case 7

- 用户短问：这个要不要打？
- 识别 intent：治理建议
- 信息是否足够：不足
- 是否需要追问：需要风险类型和证据状态
- 是否需要 DataAgent：可能需要
- 默认最小动作：不给自动处置结论，只给阶段性建议
- 预期简短回答：先确认证据，再决定验证/限权/拦截
- 是否存在误判风险：高

### Case 8

- 用户短问：用户说扫码后被盗，咋看？
- 识别 intent：单 case 判断
- 信息是否足够：不足
- 是否需要追问：需要用户 ID 和时间
- 是否需要 DataAgent：补齐后需要
- 默认最小动作：先补最小证据
- 预期简短回答：用户自述只能当线索，先补登录链路
- 是否存在误判风险：高

### Case 9

- 用户短问：只有人工备注，能认吗？
- 识别 intent：单 case 判断 / 证据边界
- 信息是否足够：不够
- 是否需要追问：需要数据链路
- 是否需要 DataAgent：需要
- 默认最小动作：明确人工备注不是事实
- 预期简短回答：不能，备注只能作为线索
- 是否存在误判风险：高

### Case 10

- 用户短问：帮我问 DataAgent。
- 识别 intent：Data Agent 问题生成
- 信息是否足够：不足
- 是否需要追问：需要 case、时间窗、目标
- 是否需要 DataAgent：需要
- 默认最小动作：先补最小输入
- 预期简短回答：先告诉我 user_id 和时间窗，我给你最小取证问题
- 是否存在误判风险：中

### Case 11

- 用户短问：这个结果够不够？
- 识别 intent：Data Agent 返回解释
- 信息是否足够：不足
- 是否需要追问：需要原始返回
- 是否需要 DataAgent：若已有返回则直接解释
- 默认最小动作：判断是否只到 SQL-only / partial / timeout
- 预期简短回答：看是否闭合关键证据，不够就降级
- 是否存在误判风险：高

### Case 12

- 用户短问：怎么治理？
- 识别 intent：治理建议
- 信息是否足够：不足
- 是否需要追问：需要风险类型和证据级别
- 是否需要 DataAgent：可能需要
- 默认最小动作：先分登录前、中、后治理，再谈人工确认
- 预期简短回答：先补证据，再决定验证、限权、拦截或恢复
- 是否存在误判风险：中

## 9. 适配结论

短问入口适配的核心不是扩展能力，而是把以下动作前置：

- 先识别 intent；
- 先判断信息是否足够；
- 先补最小字段；
- 先给阶段性边界；
- 再决定是否需要 Data Agent。
