# Dennis Risk Agent v2.4.2 Strong Model Quality Review v1

本轮按审稿人 / 质检人口径审查，不默认沿用既有“通过”结论。判断标准是：结构完整不等于专家深度充分，自测通过不等于真实运行稳定，能生成查询建议不等于已经具备可执行查数结果。

## 1. 总体结论

结论：可以继续作为内部小范围试运行版本，不建议阻塞上架；但不应对外表述为“非 ATO 场景已具备完全体专家能力”。

当前版本更准确的状态是：

- ATO / 盗号防控：是当前最深样板，具备较完整的短问入口、DataAgent 边界、查询建议、证据解释和降级规则。
- 非 ATO 场景：runtime summary 能支撑轻量但不表面的回答，但多数还不是 deep skill 完全体。
- DataAgent：边界总体清楚，仍限定为 Hive / 公司数仓取数分析能力；当前 query suggestion 是“取证建议结构”，不是已执行查询，也不是自动编排能力。
- routing / loading / trace：规则已写清，但运行稳定性依赖 Agent 执行纪律和平台集成方式，不应被视为强可观测系统。

是否需要阻塞上架：不需要。

是否需要立即修正：没有发现 P0。建议先按“内部试运行 + 观察反馈”推进，不做大改。

## 2. 风险分级

### P0：必须修，否则影响正确性 / 边界

无。

未发现以下 P0 问题：

- 未发现默认调用 DataAgent 的硬性错误。
- 未发现把 DataAgent 结果当 Dennis final judgement 的硬性错误。
- 未发现把 SQL-only / partial / timeout 写成可强结论的硬性错误。
- 未发现把用户自述 / 人工备注写成 strong evidence 的硬性错误。
- 未发现 ATO 被 runtime summary 稀释的硬性错误。

### P1：建议修，影响质量和稳定性

1. 回归结论措辞偏乐观。
   当前 regression result 多为“规则符合预期”的自测，不是平台真实多轮稳定性验证。建议后续把“通过”口径降为“满足 internal publish 层最小格式 / 边界回归”。

2. DataAgent Query Suggestion Contract 可用，但还不是强可执行 query intent。
   10 段结构完整，入参分层也正确；但多数模板仍偏“证据方向 + 字段类型”，不是足够具体的 Hive 查询任务。适合作为首次查询建议，不应表述成“一定可直接执行”。

3. 盗号短问 6 段骨架有机械化风险。
   骨架能稳定答案，但如果每次显式输出 6 个标题，会让短问回答显得模板化。更好的口径是：6 段作为内部 checklist；对用户可压缩表达，但内容不能漏。

4. 非 ATO runtime summary 深度不均。
   反爬、协议、群控、真人众包已经具备较好的判断框架；活动反作弊、流量反作弊仍偏通用，能回答短问，但距离 deep skill 还有样板、案例和指标体系缺口。

5. routing trace 是文件级轻量观测，不是平台级可观测。
   AGENTS.md 已要求“开启路由观测”时写入 `memory/routing-trace.md`，但这依赖 Agent 真实执行写文件。若内部平台不支持隐藏落盘或工具执行，trace 规则会变成纸面规则。

### P2：后续优化，不阻塞试运行

1. `ato_short_question_entrypoint_adaptation_v1.md` 中同时存在新 6 段骨架和旧“当前能不能判断 / 为什么 / 还缺什么”格式，后续可统一措辞。

2. `internal_agent_publish_guide.md` 中 ATO 短问骨架出现在非 ATO runtime summary 触发规则附近，容易让配置人员误以为非 ATO 也要套 ATO 骨架，后续可轻微整理。

3. `publish_checklist.md` 可补充 v2.4.2 短问骨架和 query suggestion regression 的检查项，但不是本轮 blocker。

4. 非 ATO 需要更多真实问法和反例来降低 runtime summary 的模板化风险。

## 3. 逐项审查结果

### 3.1 DataAgent Query Suggestion Contract

审查结论：可用于内部试运行的首次查询建议格式，但不能夸大为完整 DataAgent 自动查询编排。

达标点：

- 触发条件和非触发条件区分清楚。
- 保留 10 段标准结构。
- 已区分最小必要入参、建议补充入参、可选上下文。
- ATO 场景中 `suspicious_event_time`、`user_claim_summary`、`manual_note` 没有被写成阻塞项。
- 用户自述、人工备注被放在 weak evidence / 可选上下文，不作为 strong evidence。
- 已约束阈值必须标注为示例阈值，需业务历史分布和风控口径校准。
- 已禁止查询建议阶段输出 `block / ignore` 等强处置结论。
- 已明确 DataAgent 是 Hive / 公司数仓取数分析能力，不是全能数据底座。

主要不足：

- “建议查询数据 / 字段”仍多为字段类型和数据域，缺少足够明确的实体范围、时间范围、聚合粒度、输出行级 / 聚合级要求。
- 部分模板仍像“查数方向清单”，不是严格可直接执行的 query intent。
- 对 DataAgent 来说，后续仍需要把这些结构转成自然语言问题或具体 Hive 任务；当前 contract 不能替代那一步。

质量评价：7.5 / 10。

建议口径：

- 可称为“DataAgent / Hive 查询建议标准结构”。
- 不建议称为“可直接执行的 DataAgent 查询任务”。

### 3.2 盗号防控短问骨架

审查结论：方向正确，能明显改善短问稳定性；但需要防止答案变成机械填表。

达标点：

- 6 段骨架覆盖初步判断、风险本质、关键证据、误判边界、补证 / 查数建议、治理建议。
- 能约束短问不直接强判 ATO。
- 能区分协议上号、token 异用、普通盗号、正常异地登录。
- 默认不进入 DataAgent，只有用户明确问“查什么 / 看日志 / 生成查询建议”才进入 query suggestion。
- 没有把用户自述或人工备注当事实证据。

主要不足：

- 如果按标题逐段输出，用户体感可能偏模板化。
- “短答优先”和“所有回答都体现 6 段骨架”之间有轻微张力。短问场景更适合把 6 段作为内部 checklist，而不是每次都显式展开。
- 目前更擅长“协议上号 / token / 异地登录”一类短问；对账号租借、本人操作、亲友代用、合法代运营等灰区还需要更多真实样例验证。

质量评价：7 / 10。

建议口径：

- 作为 ATO 短问内部回答骨架是合格的。
- 不应承诺所有账号安全短问都能达到完整专家深度。

### 3.3 非盗号 runtime summary

审查结论：不是表面摘要，但也不是完整 deep skill。适合支撑短问和第一轮判断，不适合直接替代深度方案。

抽查结果：

- 反爬 / 资产保护：相对最好。能覆盖外部跟价、资产泄露、真人访问但无前端操作、前后端链路缺失、协议 / 群控 / 真人众包 / 破解包边界。接近 deep skill 压缩版。
- 协议攻击：较好。能区分后端请求无前端行为、SDK / token / 设备一致性、接口序列、与群控 / 破解包 / 正常自动化边界。
- 群控：较好。能抓住统一调度、设备团组、行为同步、收益聚集、合法矩阵边界。
- 真人众包：较好。能抓住真人但任务化组织的本质，能区分群控、协议和自然用户。
- 破解包：可用。端侧工件、SDK 缺失、版本 / 签名 / hook 边界较清楚，但作为 runtime summary 仍缺少更多样本级诊断话术。
- 活动反作弊：可用但偏通用。覆盖假量、裂变套利、渠道套利、奖励套利、查杀分离、后验质量，但具体到口令劫持、渠道结算、活动机制漏洞时仍需要深度 Skill 或案例模板。
- 流量反作弊：可用但偏通用。能讲来源、聚集、后验质量，但对渠道套利、代理作弊、结算风控的动作拆分还不够深。
- 导流截流：可用。能覆盖内容、私信、评论、直播间、承接和转生，但暂不建议作为优先深度场景。

质量分层：

- 接近 deep skill 压缩版：反爬、协议攻击、群控、真人众包。
- runtime summary 可用：破解包、导流截流。
- 需要补样板后再升级：活动反作弊、流量反作弊。

整体评价：7 / 10。

关键降级判断：

- 非 ATO summary 可以让回答不空泛，但不能据此宣称“非 ATO 已完全体化”。
- 对复杂评审、策略树、灰度、指标、复盘材料，仍应按需读取 deep skill。

### 3.4 routing / loading / trace

审查结论：加载边界设计合理，但 trace 仍是轻量工程约束，不是强平台能力。

达标点：

- startup checklist 已明确不建议每轮常驻。
- 非 ATO 默认单一 summary，跨域最多 2 个 summary。
- ATO 命中后加载完全体，不被 summary 替代。
- DataAgent 解释规则只在明确查数或已有查数结果时使用。
- AGENTS.md 已补充“开启路由观测”时必须写 `memory/routing-trace.md`。
- trace 字段足够轻量：scene、intent、loading_path、dataagent_status、degraded、degrade_reason、boundary_risk。

主要不足：

- routing trace 的执行依赖 Agent 记得调用文件写入；不是平台级自动日志。
- 如果内部 Agent 平台没有隐藏 debug / 文件落盘能力，trace 不能保证生效。
- trace 不应作为上线依赖，只能作为 smoke test / regression / 排障辅助。

质量评价：6.5 / 10。

建议口径：

- “具备按需轻量 routing trace 规范”。
- 不建议说“已具备稳定可观测体系”。

### 3.5 回归结论可信度

审查结论：当前回归材料可证明格式和边界大体符合预期，但不能证明真实用户满意度或平台运行稳定性。

达标点：

- v2.4.2 query suggestion regression 覆盖正向触发和非触发。
- ATO short answer regression 覆盖 4 个短问 + 1 个查询建议触发。
- 回归材料未发现误调 DataAgent、虚构结果、强处置结论。

主要不足：

- 多数是“应输出 / 预期输出”式自检，不是完整真实对话输出质量评测。
- “五个问题均符合预期”容易被误读成能力完全通过。
- 没有记录真实用户主观满意度、输出长度、是否机械、是否一次答到点。
- 非 ATO 完全体脑子测试虽然有价值，但不能和 deep skill 真实评审等价。

质量评价：6 / 10。

建议口径：

- 当前回归结果应定位为“最小边界回归通过”。
- 不应定位为“专家深度充分验证通过”。

## 4. 必要的最小修正建议

本轮没有 P0，因此不建议立即修改文件。

如果后续要做最小修正，建议只做以下 P1 / P2 小修：

1. 把 ATO 6 段骨架改成“内部 checklist，外部可压缩表达”，降低机械感。

2. 在 query suggestion contract 里补一句：
   “该结构是首次查询建议，不等于可直接执行 SQL；如需执行，仍需 DataAgent / Hive 侧按数据权限和表口径转换。”

3. 将 regression result 的“均符合预期”口径补充为：
   “满足 internal publish 层最小格式与边界回归；仍需真实用户试用验证回答质量。”

4. 对活动反作弊 / 流量反作弊 runtime summary 后续补两个小模板：
   - 活动：口令劫持 / 裂变套利 / 查杀分离。
   - 流量：渠道低质 / 代理套利 / 结算风控。

这些都不是本轮必须修。
