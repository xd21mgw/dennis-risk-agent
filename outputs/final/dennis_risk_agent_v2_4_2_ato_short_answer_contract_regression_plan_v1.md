# Dennis Risk Agent v2.4.2 ATO Short Answer Contract Regression Plan

## 1. 目的

验证 ATO / 账号安全短问是否稳定使用 6 段回答骨架，并在用户未明确要求查数时，不误调 DataAgent，不误进正式查询建议。

## 2. 适用范围

适用问题包括：

- 账号被盗了，怎么判断是不是协议上号？
- 账号疑似被接管，先看什么？
- token 被盗和协议上号怎么区分？
- 异地登录是不是盗号？
- 用户说被盗了，我应该先看哪些证据？

## 3. 固定回答骨架

所有 ATO / 账号安全短问默认输出 6 段：

1. 初步判断
2. 风险本质
3. 关键证据
4. 误判边界
5. 补证 / 查数建议
6. 治理建议

## 4. 回归案例

### Case 1: 协议上号判断

用户问题：
- 账号被盗了，怎么判断是不是协议上号？

预期：
- 不默认进入正式 DataAgent 查询建议。
- 先按 6 段骨架回答。
- 重点说明登录 / 授权 / 设备 / IP / UA / 地区 / token / session / 下游行为。
- 不把用户自述或人工备注当 strong evidence。

### Case 2: 异地登录是否盗号

用户问题：
- 异地登录是不是盗号？

预期：
- 不默认进入正式 DataAgent 查询建议。
- 先纠偏误判边界。
- 说明异地登录不等于盗号。
- 说明还要看授权链路、设备漂移、token/session 变化和敏感操作。

### Case 3: token 被盗与协议上号区分

用户问题：
- token 被盗和协议上号怎么区分？

预期：
- 不默认进入正式 DataAgent 查询建议。
- 先讲风险本质和关键证据差异。
- 说明需要看登录链路、登录态变化、前后端一致性和下游行为。

### Case 4: 先看哪些证据

用户问题：
- 用户说被盗了，我应该先看哪些证据？

预期：
- 不默认进入正式 DataAgent 查询建议。
- 输出优先级：登录 / 授权链路 → token/session → 设备/IP/UA/地区 → 前后端链路 → 下游行为。
- 如用户后续明确要查数，再进入 DataAgent Query Suggestion Contract。

### Case 5: 明确要求查数

用户问题：
- 账号被盗了，user_id 是 12345，昨晚到今天异常，帮我看应该查什么。

预期：
- 触发 `dataagent_query_suggestion_contract_v1.md`。
- 首次回答必须按标准查询建议结构输出。
- 但仍不调用 DataAgent，不假装已有结果。

## 5. 验收标准

1. 前 4 个短问不应默认生成正式 DataAgent 查询建议。
2. 第 5 个因为明确“查什么”，可以触发 DataAgent Query Suggestion Contract。
3. 所有回答都要体现 6 段骨架。
4. 不误调 DataAgent。
5. 不把用户自述 / 人工备注当 strong evidence。
6. 不直接给封禁 / 冻结等强处置结论。

## 6. 预期检查点

- 是否能先给方向，不下死结论。
- 是否能稳定保持短答骨架。
- 是否能把“查数建议”与“查询结果”分开。
- 是否只在用户明确要求时进入 DataAgent Query Suggestion Contract。
