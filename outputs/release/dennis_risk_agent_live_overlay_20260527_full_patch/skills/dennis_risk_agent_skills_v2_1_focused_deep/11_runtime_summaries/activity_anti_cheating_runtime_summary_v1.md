# Activity Anti Cheating Runtime Summary v1

## 一、场景定位

活动反作弊关注的是活动链路被假量、套利、裂变、真人众包或渠道组织化执行所利用。
它既防奖励被薅，也防活动机制被大量复制或转卖。
本场景默认轻量支持，不默认调 DataAgent。

通用研判纪律：遵守 `computer_use_poc/general_evidence_reasoning_contract_v1.md`。活动策略命中、奖励领取异常、渠道异常或 no_data 不能单独定性作弊；需要注册-活跃-任务-奖励-提现链路、设备/IP/账号聚集、后验质量和时间序列交叉验证。source 不完整时只输出 partial / insufficient conclusion。

## 二、核心判断问题

- 活动是不是被假量、套利或任务化参与污染了。
- 后验质量和参与链路能不能解释当前异常。
- 是否需要先查杀分离，而不是直接打掉全部流量。

## 三、场景本质

本质是在防“活动机制被工具化、规模化、套利化”。
关键不只是参与人数，而是参与动机、链路结构、后验质量和收益闭环。

## 四、典型攻击路径

1. 假量批量参与。
2. 裂变套利。
3. 渠道套利。
4. 奖励套利。
5. 真人众包代做任务。
6. 低质用户堆量骗奖励。
7. 账号 / 设备 / 邀请关系复用。

## 五、强证据

- 邀请、奖励、回流链路异常闭合。
- 后验质量明显低于正常用户。
- 设备 / 账号 / 关系网络聚集。
- 同批参与、同批得奖、同批提现。
- 任务完成与留存 / 转化 / 消费脱钩。
- 规模化、模板化、组织化参与。

## 六、中证据 / 弱证据

中证据：

- 活动参与量异常高。
- 奖励领取集中。
- 渠道质量异常但缺后验验证。

弱证据：

- 单一转化异常。
- 单一低留存。
- 单一设备异常。

这些不能单独定性活动作弊。

## 七、反证与误判边界

- 活动本身设计过宽、规则太松、用户自然涌入都可能造成高参与。
- 低质量用户不一定是黑产。
- 不能把低留存、低付费直接等同假量。
- 需要查杀分离，避免把正常流量全部打掉。

## 八、低成本取证方向

- 先看活动链路、奖励链路、邀请关系。
- 再看后验质量和留存 / 转化 / 付费。
- 再看账号 / 设备 / IP 聚集。
- 再看是否存在回流套利或转卖。
- 先看短窗口和样本分层，不默认大范围回捞。

## 九、治理方法

### 识别

- 活动链路识别。
- 奖励链路识别。
- 邀请关系识别。

### 拦截 / 限制

- 奖励限领、频控、阈值验证、任务分层。

### 体验或业务损伤控制

- 做查杀分离。
- 对正常活动流量保留灰度兜底。

### 人工复核

- 高价值活动、高风险渠道、争议样本要人工确认。

### 复盘沉淀

- 复盘活动设计漏洞。
- 复盘后验质量。
- 复盘哪些特征更适合回捞。

高风险动作必须人工确认，不能自动处罚、封禁、冻结、上线策略。

## 十、短问回复话术

1. “这批活动用户是不是假量？”  
要看奖励、邀请、回流和后验质量，不能只看量。

2. “渠道拉新质量很差，是不是在套利？”  
先看渠道链路和后验质量，再判断是不是套利。

3. “活动奖励被薅了怎么判断？”  
看奖励链路、邀请链路和重复聚集。

4. “真人众包和活动作弊一样吗？”  
不一样，前者更偏组织化执行，后者更偏活动机制套利。

5. “低留存是不是就该全部打掉？”  
不行，要做查杀分离，避免误伤正常流量。

## 十一、DataAgent 默认边界

- 本场景默认不直接调 DataAgent。
- 用户明确要求“查数 / 调 DataAgent / 生成查询问题”时，才生成 DataAgent 取证方向。
- 高成本查询必须用户确认。
- SQL-only / partial / timeout 不能强结论。

## 十二、默认输出结构 / 升级条件 / 当前边界

默认输出结构：

- 当前判断。
- 为什么。
- 还缺什么证据。
- 建议怎么取证。
- 建议怎么治理。
- 是否需要 DataAgent。

何时升级完整 Skill：

- 当问题进入活动作弊评审、策略树、灰度或后验复盘。
- 当要区分假量、裂变套利、渠道套利、真人众包时。

何时允许查数 / 调 DataAgent：

- 用户明确要求查数 / 拉样本 / 看日志 / 验证数据。
- 需要验证活动链路、奖励链路、邀请关系、后验质量时。
- 高成本查询必须用户确认。

当前不应直接下结论的边界：

- 单一指标异常。
- 单一策略命中。
- 单一低留存。

## 十三、禁止行为

- 不基于单一指标异常强判。
- 不基于单一策略命中强判。
- 不把样本比例、具体策略名、具体 IP、具体时间窗沉淀为长期本质规则。
- 不默认查数。
- 不自动处罚 / 封禁 / 冻结 / 上线策略。
