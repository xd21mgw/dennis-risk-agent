# Traffic Diversion Runtime Summary v1

## 一、场景定位

导流截流关注的是通过内容、私信、评论、主页、直播间等链路，把流量从平台内导向站外或其他承接资源。
它既可能是正常营销，也可能是黑灰产导流、私域承接或转生链路。
本场景默认轻量支持，不默认调 DataAgent。

## 二、核心判断问题

- 流量是不是被导到站外或别的承接资源。
- 是否存在组织化承接和批量触达。
- 导流后是否有稳定变现或转生目标。

## 三、场景本质

本质是在防“流量被从平台主链路切走并外部承接”。
判断重点不是有无链接，而是是否存在组织化承接、批量触达和变现目标。

## 四、典型攻击路径

1. 内容中埋导流信息。
2. 私信导流。
3. 评论导流。
4. 主页 / 签名 / 头像导流。
5. 直播间截流。
6. 站外承接到私域、群、站点或其他平台。
7. 转生链路，把导流资产换号继续做。

## 五、强证据

- 导流入口和承接链路闭合。
- 多账号矩阵协同触达。
- 主页 / 评论 / 私信 / 直播间多点位一致承接。
- 站外承接资源稳定复用。
- 触达目标与变现 / 转化链路一致。

## 六、中证据 / 弱证据

中证据：

- 私信 / 评论 / 主页中有相似引导。
- 直播间出现异常加好友或外引行为。
- 同批账号有类似话术。

弱证据：

- 单个链接。
- 单次私信。
- 单条评论。
- 单个加好友行为。

这些不能单独定性导流截流。

## 七、反证与误判边界

- 正常营销、创作者引流、商家投放、合法私域运营都可能有类似表象。
- 不能把任何外链都当导流。
- 不能把单个账号私信都当黑产。
- 缺少承接、矩阵和目标时，只能给风险线索。

## 八、低成本取证方向

- 先看导流入口（内容、私信、评论、主页、直播间）。
- 再看承接资源和转生链路。
- 再看矩阵协同与账号聚集。
- 再看转化闭环和行为重复性。
- 先查短窗和样本链路，不默认大样本。

## 九、治理方法

### 识别

- 导流入口识别。
- 承接链路识别。
- 矩阵协同识别。

### 拦截 / 限制

- 对导流点做限权、限流、词和链接治理。

### 体验或业务损伤控制

- 对合法营销、商家运营和创作者运营提供白名单或分层治理。

### 人工复核

- 对高价值账号、争议内容、站外承接做人工确认。

### 复盘沉淀

- 复盘导流入口。
- 复盘承接链路。
- 复盘转生与矩阵迁移。

高风险动作必须人工确认，不能自动处罚、封禁、冻结、上线策略。

## 十、短问回复话术

1. “直播间用户被陌生人加好友，是不是导流？”
先看是否有站外承接和矩阵，不是单次加好友就能定。

2. “评论区这些账号是不是在引流？”
要看评论后是否有承接链路和转生链路。

3. “主页放联系方式算不算导流？”
要结合业务场景、承接资源和组织性，不能一刀切。

4. “私信里发链接就是导流吗？”
不一定，要看是否批量、是否有承接目标和协同账号。

5. “截流和导流怎么分？”
导流是把流量带出去，截流是把原链路流量抢走到别的承接点。

## 十一、DataAgent 默认边界

- 本场景默认不直接调 DataAgent。
- 用户明确要求“查数 / 调 DataAgent / 生成查询问题”时，才生成 DataAgent 取证方向。
- 高成本查询必须用户确认。
- SQL-only / partial / timeout 不能强结论。

## 十二、默认输出结构 / 升级条件 / 当前边界

默认输出结构：

- 当前判断。
- 为什么。
- 还缺什么证据。
- 建议怎么取证。
- 建议怎么治理。
- 是否需要 DataAgent。

何时升级完整 Skill：

- 当问题进入导流治理、矩阵治理、站外承接评审或灰度处置。
- 当要区分导流、正常营销、商家运营、创作者运营时。

何时允许查数 / 调 DataAgent：

- 用户明确要求查数 / 拉样本 / 看日志 / 验证数据。
- 需要验证承接链路、矩阵协同和转生时。
- 高成本查询必须用户确认。

当前不应直接下结论的边界：

- 单个链接。
- 单次私信。
- 单条评论。
- 单个加好友。

## 十三、禁止行为

- 不基于单一链接强判。
- 不基于单一私信 / 评论强判。
- 不把样本比例、具体策略名、具体 IP、具体时间窗沉淀为长期本质规则。
- 不默认查数。
- 不自动处罚 / 封禁 / 冻结 / 上线策略。
