# Group Control Runtime Summary v1

## 一、场景定位

群控关注的是多账号、多设备、多动作在统一调度下运行，而不是简单的高频或聚集。
典型表现是账号行为、设备环境、收益目标呈现组织化、同步化、批量化。
本场景默认轻量支持，不默认调 DataAgent。

## 二、核心判断问题

- 这些账号/设备是不是被统一调度。
- 行为相似是自然重合还是组织化执行。
- 是否存在收益聚集或任务目标驱动。

## 三、场景本质

本质是在防“统一控制下的规模化作恶”。
关键不是账号多，而是有调度、有分工、有同步、有收益聚集。

## 四、典型攻击路径

1. 多设备统一脚本或统一调度。
2. 同批账号按固定节奏执行相同行为。
3. 账号 / 设备 / IP 形成明显团组。
4. 同一批次集中注册、登录、发帖、互动或转化。
5. 通过代理、云手机、真机农场完成大规模执行。
6. 以收益聚集或任务完成为目标。
7. 与真人众包混合，伪装成正常用户。

## 五、强证据

- 设备团组明显。
- 行为路径高度一致。
- 同步时间窗内统一动作。
- 收益或任务结果聚集明显。
- 账号 / 设备 / IP 之间形成稳定关系网络。
- 目标一致且非自然用户路径。

## 六、中证据 / 弱证据

中证据：

- 同批账号动作很像。
- 单设备覆盖多个账号。
- 短时间内多次重复动作。

弱证据：

- 高频。
- 聚集。
- 单一设备 / IP 异常。

这些都不能单独定性群控。

## 七、反证与误判边界

- 合法矩阵、MCN、商家代运营、客服代管、内部测试都可能出现类似组织化行为。
- 真人众包可能具有组织化外观，但不是群控。
- 只看“像”会误伤正常运营和授权矩阵。
- 没有设备 / 关系网络 / 收益证据时，不可强判。

## 八、低成本取证方向

- 先看设备团组。
- 再看行为路径。
- 再看账号 / 设备 / IP / UA / 地区一致性。
- 再看收益聚集或任务完成聚集。
- 先查短窗口和代表样本，不默认大样本回捞。

## 九、治理方法

### 识别

- 设备团组识别。
- 行为相似度识别。
- 同步节奏识别。

### 拦截 / 限制

- 对高风险团组做验证、限权、限频、分层风控。

### 体验或业务损伤控制

- 对合法矩阵、代运营、内部测试做授权登记和白名单。

### 人工复核

- 对高价值账号、商家矩阵、争议设备团组做人工确认。

### 复盘沉淀

- 复盘统一调度特征。
- 复盘收益聚集和关系边。
- 复盘群控与真人众包边界。

高风险动作必须人工确认，不能自动处罚、封禁、冻结、上线策略。

## 十、短问回复话术

1. “这些设备行为很像，是不是群控？”
要先看是否有统一调度和收益目标，像只是表象。

2. “很多账号同一批设备操作，怎么判断？”
先看设备团组、行为路径和账号关系，再看收益聚集。

3. “同一时间很多号一起动，是不是群控？”
同步只是线索，不足以定性。

4. “商家代运营会不会像群控？”
会，所以必须看授权矩阵和业务边界。

5. “真机也会是群控吗？”
会，真机不等于正常用户，关键是是否统一调度。

## 十一、DataAgent 默认边界

- 本场景默认不直接调 DataAgent。
- 用户明确要求“查数 / 调 DataAgent / 生成查询问题”时，才生成 DataAgent 取证方向。
- 高成本查询必须用户确认。
- SQL-only / partial / timeout 不能强结论。

## 十二、默认输出结构 / 升级条件 / 当前边界

默认输出结构：

- 当前判断。
- 为什么。
- 还缺什么证据。
- 建议怎么取证。
- 建议怎么治理。
- 是否需要 DataAgent。

何时升级完整 Skill：

- 当需要完整群控评审、策略树、回捞或灰度时。
- 当要区分群控、合法矩阵、真人众包时。

何时允许查数 / 调 DataAgent：

- 用户明确要求查数 / 拉样本 / 关联关系网络。
- 需要验证设备团组、同步节奏或收益聚集时。
- 高成本查询必须用户确认。

当前不应直接下结论的边界：

- 单一设备异常。
- 单一时间同步。
- 单一行为相似。
- 单一高频。

## 十三、禁止行为

- 不基于单一设备聚集强判。
- 不基于单一时间同步强判。
- 不把样本比例、具体策略名、具体 IP、具体时间窗沉淀为长期本质规则。
- 不默认查数。
- 不自动处罚 / 封禁 / 冻结 / 上线策略。
