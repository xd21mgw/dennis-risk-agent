# Cracked App Runtime Summary v1

## 一、场景定位

破解包关注的是客户端被改造、被注入、被绕过或被删减，从而让攻击者绕开原本采集、验证或风控能力。
常见结果是 SDK 缺失、埋点缺失、设备环境失真、风控信号被绕过。
本场景默认轻量支持，不默认调 DataAgent。

## 二、核心判断问题

- 客户端是不是被改造过。
- 端侧采集和校验是不是被绕过。
- SDK 缺失是改包还是埋点 / 版本问题。

## 三、场景本质

本质是在防“客户端被改造成更适合黑产操作的版本”。
攻击目标不是单纯登录，而是让平台看到假正常、真绕过。

## 四、典型攻击路径

1. 破解包移除或弱化 SDK。
2. 插件注入篡改逻辑。
3. 客户端能力绕过，跳过验证或采集。
4. 伪装官方版本或改签。
5. 通过动态加载或 hook 绕过限制。
6. 配合协议、群控、脚本完成自动化作恶。
7. 利用埋点缺失掩盖真实行为。

## 五、强证据

- 包签名、版本、渠道异常。
- Manifest / 权限 / 导出组件异常。
- dex / so / assets 出现篡改迹象。
- SDK 状态缺失或明显被替换。
- runtime 前台 activity / 截图 / 行为与官方包不一致。
- 方法级短链证据支持改包或 hook。

## 六、中证据 / 弱证据

中证据：

- 前端无日志但后端有请求。
- SDK 信号异常但仍有部分正常行为。
- 版本渠道异常但没有完整工件证据。

弱证据：

- 只有风控标签。
- 只有设备异常。
- 只有无日志现象。

这些都不能单独定性破解包。

## 七、反证与误判边界

- 官方包埋点缺失、版本过旧、采集延迟都可能造成相似表象。
- 只看“前端无日志”会误把埋点问题当破解包。
- 只有设备 / 登录异常，不足以区分破解包和协议。
- 需要工件级证据，不应只靠行为侧判断。

## 八、低成本取证方向

- 先看包签名、版本、渠道。
- 再看 Manifest / 权限 / 导出组件。
- 再看 dex / so / assets 是否异常。
- 再看 SDK 是否缺失或被替换。
- 再看 runtime 行为是否与官方包一致。
- 优先查版本分布和样本包，不默认大规模扫描。

## 九、治理方法

### 识别

- 包签名 / 版本 / 渠道识别。
- 工件差异识别。
- SDK 覆盖率识别。

### 拦截 / 限制

- 风险版本限制。
- 强制升级。
- 完整性校验。

### 体验或业务损伤控制

- 对老版本、低覆盖包、兼容包设置分层策略。

### 人工复核

- 对改包、hook、插件注入类样本做人工确认。

### 复盘沉淀

- 复盘包特征。
- 复盘绕过路径。
- 复盘 SDK 缺失与误判边界。

高风险动作必须人工确认，不能自动处罚、封禁、冻结、上线策略。

## 十、短问回复话术

1. “这个是不是破解包？”  
先看包签名、版本、工件和 SDK 状态，不能只看无日志。

2. “SDK 没日志是不是包被改了？”  
不一定，也可能是埋点缺失或版本过旧。

3. “客户端被注入了怎么判断？”  
要看 Manifest、dex / so / assets 和 runtime 行为，不是只看登录异常。

4. “这个版本要不要强制升级？”  
先看风险版本分布和完整性证据，再决定分层治理。

5. “破解包和协议怎么区分？”  
破解包看工件和端侧改造，协议看前后端链路和请求序列。

## 十一、DataAgent 默认边界

- 本场景默认不直接调 DataAgent。
- 用户明确要求“查数 / 调 DataAgent / 生成查询问题”时，才生成 DataAgent 取证方向。
- 高成本查询必须用户确认。
- SQL-only / partial / timeout 不能强结论。

## 十二、默认输出结构 / 升级条件 / 当前边界

默认输出结构：

- 当前判断。
- 为什么。
- 还缺什么证据。
- 建议怎么取证。
- 建议怎么治理。
- 是否需要 DataAgent。

何时升级完整 Skill：

- 当问题进入改包、注入、hook、渠道版本治理或灰度评审。
- 当要区分破解包、协议、群控时。

何时允许查数 / 调 DataAgent：

- 用户明确要求查数 / 拉样本 / 看日志 / 验证数据。
- 需要验证版本、渠道、工件和 SDK 覆盖时。
- 高成本查询必须用户确认。

当前不应直接下结论的边界：

- 单一无日志。
- 单一版本异常。
- 单一设备异常。

## 十三、禁止行为

- 不基于单一无日志现象强判。
- 不基于单一版本异常强判。
- 不把样本比例、具体策略名、具体 IP、具体时间窗沉淀为长期本质规则。
- 不默认查数。
- 不自动处罚 / 封禁 / 冻结 / 上线策略。
