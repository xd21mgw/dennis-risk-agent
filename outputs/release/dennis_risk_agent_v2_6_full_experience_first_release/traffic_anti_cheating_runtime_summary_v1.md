# Traffic Anti Cheating Runtime Summary v1

## 一、场景定位

流量反作弊关注的是流量被刷量、虚假互动、低质用户、渠道套利或异常聚集污染，导致投放、内容分发或增长判断失真。
它和活动反作弊、导流截流、反爬有交叉，但重点是流量质量与转化真实性。
本场景默认轻量支持，不默认调 DataAgent。

## 二、核心判断问题

- 流量是不是被人为制造或污染了。
- 质量异常是流量作弊还是业务自然波动。
- 来源、聚集和后验质量能不能解释当前表现。

## 三、场景本质

本质是在防“流量被人为制造、污染、套利或劫持”，导致业务指标失真。
关键不是流量大，而是流量是否真实、可转化、可留存、可解释。

## 四、典型攻击路径

1. 异常刷量。
2. 虚假互动。
3. 低质用户批量进入。
4. 渠道套利 / 倒量。
5. 账号 / 设备 / IP 形成异常聚集。
6. 通过真人众包或脚本混合制造流量。
7. 与活动、导流、反爬混合。

## 五、强证据

- 留存 / 转化 / 付费显著异常。
- 账号 / 设备 / IP / 地区聚集明显。
- 互动行为模板化且缺乏真实消费。
- 流量来源与后验质量严重不匹配。
- 渠道归因、活动归因和真实效果脱钩。

## 六、中证据 / 弱证据

中证据：

- 某渠道指标看起来不错，但后验质量差。
- 同批流量聚集但无法完全解释。
- 部分账号行为模板化。

弱证据：

- 单一 DAU / DNU / CTR 波动。
- 单一活跃指标异常。
- 单一高频互动。

这些不能单独定性流量作弊。

## 七、反证与误判边界

- 热点内容、热点活动、正常投放、商家运营都可能形成聚集。
- 低质用户不一定是黑产。
- 不能把“转化差”直接等同作弊。
- 与活动反作弊、导流、反爬交叉时要先拆链路，不要直接定性。

## 八、低成本取证方向

- 先看账号 / 设备 / IP / 地区聚集。
- 再看留存 / 转化 / 付费。
- 再看来源渠道和后验质量。
- 再看是否和活动、导流、反爬链路交叉。
- 先查短窗和样本分层，不默认大样本。

## 九、治理方法

### 识别

- 流量质量识别。
- 聚集识别。
- 转化和后验质量识别。

### 拦截 / 限制

- 限频、限量、限渠道、分层验证。

### 体验或业务损伤控制

- 对正常渠道和正常用户保留灰度和兜底。

### 人工复核

- 高价值渠道、争议流量、投放样本做人工确认。

### 复盘沉淀

- 复盘渠道质量。
- 复盘后验质量。
- 复盘与活动、导流、反爬的交叉边界。

高风险动作必须人工确认，不能自动处罚、封禁、冻结、上线策略。

## 十、短问回复话术

1. “这批流量是不是刷的？”
先看留存、转化、聚集和来源，不要只看量。

2. “渠道质量很差是不是作弊？”
不一定，要看后验质量和归因链路。

3. “虚假互动怎么判断？”
看互动是否模板化、是否有真实消费和转化。

4. “低质用户是不是黑产？”
不一定，低质是表象，要先分层。

5. “流量作弊和活动作弊一样吗？”
有交叉，但重点不同：一个偏流量质量，一个偏活动机制。

## 十一、DataAgent 默认边界

- 本场景默认不直接调 DataAgent。
- 用户明确要求“查数 / 调 DataAgent / 生成查询问题”时，才生成 DataAgent 取证方向。
- 高成本查询必须用户确认。
- SQL-only / partial / timeout 不能强结论。

## 十二、默认输出结构 / 升级条件 / 当前边界

默认输出结构：

- 当前判断。
- 为什么。
- 还缺什么证据。
- 建议怎么取证。
- 建议怎么治理。
- 是否需要 DataAgent。

何时升级完整 Skill：

- 当问题进入流量作弊评审、渠道治理、指标归因或灰度处置。
- 当要区分流量作弊、活动作弊、导流、反爬时。

何时允许查数 / 调 DataAgent：

- 用户明确要求查数 / 拉样本 / 看日志 / 验证数据。
- 需要验证留存、转化、聚集和渠道质量时。
- 高成本查询必须用户确认。

当前不应直接下结论的边界：

- 单一 DAU / DNU / CTR 波动。
- 单一高频互动。
- 单一来源异常。

## 十三、禁止行为

- 不基于单一指标异常强判。
- 不基于单一聚集强判。
- 不把样本比例、具体策略名、具体 IP、具体时间窗沉淀为长期本质规则。
- 不默认查数。
- 不自动处罚 / 封禁 / 冻结 / 上线策略。
