# Anti Crawler Runtime Summary v1

## 一、场景定位

反爬关注的是平台资源、内容资产、关系资产或价格资产被非正常获取、批量访问或被外部系统持续消耗。
它既可能表现为接口爬取，也可能表现为站外跟价、资产泄露、未登录态访问、真人伪装访问。
本场景默认先判断风险与链路，不默认调 DataAgent。

## 二、核心判断问题

- 这次访问是在正常消费，还是在系统性获取资产。
- 请求链路是否像真实用户，还是像批量化、脚本化、伪装化获取。
- 资产被拿走后，是否出现外部同步、复制、跟价或搬运。

## 三、场景本质

本质是在防“平台资产被系统性、自动化、批量化地获取或搬运”，而不是单纯防高频。
核心差异是：正常访问是围绕业务消费，黑灰产访问是围绕资源获取、复制、转卖或外溢。

## 四、典型攻击路径

1. 接口爬取，批量拉取内容、价格、库存、关系链。
2. 未登录态爬取，绕过鉴权直接访问公开或半公开接口。
3. 站外跟价，利用价格 / 库存 / 上新信息进行快速外部同步。
4. 真人访问伪装，使用正常浏览链路掩盖自动化获取。
5. SDK / 埋点缺失，导致前端看不到行为，后端仍有请求。
6. 通过合作方、缓存、暴露页或搜索结果持续收集资产。
7. 组合协议 / 群控 / 真人众包 / 破解包完成规避。

## 五、强证据

- 前后端链路不一致且后端请求持续出现。
- 接口序列固化，参数组合稳定且跨账号复用。
- 同设备 / 同 IP / 同 UA / 同代理高频访问多个资源。
- 未登录态即可持续拉取敏感资产。
- 资产访问后出现明显外部同步、复制或跟价。
- SDK / 埋点缺失不能解释全部访问，且后端仍可见异常链路。
- 访问目标是资产而非正常消费路径。

## 六、中证据 / 弱证据

中证据：

- 单日高频访问。
- 单一资源被重复访问。
- 价格 / 库存 / 内容更新后外部快速同步。
- 访问轨迹与正常浏览不同，但缺少完整后端验证。

弱证据：

- 用户投诉。
- 个别接口异常。
- 单一高频指标。
- 站外价格相似，但没有链路对齐。

这些都不能单独定性。

## 七、反证与误判边界

- 合法高频访问不等于反爬。
- 正常爬虫合作方、蓝军测试、搜索引擎抓取、业务系统同步都可能造成相似表象。
- 前端无日志可能是埋点缺失，不一定是协议或爬虫。
- 只看频次会误伤热点商品、热点内容和正常用户集中访问。
- 缺少设备 / 账号 / 请求序列时，只能给风险线索，不能强判。

## 八、低成本取证方向

- 先看前后端链路一致性。
- 再看接口序列是否固化。
- 再看设备 / IP / UA / 地区是否聚集。
- 再看是否存在未登录态访问。
- 再看资产暴露后外部同步、跟价或搬运轨迹。
- 优先查短时间窗和单接口，不默认扩窗。

## 九、治理方法

### 识别

- 前后端链路一致性校验。
- 设备 / IP / UA 聚集识别。
- 接口序列和参数模板识别。

### 拦截 / 限制

- 限频、限流、限接口、加鉴权、加验证。
- 对高价值资产做延迟展示或分层展示。
- 对高风险接口做挑战或二次确认。

### 体验或业务损伤控制

- 对正常访问保留白名单或降级兜底。
- 对合作方、内部工具做授权登记。

### 人工复核

- 对高价值资产泄露、站外跟价、合作方争议流量做人工确认。

### 复盘沉淀

- 复盘链路缺口。
- 复盘可推算接口和暴露面。
- 复盘是否需要版本治理、产品治理、缓存治理。

高风险动作必须人工确认，不能自动处罚、封禁、冻结、上线策略。

## 十、短问回复话术

1. “这个接口是不是被爬？”
要先看接口序列、前后端链路和设备 / IP 是否聚集，单看高频不够。

2. “外网一直能跟价我们商品，可能怎么来的？”
先排前端暴露、缓存、合作方同步和接口访问，再看是否是资产泄露。

3. “真人访问但没前端操作，可能是什么？”
可能是埋点缺失、协议绕采集、服务端链路或正常真人，不能直接定爬。

4. “这个是不是批量拉取资产？”
先看请求是否围绕资产而非消费路径，再看同源设备 / IP / 参数模板。

5. “这批流量很高，是不是反爬？”
高频只是表象，要看链路、目标和资源消耗模式。

## 十一、DataAgent 默认边界

- 本场景默认不直接调 DataAgent。
- 用户明确要求“查数 / 调 DataAgent / 生成查询问题”时，才生成 DataAgent 取证方向。
- 高成本查询必须用户确认。
- SQL-only / partial / timeout 不能强结论。

## 十二、默认输出结构 / 升级条件 / 当前边界

默认输出结构：

- 当前判断。
- 为什么。
- 还缺什么证据。
- 建议怎么取证。
- 建议怎么治理。
- 是否需要 DataAgent。

何时升级完整 Skill：

- 用户要求完整方案、评审、汇报、策略树、灰度、指标时。
- 当前样本边界不清，需要更深规则时。
- 与协议 / 群控 / 真人众包 / 破解包边界纠缠时。

何时允许查数 / 调 DataAgent：

- 用户明确要求查数 / 拉样本 / 看日志 / 验证数据。
- 需要验证当前轻量判断无法闭合的关键链路。
- 高成本查询必须用户确认。

当前不应直接下结论的边界：

- 单一高频。
- 单一策略命中。
- 单一接口异常。
- 单一站外价格相似。
- 单一无日志。

## 十三、禁止行为

- 不基于单一策略命中强判。
- 不基于单一指标异常强判。
- 不把样本比例、具体策略名、具体 IP、具体时间窗沉淀为长期本质规则。
- 不默认查数。
- 不自动处罚 / 封禁 / 冻结 / 上线策略。
