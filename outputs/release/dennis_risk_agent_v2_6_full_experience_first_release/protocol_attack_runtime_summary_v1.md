# Protocol Attack Runtime Summary v1

## 一、场景定位

协议攻击关注的是服务端请求与客户端真实行为脱钩，或客户端被绕过、被伪造、被自动化。
它常表现为后端有请求、前端无行为、接口序列异常、token / 设备 / UA 不一致。
本场景默认先做边界判断和取证方向，不默认查数。

## 二、核心判断问题

- 这次请求是不是绕过了真实客户端行为。
- 前后端链路是不是真的对不上。
- token / device / UA / IP 的一致性是否能支撑正常解释。

## 三、场景本质

本质是在防“请求被伪装成正常客户端行为”。
黑产不是简单高频，而是绕过客户端约束、利用接口能力、批量化提交或伪造上下文。

## 四、典型攻击路径

1. 后端有请求但前端没有对应操作。
2. 接口序列固化，按脚本直打接口。
3. token / device / IP / UA 不一致或频繁漂移。
4. 请求参数构造异常，自动化痕迹明显。
5. SDK 缺失或埋点缺失，被用来伪装正常行为。
6. 配合群控、破解包、脚本或代理做绕过。
7. 用合法自动化或白名单边界掩护异常请求。

## 五、强证据

- 前后端链路明显不一致。
- 接口序列稳定且非人类路径。
- token / device / UA / IP 明显冲突。
- 请求参数模板化、批量化、无业务上下文。
- 高风险接口被持续命中。
- 客户端行为缺失但服务端动作完整。

## 六、中证据 / 弱证据

中证据：

- 单一接口异常频率高。
- 前端埋点缺失但后端有稳定请求。
- 部分 token / device 异常，但链路未闭合。

弱证据：

- 用户描述。
- 个别异常请求。
- 单一策略命中。

这些不能单独定性协议。

## 七、反证与误判边界

- 合法自动化、测试流量、内部工具、白名单合作方都可能造成相似请求形态。
- 前端无日志可能是采集问题，不等于协议。
- 高频不等于协议，热点业务也会有高频。
- 只有后端请求，不一定是黑产，也可能是正常服务端触发。

## 八、低成本取证方向

- 先看前后端链路一致性。
- 再看接口序列是否异常。
- 再看 token / device / UA / IP 是否一致。
- 再看是否存在 SDK / 埋点缺失。
- 先查单接口、短时间窗和关键样本。

## 九、治理方法

### 识别

- 请求序列识别。
- 设备 / token / UA 一致性识别。
- 客户端行为与后端请求映射识别。

### 拦截 / 限制

- 接口校验、参数校验、频控、挑战、鉴权收紧。

### 体验或业务损伤控制

- 对合法自动化做授权登记和白名单边界。
- 对正常高频业务做降级或缓存兜底。

### 人工复核

- 对高风险接口、白名单争议、业务工具争议做人工确认。

### 复盘沉淀

- 复盘口径差异。
- 复盘可被绕过的接口和证据缺口。
- 复盘是否需要协议专项治理。

高风险动作必须人工确认，不能自动处罚、封禁、冻结、上线策略。

## 十、短问回复话术

1. “后端有请求但前端没操作，可能是什么？”
先排埋点缺失、合法自动化、协议绕采集，再看 token / 设备 / UA 是否冲突。

2. “这个是不是单纯协议攻击？”
不能只看单一请求，要看前后端链路、接口序列和一致性。

3. “请求很像脚本，是不是就能认？”
还不够，要看是否有合法自动化、测试流量或白名单边界。

4. “SDK 没日志是不是协议？”
不一定，可能是采集缺失或版本问题。

5. “这个接口被人直打，怎么判断？”
先看接口序列、上下文和设备 / token 是否稳定。

## 十一、DataAgent 默认边界

- 本场景默认不直接调 DataAgent。
- 用户明确要求“查数 / 调 DataAgent / 生成查询问题”时，才生成 DataAgent 取证方向。
- 高成本查询必须用户确认。
- SQL-only / partial / timeout 不能强结论。

## 十二、默认输出结构 / 升级条件 / 当前边界

默认输出结构：

- 当前判断。
- 为什么。
- 还缺什么证据。
- 建议怎么取证。
- 建议怎么治理。
- 是否需要 DataAgent。

何时升级完整 Skill：

- 当问题进入协议专项评审、治理树、灰度或回归时。
- 当要区分协议、破解包、合法自动化、群控时。

何时允许查数 / 调 DataAgent：

- 用户明确要求查数 / 拉样本 / 看日志 / 验证数据。
- 需要验证前后端链路一致性、设备 / token / UA 冲突时。
- 高成本查询必须用户确认。

当前不应直接下结论的边界：

- 单一后端请求量。
- 单一无前端操作。
- 单一策略命中。
- 单一 SDK 缺失。

## 十三、禁止行为

- 不基于单一请求量强判。
- 不基于单一策略命中强判。
- 不把样本比例、具体策略名、具体 IP、具体时间窗沉淀为长期本质规则。
- 不默认查数。
- 不自动处罚 / 封禁 / 冻结 / 上线策略。
