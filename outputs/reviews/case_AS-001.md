# Case AS-001 回归评审

## 原始问题

怀疑一批账号不是重新登录被盗，而是 token 泄露后被黑产直接复用。如何判断、补证和治理？

## Skill 路由

- 主控 Skill：account_security_expert_skill
- 辅助 Skill：protocol_attack_expert_skill、credential_stuffing_ato_skill、evidence_decomposition_skill、risk_governance_design_skill

## 回答

一句话判断：不能只看“无登录记录”就定性 token 泄露，应证明 token 在非原设备、非原网络、非正常端侧链路中被复用，并且登录后出现账号接管或下游变现行为。

领域归类：账号安全。

风险类型：token 泄露 / ATO / 协议化复用，可能混合钓鱼、木马、破解包或服务端日志泄露。

黑产本质：
- 作恶方：盗号团伙、撞库/钓鱼团伙、外挂/破解包操作者、账号交易商。
- 上游资源：泄露 token、设备指纹伪造能力、代理 IP、账号画像、下游变现入口。
- 中游执行：绕过密码登录，携带 token 直打账号态接口或在新环境恢复会话。
- 下游变现：私信导流、账号资产盗用、支付/优惠券/内容资产转移、账号出售。
- 平台被利用环节：token 生命周期、环境绑定、敏感动作二次校验、会话踢出机制。
- 最适合治理节点：token 与设备/环境/风险状态绑定，以及敏感动作前的 step-up。

关键证据：
- 强证据：无新登录但账号态敏感接口在陌生设备/IP/UA/SDK 版本上持续调用；token 对应设备与请求设备冲突；同一 token 在多地短时间并发；请求缺少正常端侧事件链；高风险行为紧随 token 异常出现。
- 中证据：受害账号集中来自同版本客户端、同渠道、同插件环境或同批外部投诉；异常 token 调用命中特定接口序列；下游私信/提现/换绑/资产转移聚集。
- 弱证据：登录失败未上升、客诉上升、IP 聚集、账号价值偏高。这些只能提示方向，不能单独定性。
- 反证 / 误判：用户换机或漫游；合法多端登录；埋点缺失导致“无登录”；服务端登录日志延迟；客服代操作；蓝军测试；token 刷新链路口径变化。

补证动作：
- 前后端 join：登录、token 签发、token 刷新、账号态接口、敏感动作、端侧事件链。
- 查 token 环境一致性：签发设备、请求设备、IP、UA、SDK、App 版本、网络库、指纹。
- 查并发和迁移：同 token 多地并发、短时跨城市、跨设备复用、刷新失败后继续调用。
- 查下游链路：私信、换绑、支付、提现、优惠券、内容删除、账号出售迹象。
- 查来源：同版本漏洞、风险 App、抓包代理、日志泄露、SDK 采集异常、客服/合作方链路。

治理方案：
- 短期止血：高置信 token 踢出，冻结敏感动作，触发用户确认和找回；对团伙设备/IP/账号做联动处置。
- 中期治理：token 与设备指纹、网络环境、风险状态绑定；高风险环境刷新 token 失效；敏感动作要求可信环境或二次验证。
- 长期能力：建设 token 风险画像、会话一致性校验、端侧完整性校验、泄露样本库、用户找回与客诉回流闭环。

灰度策略：
- 低置信只加采和观察，不踢出。
- 中置信对敏感动作 step-up，不影响普通浏览。
- 高置信先覆盖高价值账号和高危接口，再扩到全量 token 生命周期。
- 设置白名单：企业账号、多端授权、客服测试、内部蓝军。

评估指标：
- 风险 token 踢出量、ATO 客诉下降、敏感动作拦截准确率、找回成功率、误伤率、验证通过率、黑产迁移到重新登录/群控的比例、用户打扰率。

可沉淀资产：
- token 复用证据模板、会话一致性规则、账号态接口风险分级、ATO 样本库、token 事件链看板、处置 SOP。
