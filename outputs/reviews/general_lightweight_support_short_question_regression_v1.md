# 通用轻量支持层短问回归 v1

## 1. 回归目标

验证 Dennis Risk Agent 在非 ATO 场景下，面对 1-3 句话短问时，是否能保持**轻量支持**：

- 先判断场景；
- 先拆证据；
- 先给取证方向；
- 先给治理建议；
- **默认不调用 DataAgent**；
- 只有用户明确要求查数 / 调 DataAgent / 生成查询问题时，才进入 DataAgent。

本轮不调用 DataAgent，不修改核心 Skill。

## 2. 回归样例

### Case 1：反爬 - 接口被爬

- 用户短问：这个接口是不是被爬？
- 识别场景：反爬
- 识别 intent：反爬 / 资产访问异常
- 是否信息足够：不足，不能直接定性
- 默认是否调用 DataAgent：否，除非用户明确要求查数
- 当前轻量判断：先看是否有异常接口序列、前后端链路、SDK 覆盖、设备 / IP / UA 聚集
- 需要补哪些证据：接口范围、时间窗、是否有前端 / 后端日志、是否有异常 token / 设备线索
- 推荐 DataAgent 取证方向，如需要：前后端链路、接口序列、设备 / IP / UA、SDK 覆盖、资产访问频次
- 治理建议：先做链路拆解和风控分层，再决定限频 / 验证 / 资产保护
- 是否需要人工复核：需要
- 是否存在强判风险：有，如果把高频访问直接等同协议或爬虫
- 是否符合“通用轻量支持 + ATO 深度样板”定位：符合

### Case 2：反爬 - 外网跟价

- 用户短问：外网一直能跟价我们商品，可能怎么来的？
- 识别场景：反爬 / 外网资产暴露
- 识别 intent：反爬 / 价格资产泄漏
- 是否信息足够：不足
- 默认是否调用 DataAgent：否，除非用户明确要求查数
- 当前轻量判断：优先考虑缓存暴露、前端暴露、合作方流转、接口访问、人工搬运等路径
- 需要补哪些证据：价格更新时间、曝光链路、访问来源、是否有异常请求 / 聚集
- 推荐 DataAgent 取证方向，如需要：访问链路、来源分布、时间对齐、账号 / IP 聚集
- 治理建议：先收敛暴露面，再看限权、鉴权、延迟展示或风控验证
- 是否需要人工复核：需要
- 是否存在强判风险：有，如果直接认定内部接口被爬
- 是否符合定位：符合

### Case 3：协议 - 后端有请求但前端无操作

- 用户短问：后端有请求，但用户前端没操作，可能是什么？
- 识别场景：协议攻击 / 前后端链路不一致
- 识别 intent：协议 / 前后端链路一致性
- 是否信息足够：不足
- 默认是否调用 DataAgent：否，除非用户明确要求查数
- 当前轻量判断：优先考虑埋点缺失、破解包绕采集、口径问题、合法自动化、真实无端请求
- 需要补哪些证据：前端行为、后端请求、SDK 覆盖、token / device / IP / UA 一致性
- 推荐 DataAgent 取证方向，如需要：前后端链路 join、设备 / 指纹、网关 / 业务日志
- 治理建议：先排口径和采集缺失，再做异常请求和策略治理
- 是否需要人工复核：需要
- 是否存在强判风险：高，如果把“前端无操作”直接定成协议
- 是否符合定位：符合

### Case 4：协议 - 单纯协议

- 用户短问：这个是不是单纯协议攻击？
- 识别场景：协议攻击
- 识别 intent：协议判断

- 当前轻量判断：先判断是否缺前端、接口序列是否固化、token / device / UA / IP 是否冲突
- 需要补哪些证据：目标接口、时间窗、前后端链路、风控命中
- 推荐 DataAgent 取证方向，如需要：链路一致性、接口序列、设备 / 账号 / IP 关联
- 治理建议：先补证，再决定是否收紧接口、加验证或拦截
- 是否需要人工复核：需要
- 是否存在强判风险：中
- 是否符合定位：符合

### Case 5：群控 - 设备行为很像

- 用户短问：这些设备行为很像，是不是群控？

- 识别 intent：群控 / 统一调度
- 是否信息足够：不足
- 默认是否调用 DataAgent：否，除非用户明确要求查数
- 当前轻量判断：动作像只是表象，要看是否有统一调度、设备团组和收益目标
- 需要补哪些证据：设备 / IP / UA、行为序列、账号关系、是否有同批收益聚集
- 推荐 DataAgent 取证方向，如需要：设备团组、关系网络、行为路径、收益结果
- 治理建议：先做设备 / 账号分层和验证，不要把“像”直接当群控
- 是否需要人工复核：需要

- 是否符合定位：符合

### Case 6：群控 - 同批设备操作

- 识别场景：群控
- 识别 intent：群控 / 批量统一调度
- 是否信息足够：不足

- 当前轻量判断：优先看是否同源设备、同源账号、同批时间、同路由动作、同收益目标
- 需要补哪些证据：设备团组、账号共设备、行为节奏、收益聚集
- 推荐 DataAgent 取证方向，如需要：关系网络、设备聚集、同批行为路径
- 治理建议：先分层，再决定是否验证、限权或联动处置
- 是否需要人工复核：需要

### Case 7：活动反作弊 - 假量

- 用户短问：这批活动用户是不是假量？
- 识别场景：活动反作弊
- 识别 intent：活动套利 / 假量判断
- 是否信息足够：不足
- 默认是否调用 DataAgent：否，除非用户明确要求查数
- 当前轻量判断：先看邀请、奖励、回流、设备 / 账号聚集和后验质量
- 需要补哪些证据：活动规则、参与路径、奖励结果、留存 / 付费 / 后验质量
- 推荐 DataAgent 取证方向，如需要：活动链路、奖励链路、邀请关系、后验质量
- 治理建议：先做查杀分离和后验评估，不要直接把低质量当黑产
- 是否需要人工复核：需要

### Case 12：跨场景混合 - 协议、群控、盗号

- 用户短问：这个风险更像协议、群控，还是盗号？
- 识别场景：跨场景混合
- 识别 intent：风险分类 / 场景判断
- 是否信息足够：不足
- 默认是否调用 DataAgent：否，除非用户明确要求查数
- 当前轻量判断：先按最小区分点拆成三类看：
  - 协议：前后端链路和采集缺失。
  - 群控：统一调度和设备团组。
  - 盗号：登录接管和账号控制权变化。
- 需要补哪些证据：对应场景的最小链路证据
- 推荐 DataAgent 取证方向，如需要：按场景拆分 query plan，而不是一次性大查询
- 治理建议：先分流，再决定是否进入各自专项治理
- 是否需要人工复核：需要
- 是否存在强判风险：高
- 是否符合定位：符合

## 3. 汇总结论

### 3.1 12 个短问是否通过

通过。

### 3.2 哪些场景轻量支持较稳

较稳的是：

- 协议攻击。
- 群控。
- 导流截流。
- 反爬的基础边界判断。

这些场景都能先给场景拆解、证据方向和治理建议，而不必默认查数。

### 3.3 哪些场景还需要后续 overlay

后续可能还需要更细的场景 overlay 的有：

- 反爬的资产泄露与外网跟价细分。
- 活动反作弊的渠道套利 / 真人众包更细分。
- 导流截流的直播间、评论、私信、主页承接更细分。

### 3.4 是否需要修改通用 scenario contract

暂不需要。

### 3.5 是否需要修改核心 Skill

否。

### 3.6 是否建议下一步扩第二个深度场景

不建议立刻扩第二个深度场景。更合理的顺序是：

1. 先把 ATO 的深度闭环和 runtime slim 稳住。
2. 再把通用轻量支持层继续打磨。
3. 再选一个高价值、低歧义的第二场景做深度样板。

### 3.7 当前建议

当前更重要的是：

- 保持“通用轻量支持 + ATO 深度样板”的定位。
- 对非 ATO 场景坚持默认不查数。
- 用短问入口先接住问题，再决定是否生成 DataAgent 取证方向。
