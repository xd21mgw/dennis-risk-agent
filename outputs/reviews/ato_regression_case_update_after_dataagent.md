# ATO 回归 Case 使用建议更新

## 1. 更新背景

本轮 Data Agent 对 Sheet2 15 个 Web 扫码登录类 ATO 样本做了 2026-05-04 ~ 2026-05-05 短窗口只读取证。

稳定发现：
- ASYNC_WEB_LOGIN 覆盖 13/15。
- 发布行为只覆盖 5/15。
- 10/15 短窗口内未发现发布。
- caption / upload_timestamp 权限不足。
- 发布行为不适合作为独立回捞主特征。

业务先验补充：ATO 后下游作恶不一定是发布内容，也可能是点赞、关注、评论、私信、爬虫、活动套利、直播截流、账号交易、养号、转生，或仅登录控制但尚未动作。

因此回归 case 的主轴应调整为：

```text
ATO 发生方式：Web 扫码登录
→ 下游作恶方式：发布 / 互动 / 接口访问 / 活动 / 导流 / 养号 / 未验证
```

## 2. 可作为 Web 扫码登录类正例的 case

适用条件：
- 存在 ASYNC_WEB_LOGIN 或等价 Web 扫码 / 异步登录 / 授权登录迹象。
- 存在登录环境突变。
- 命中 stealAccount 或相关盗号策略。
- 存在无历史环境、地区不匹配、web_% 设备等共性。
- 有人工核查线索，但只作为线索，不作为事实。

回归用途：
- 验证 Dennis Agent 能识别“登录态接管类 ATO”。
- 验证 ATO 判断不依赖发布行为。
- 验证人工标签和 Data Agent 数据发现的分离。

expected_conclusion：

```text
data_supports_web_scan_ato_suspicion
```

## 3. 可作为“扫码登录但无发布”的边界样本

适用条件：
- 有 Web 扫码 / ASYNC_WEB_LOGIN / 授权登录证据。
- 查询窗口内无发布行为。
- 缺其他下游行为数据或暂未探查。

回归用途：
- 防止把所有 ATO 样本都要求有发布行为。
- 防止把“短窗口无发布”当作非盗号反证。
- 验证 `login_control_without_observed_downstream_abuse` 标签。

expected_conclusion：

```text
web_scan_ato_suspicion_downstream_unverified
```

must_not：
- 不得输出“无发布，所以不是盗号”。
- 不得强行补写“发布色情 / 招嫖内容”。
- 不得把短窗口未发现发布解释为没有下游作恶。

## 4. 可作为“有发布但内容不可验证”的边界样本

适用条件：
- 有发布行为。
- caption / upload_timestamp / 内容策略不可用或权限不足。
- 发布设备与登录链路是否一致仍需进一步验证。

回归用途：
- 防止把“有发布”直接升级为“色情 / 招嫖发布”。
- 验证内容权限缺口下的降级能力。

expected_conclusion：

```text
web_scan_ato_suspicion_with_publish_content_unverified
```

must_not：
- 不得在 caption 无权限时判断内容类型。
- 不得在 upload_timestamp 无权限时判断短时间集中发布。

## 5. must_have 更新

Web 扫码登录类 ATO must_have：

- 是否存在 Web 扫码 / 异步登录 / 授权登录迹象。
- 是否存在登录环境突变。
- 是否命中 stealAccount 或相关盗号策略。
- 是否存在无历史环境 / 地区不匹配 / web_% 设备等共性。
- 是否有人工核查线索，但不能直接当事实。

下游作恶子标签 must_have：

- 发布类：发布记录、发布设备/IP/地区、内容风险策略或 caption。
- 互动类：点赞、关注、评论、私信行为。
- 爬虫/接口类：接口访问、资产访问、请求路径。
- 活动类：活动参与、奖励、提现、邀请关系。
- 导流类：私信、关注、搜索、主页、站外承接。
- 养号/交易类：换绑、改密、资料变更、多设备迁移、交易线索。

## 6. must_not 更新

通用 must_not：

- 不得要求所有 ATO 样本都有发布行为。
- 不得把“无发布”当作非盗号反证。
- 不得把发布色情 / 招嫖作为 ATO 必要条件。
- 不得把人工备注中的作恶内容直接当事实。
- 不得把短窗口未发现发布解释为没有下游作恶。
- 不得因用户自述“扫码”直接强判 ATO。
- 不得把 5/15 的发布行为外推到 15/15。
- 不得把发布行为作为回捞主特征独立使用。

## 7. 原标签降级建议

以下原标签应降级为人工线索：

| 原标签 / 字段 | 降级后含义 |
|---|---|
| 地推欺诈 | ATO 发生方式线索，需 Web 扫码 / 授权登录验证 |
| 扫码后发布 | 链路假设，需登录发布 join 验证 |
| 色情视频-网址 | 下游作恶人工线索，需 caption / 内容策略验证 |
| 招嫖视频-微信 | 下游作恶人工线索，需内容识别和导流链路验证 |
| 招嫖视频-钱 | 下游作恶人工线索，需内容和收益链路验证 |
| 已回捞 | 回捞状态线索，需回捞记录验证 |

## 8. 回归集调整建议

新增长期回归类别：

```yaml
regression_type:
  - positive_web_scan_login_ato
  - web_scan_login_no_publish_boundary
  - web_scan_login_publish_content_unverified
  - web_scan_login_downstream_unknown
  - downstream_abuse_type_branch_validation
```

每轮回归至少保留：
- 2 个 Web 扫码登录正例。
- 2 个扫码登录但无发布边界样本。
- 1 个有发布但内容不可验证样本。
- 1 个下游作恶未知样本。

## 9. 对既有 27 个 case 的影响

影响：
- ATO_XLSX_001 ~ ATO_XLSX_006 原本偏“地推扫码后发布”的描述应保留为人工线索。
- 未经 Data Agent 验证发布的样本，应优先作为 Web 扫码登录类正例或“下游未验证”边界样本。
- 已验证有发布的样本，也只能标记“有发布行为”，不能直接标记色情 / 招嫖内容。

不影响：
- 钓鱼 / 短信 / token / 非盗号 / 不确定样本的基本分层。

## 10. 结论

回归 case 的判断主轴应从：

```text
地推扫码 → 发布异常内容
```

调整为：

```text
ATO 发生方式：Web 扫码登录
下游作恶方式：发布 / 互动 / 接口访问 / 活动 / 导流 / 养号 / 未验证
```

最关键的防误判规则：

```text
无发布不是非盗号反证，发布色情/招嫖也不是 ATO 必要条件。
```
