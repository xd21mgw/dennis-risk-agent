# v2.3 Executable 回归：AS-001

## Case 信息

- Case：AS-001
- 问题：怀疑一批账号不是重新登录被盗，而是 token 泄露后被黑产直接复用。如何判断、补证和治理？
- 目标 Skill：account_security_expert_skill

## 路由

- 主控 Skill：account_security_expert_skill
- 辅助 Skill：credential_stuffing_ato_skill、protocol_attack_expert_skill、evidence_decomposition_skill、risk_governance_design_skill
- 触发原因：问题核心是账号态 token 复用和 ATO，下游可能协议化调用，需要账号安全主控、协议和 ATO 辅助。

## 输入充分性

输入中等充分：已给出怀疑方向“无重新登录、token 泄露复用”，但缺 token 签发/刷新、设备/IP/UA、下游行为、是否可踢出、弱端来源等日志。因此可以输出判断框架和治理方案，但具体账号不能强定性。

## 判断规则命中

命中 account_security_expert_skill 判断规则第 2 条：无重新登录但 token 在新设备/IP/UA/SDK/环境调用账号态接口，且伴随敏感动作或批量模板，则判断为 token 泄露/复用方向。

同时命中第 7、8 条约束：只有 IP/设备变化不得强判；正常换机、多端登录、可信旧设备确认、SDK 口径变化需要降级。

## 一句话判断

token 泄露复用的本质是黑产绕过重新登录，搬运存量登录态到新环境继续调用账号态能力；定性要证明 token 与设备/环境/行为链冲突，并排除正常换机和埋点口径问题。

## 证据分层

强证据：
- 无新登录但账号态敏感接口在陌生设备/IP/UA/SDK 上调用；
- token 签发环境与当前请求环境冲突；
- 同 token 多地并发或短时跨环境使用；
- token 刷新链路缺登录/验证/迁移确认；
- 登录态复用后发生换绑、私信、支付、提现、资产转移；
- 多账号呈现同一“旧 token + 新设备模板”批量模式。

中证据：
- 登录失败未明显上升但 ATO 客诉上升；
- 同版本客户端、弱端或未接风控入口集中；
- 下游行为突变；
- token 长期有效或无法踢出；
- 高价值账号被集中命中。

弱证据：
- IP 变化；
- 城市变化；
- 设备型号变化；
- 单次 token refresh 异常；
- 用户活跃突增。

## 反证与误判

- 用户正常换机、系统搬家、多端登录；
- 可信旧设备确认；
- 企业/机构账号；
- 网络漫游、公司出口、VPN；
- SDK 升级或埋点口径变化；
- 登录日志延迟；
- 用户本人操作或客服代操作。

## 补证动作

- 以 token_id/refresh_token_id 为主键回看签发、刷新、使用、踢出链路；
- 比对签发设备与当前设备/IP/UA/SDK/地理；
- 查是否有重新登录、验证、设备绑定、官方迁移确认；
- 查弱端/未接风控入口、token 是否永久有效、是否可踢出；
- 查登录态复用后的敏感动作；
- 查客诉、找回、下游私信/支付/提现/导流扩散；
- 查批量模板：同工具、同代理池、同设备环境。

## 治理方案

- 高置信：风险 token 柔性踢出，冻结敏感动作，账号保护和快速找回；
- 中置信：敏感动作 Step-up，要求重绑设备或可信设备确认；
- 低置信：加采、提醒、观察，不影响普通浏览；
- 机制建设：token/设备/环境绑定，refresh token 跨环境重校验，弱端接风控，token 可踢出能力。

## 灰度策略

先覆盖高价值账号、高风险 token、敏感动作；普通浏览只降权观察；正常换机和多端登录设反证白名单；监控登录打扰率、验证通过率、找回成功率和 ATO 客诉。

## 评估指标

风险 token 命中量、token 踢出量、ATO 客诉、敏感动作拦截量、找回成功率、验证通过率、登录打扰率、误伤率、弱端接入率、黑产迁移到重新登录/群控的比例。
