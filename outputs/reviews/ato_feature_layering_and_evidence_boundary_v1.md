# ATO 特征分层与证据边界规范 v1

## 1. 为什么需要特征分层

本轮 ATO case 回扫和 Data Agent 小批量验证的价值，是把人工核查样本转成可验证的风险假设，而不是直接生成线上策略、长期规则或最终定性。

需要分层的原因：

- case 回扫是为了生成假设，不是直接生成线上策略。
- Data Agent 返回的是数据发现和覆盖范围，不是最终风控定性。
- 单批样本统计容易受时间窗、样本选择、权限和人工标签口径影响，不能直接写入 Skill。
- 具体策略名 / 规则名属于实现细节，不能作为长期本质特征。
- ATO 发生方式和 ATO 后下游作恶方式必须拆开，否则会把“扫码登录”过拟合成“发布色情/招嫖内容”。

推荐链路：

```text
raw_observation
→ data_finding
→ candidate_feature
→ mechanism_feature
→ principle_rule
```

## 2. ATO 特征分层

### 2.1 raw_observation：原始观测层

定义：

直接来自 Data Agent 返回、人工表格或单次回扫结果的原始观测。

例子：

- 具体策略名，例如 `stealAccount`。
- 具体时间窗，例如 `2026-05-04 ~ 2026-05-05`。
- 单批样本统计，例如 `13/15`、`5/15`。
- 具体发布平台统计，例如 `Android 7/9`。
- 某个 case 的人工备注、来源线索、作恶内容描述。

使用要求：

- 只保留在 Data Agent response、review、eval、case snapshot。
- 不得写入 Skill 作为长期规则。
- 不得作为 ATO 成立必要条件。
- 不得单独作为强证据。
- 必须保留上下文：样本范围、时间窗口、权限限制、字段缺失。

### 2.2 data_finding：数据发现层

定义：

对原始观测做过聚合和边界解释后的数据发现，仍然只代表本轮样本。

例子：

- ASYNC_WEB_LOGIN 覆盖较高。
- 短窗口内仅部分样本有发布。
- 部分样本存在登录环境突变。
- 部分样本命中账号安全风险策略。
- 部分样本存在 web 类设备或 web 类登录环境。

使用要求：

- 可作为本轮样本解释。
- 可用于生成候选假设。
- 不能直接成为最终规则。
- 需要同时记录反证、缺失证据和质量风险。

### 2.3 candidate_feature：候选特征层

定义：

可进入下一轮 Data Agent 回捞验证的候选特征，通常由多条 data_finding 抽象而来。

例子：

- Web 扫码 / 异步登录。
- 授权登录异常。
- web 类设备 / web 类登录环境。
- 地区不匹配。
- 无历史环境。
- 登录后短时间出现异常行为。

使用要求：

- 可进入下一轮 Data Agent 回捞验证。
- 必须经过正例、反例、不确定样本验证。
- 不能单独作为强结论。
- 不能只看覆盖率，还要看误伤、反证和业务合理性。

### 2.4 mechanism_feature：机制特征层

定义：

能解释 ATO 本质机制的稳定特征，具备进入证据卡、query_intent 或 Skill 候选的价值。

例子：

- 账号控制权转移。
- 登录环境突变。
- token/session 异常。
- 异常授权链路。
- 账号接管风险策略命中。
- 盗号后下游作恶方式分流。

使用要求：

- 可作为证据卡 / query_intent 的稳定组成。
- 可以进入 Skill 候选，但需要更多样本验证。
- 需要同时保留反证：本人新设备、合法授权、账号租借、历史 case、时间窗外行为、权限缺失。

### 2.5 principle_rule：本质规则层

定义：

跨批次、跨样本、跨下游作恶方式仍成立的通用判断原则。

例子：

- ATO 发生方式与 ATO 后下游作恶方式必须拆开。
- 发布异常内容不是 ATO 成立必要条件。
- 无发布不能反向排除 ATO。
- 人工备注 / 申诉只作为线索，不直接作为事实。
- Data Agent 只提供 evidence provider 级发现，最终判断由 Dennis 主 Agent 生成。

使用要求：

- 可作为后续轻量回写 `account_security_expert_skill` 的候选规则。
- 不包含具体样本比例、具体策略名、具体时间窗。
- 不包含单次回扫中的具体作恶内容或个案备注。

## 3. 具体策略名处理规则

### 3.1 保留位置

`stealAccount` 这类具体策略名可以保留在：

- raw_observation。
- Data Agent 原始返回。
- case snapshot。
- 内部审计和回放记录。

### 3.2 长期规则中的抽象表达

进入长期规则、证据卡或 Skill 候选时，必须抽象为：

- 账号接管风险策略命中。
- 账号异常登录 / 异常授权策略命中。
- 账号安全风险策略命中。
- 盗号相关策略命中。

### 3.3 禁止用法

- 具体策略名不能作为 ATO 成立必要条件。
- 具体策略名不能单独作为强证据。
- 具体策略名不能写成长期本质特征。
- 具体策略名不能替代登录链路、设备环境、token/session、下游行为和反证排除。

### 3.4 正确用法

具体策略名只能作为独立风险信号之一：

```text
账号安全风险策略命中
+ Web 扫码 / 异步登录
+ 登录环境突变
+ 无历史环境 / 地区不匹配
+ token/session 或授权链路异常
→ 才能提升 ATO 嫌疑强度
```

## 4. 表象特征处理规则

发布色情/招嫖内容、批量点赞、关注、私信、爬虫、活动套利、导流等，属于 ATO 后下游作恶方式。

使用规则：

- 可以作为下游子标签。
- 可以作为治理分流依据。
- 可以帮助解释黑产变现路径。
- 不能作为 ATO 成立必要条件。
- 无某类下游作恶，不代表没有 ATO。
- 有某类下游作恶，也不能脱离登录 / 授权 / token / 设备链路直接判 ATO。

示例：

```text
有发布行为
→ 只能说明存在发布子路径
→ 不能直接说明 ATO 成立
→ 还需要异常登录 / 授权 / token / 设备链路闭合
```

```text
无发布行为
→ 不能反向排除 ATO
→ 可能是其他下游作恶，或仅登录控制尚未动作
```

## 5. 哪些内容可以回写 Skill

### 5.1 可回写候选

以下内容具备进入 `account_security_expert_skill` 的候选价值：

- ATO 发生方式与下游作恶方式解耦。
- Web 扫码 / 异步登录 / 授权登录可作为 ATO 发生方式候选。
- 登录环境突变、无历史环境、地区不匹配、token/session 异常属于关键证据方向。
- 人工备注不能直接当事实。
- 无发布不能反向排除 ATO。
- 发布色情/招嫖内容只是下游作恶子标签，不是 ATO 必要条件。

### 5.2 暂不回写

以下内容只应保留在 review / eval：

- `13/15`、`5/15`、`Android 7/9` 等样本统计。
- `2026-05-04 ~ 2026-05-05` 时间窗。
- `stealAccount` 等具体策略名。
- 色情/招嫖作为必要路径。
- 单批样本中的具体比例。
- 单个 case 的人工备注原文。

## 6. 下一轮 Data Agent 验证重点

优先验证候选机制特征，而不是直接扩展成长期规则：

P0：
- Web 扫码 / 异步登录 / 授权登录。
- 登录环境突变。
- 无历史环境。
- 地区不匹配。
- 账号安全风险策略命中。

P1：
- token/session 异常。
- 登录后短时间异常行为。
- 有发布样本的内容风险证据。
- 无发布样本的其他下游行为，例如点赞、关注、私信、接口访问、活动套利、导流、养号。

P2：
- 长周期扩窗，仅在 P0/P1 无法解释时再跑。

## 7. 输出结论

1. 当前不建议立即回写 `account_security_expert_skill`。
2. 回写条件：更多正反例、更多时间窗、更多下游作恶类型验证后，再沉淀 principle_rule。
3. 下一轮 Data Agent 应优先验证候选机制特征：Web 扫码 / 异步登录、异常授权、登录环境突变、无历史环境、地区不匹配、token/session 异常、账号安全风险策略命中。
4. 本文件未修改核心 Skill。
5. 本轮新增文件：`outputs/reviews/ato_feature_layering_and_evidence_boundary_v1.md`。
