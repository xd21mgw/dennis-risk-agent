# ATO 客诉典型盗号路径归纳

## 1. 地推扫码欺诈

### 典型链路

```text
线下地推 / 送礼 / 助力 / 关注 / 涨人气
→ 用户扫码、授权，或短暂交出手机
→ 黑产获得扫码 / OAuth / Web 登录能力
→ Web 新设备或陌生环境获得登录态
→ 后续发布色情 / 招嫖 / 网址类内容
→ 作品删除、隐藏或账号封禁
→ 用户客诉称非本人操作
```

### Excel 中的典型表述

- “扫码送小礼品”
- “给直播间涨人气 / 充人数”
- “给她关注快手号”
- “助力一下”
- “拿走手机扫码”
- “扫完没感觉，第二天发现发了色情作品”

### 强证据

- 扫码 / OAuth 授权后出现 Web 新设备登录。
- 新设备生成 token 或登录态。
- 异常登录后发生发布行为。
- 发布设备与 Web 新设备一致。
- 风控命中扫码盗号 / Web 扫码无历史设备 / stealAccount 类策略。

### 反证

- 只有用户说“扫过码”，没有登录 / 授权 / token / 发布链路。
- 发布前后均为本人历史设备。
- 账号主动分享或授权运营行为。
- 申诉时间与数据时间不一致。

## 2. 钓鱼网站 / 钓鱼链接

### 典型链路

```text
用户点击或扫码进入仿冒页面 / 任务链接 / 会员领取链接
→ 输入手机号、短信验证码、登录信息或授权
→ 黑产 web 端 / 小程序端登录
→ 登录态被接管或 token 被置换
→ 下游发布色情 / 招嫖 / 网址类内容
```

### Excel 中的典型表述

- “购买会员，店主发链接”
- “任务 App 助力链接”
- “浏览器上传 / 自助领取”
- “输入手机号和验证码”
- “链接显示无效，之后发现被封”

### 强证据

- web 端短信验证码登录。
- 登录来源命中钓鱼风险、webday、recharge、shop 等线索。
- 新设备 / 新 IP / 异地 web 登录后发布。
- 用户历史长期未登录，但异常窗口内有 web 登录 + 发布链路。

### 反证

- 只有钓鱼来源备注，未见 web 登录或短信验证码链路。
- 用户本人有同一时间正常登录和发布行为。
- 只存在内容违规，无账号控制权变化。

## 3. 短信验证码泄露

### 典型链路

```text
用户被电话 / 任务 / 朋友请求索要验证码
→ 验证码被用于 web / app / 小程序登录
→ token 或会话被置换
→ 登录后发布、改资料、换绑或其他敏感动作
```

### Excel 中的典型表述

- “陌生人打电话要验证码”
- “朋友让我帮忙，要了手机号”
- “没收到短信提示但被登录”
- “web 端短信验证码登录”
- “短信泄露后登录微信小程序，之后置换 web 端 token”

### 强证据

- 短信验证码登录行为与异常发布时间近。
- 登录后 token/session 切换或多端冲突。
- 用户历史登录方式与本次短信登录不同。
- 风控命中验证码泄露 / 异常登录 / 风险设备。

### 反证

- 用户本人近期频繁使用验证码登录。
- 登录设备、IP、地区均为常用环境。
- 无发布 / 敏感动作 / 下游作恶。

## 4. token 泄露 / 登录态复用

### 典型链路

```text
token 被下发、复用、置换或未被风控拦截
→ 黑产绕过重新登录
→ 用户无明显登录提醒或设备变更感知
→ 下游发布、导流、招嫖或其他违规动作
```

### Excel 中的典型表述

- “风控拦截 token 仍然下发”
- “置换 web 端 token 作恶”
- “没有异地登录但出现违规作品”
- “很久没登录，突然有作品不是本人发”

### 强证据

- token 与设备 / IP / UA / 地区冲突。
- 风控拦截后仍有 token 下发或有效使用。
- token 生命周期异常延长。
- 下游发布行为与登录链路脱节，但与 token 使用链路一致。

### 反证

- 没有 token/session 数据，仅是用户感知“没登录提醒”。
- 正常多端登录或官方授权场景。
- 账号主动分享或租借。

## 5. 非盗号 / 误报 / 历史 case

### 典型链路

```text
反诈封禁 / 导流封禁 / 历史群控误伤 / 主动分享 / 租借实名
→ 用户因封禁、资料变化或作品异常发起客诉
→ 数据无法构建异常登录 → 账号接管 → 下游作恶链路
→ 应作为反证或证据不足样本
```

### Excel 中的典型表述

- “非被盗”
- “反诈封禁导致客诉”
- “导流封禁”
- “历史群控误伤”
- “账号主动分享”
- “实名租借”
- “无盗号特征”

### 证据不足或反证条件

- 用户申诉但没有异常登录。
- 有发布行为但缺登录态接管链路。
- 地区不一致但可被用户移动解释。
- 无登录记录不能解释为无风险，也不能支持盗号。
- 历史 case 不能当作当前窗口盗号事实。

## 6. 本质区分

正常人 / 正常误报：
- 可能扫码、分享、跨地区登录、长期未登录后发现封禁。
- 也可能误解反诈、导流、历史处罚原因。

黑灰产 ATO：
- 目标是获得账号控制权或登录态。
- 通过扫码、钓鱼、验证码、token/session 复用获得入口。
- 下游快速发布色情 / 招嫖 / 网址等变现内容。
- 往往存在新设备、Web 登录、token 生成、策略命中、发布链路。

最小区分点：

```text
是否能闭合“异常登录 / 授权 / token → 账号接管 → 下游作恶”的证据链。
```
