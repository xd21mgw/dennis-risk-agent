# ATO 下一轮 Data Agent 查询计划 v1

## 1. 策略调整

本轮不建议立即跑 7~10 天长周期 Hive 扩窗。

原因：
- 当前核心问题不是时间窗是否足够，而是标签体系把“ATO 发生方式”和“ATO 后下游作恶方式”混在了一起。
- 发布行为不是 ATO 成立必要条件。
- 下游作恶路径很多，先扩窗查发布可能继续强化“盗号=发布”的过拟合。
- 更低成本的做法是先按下游作恶分支做轻量探查，再决定是否需要长周期扩窗。

下一轮目标：

```text
先稳住 Web 扫码登录类 ATO 发生方式
再按下游作恶方式做低成本分支查询
最后才考虑 7~10 天长周期扩窗
```

## 2. 低成本优先级

| 优先级 | 查询方向 | 目标 |
|---|---|---|
| P0 | Web 扫码登录 / 账号接管风险策略命中 / 地区不匹配 / 无历史环境验证 | 确认 ATO 发生方式，不依赖发布 |
| P1 | 有发布 5 个样本的内容风险补证 | 验证发布内容是否色情 / 招嫖 / 导流 |
| P1 | 无发布 10 个样本的其他下游行为轻量探查 | 查点赞、关注、私信、接口访问、活动、导流、养号等 |
| P2 | 7~10 天长周期扩窗 | 仅在 P0/P1 仍无法解释时再跑 |

## 3. Plan P0：Web 扫码登录发生方式验证

### 3.1 目标

验证 15 个样本是否稳定满足 Web 扫码登录类 ATO 特征：

- ASYNC_WEB_LOGIN。
- Web 扫码 / OAuth / 授权登录。
- 账号接管风险策略或相关账号安全风险策略。
- web_% 设备。
- 无历史环境。
- 地区 / IP / UA 与历史不匹配。

### 3.2 样本范围

本批 15 个 Sheet2 地推 / 扫码样本。

### 3.3 时间窗口

```text
2026-05-04 00:00:00 ~ 2026-05-05 23:59:59
```

不先扩窗。

### 3.4 需要覆盖的数据域

- 登录 / 授权事件。
- 账号安全事件。
- 设备信息。
- IP / UA / 地区。
- 策略 / 风险画像。

### 3.5 发给 Data Agent 的问题模板

```text
请基于数据平台可查询的数据，对 15 个 ATO 地推/扫码样本做只读取证分析。

本轮只验证 ATO 发生方式，不验证最终下游作恶。

样本范围：
15 个 Sheet2 高置信地推/扫码样本，样本 ID / user_id 列表由人工提供。

时间窗口：
2026-05-04 00:00:00 ~ 2026-05-05 23:59:59。

业务场景：
账号安全 / ATO / Web 扫码登录。

请输出：
1. 是否存在 ASYNC_WEB_LOGIN、Web扫码、OAuth、授权登录。
2. 是否命中账号接管风险策略或相关账号安全风险策略。
3. 是否存在 web_% 设备、新设备、无历史环境。
4. 是否存在 IP / UA / 地区与历史不匹配。
5. 每个特征覆盖多少样本。
6. 哪些是数据发现，哪些只是推测。
7. 哪些字段或数据源缺失。

注意：
Data Agent 只输出数据发现、覆盖范围、缺失证据和口径风险。
不要输出最终风控判断。
不要要求所有样本都有发布行为。
```

### 3.6 预期返回

- Web 扫码 / ASYNC_WEB_LOGIN 覆盖率。
- 账号接管风险策略命中覆盖率。
- web_% / 无历史设备覆盖率。
- 地区 / IP / UA 不匹配覆盖率。
- 可用于回捞的高精特征组合。

### 3.7 降级规则

- 若只有 ASYNC_WEB_LOGIN 但无策略和设备异常：只能 partial_support。
- 若策略命中仅为 monitor：不能作为强处置证据。
- 若设备历史口径缺失：写入 quality_risks。
- 若返回 SQL-only：不进入 evidence。

## 4. Plan P1-A：有发布 5 个样本的内容风险补证

### 4.1 目标

对已发现有发布行为的 5 个样本，验证发布是否属于色情 / 招嫖 / 导流内容，避免把人工标签当事实。

### 4.2 样本范围

```text
05-04 ~ 05-05 短窗口内有发布行为的 5 个样本
```

### 4.3 时间窗口

```text
2026-05-04 00:00:00 ~ 2026-05-05 23:59:59
```

### 4.4 需要覆盖的数据域

- 发布 / 内容行为。
- 内容风险策略。
- 内容审核结果。
- 删除 / 隐藏 / 封禁状态。
- 发布设备 / IP / 地区。

### 4.5 发给 Data Agent 的问题模板

```text
请对 5 个已发现发布行为的 ATO 样本做只读取证分析。

目标：
验证这些发布是否存在色情、招嫖、导流或其他内容风险证据。

时间窗口：
2026-05-04 00:00:00 ~ 2026-05-05 23:59:59。

请输出：
1. 每个样本的发布数量、发布平台、发布设备、发布 IP / 地区。
2. 是否有 caption 或内容风险策略命中；如无权限请说明。
3. 是否存在删除、隐藏、封禁。
4. 发布设备是否能与 Web 扫码登录设备关联。
5. 哪些内容风险是数据发现，哪些只是人工标签。

注意：
如果 caption / 内容字段无权限，不要判断色情或招嫖内容成立。
```

### 4.6 降级规则

- caption 无权限：内容类型保持未验证。
- 只有发布记录：不能判断色情 / 招嫖。
- 发布设备无法关联登录设备：不能闭合登录发布链路。

## 5. Plan P1-B：无发布 10 个样本的其他下游行为轻量探查

### 5.1 目标

对短窗口无发布的 10 个样本，不扩窗先查其他低成本下游行为，避免把“无发布”误判为无作恶。

### 5.2 样本范围

```text
05-04 ~ 05-05 短窗口内未发现发布行为的 10 个样本
```

### 5.3 时间窗口

```text
2026-05-04 00:00:00 ~ 2026-05-05 23:59:59
```

### 5.4 需要覆盖的数据域

- 点赞 / 关注 / 评论 / 私信行为。
- 接口访问 / 资产访问。
- 活动参与 / 奖励。
- 直播间互动 / 私域导流。
- 资料变更 / 养号动作。
- 策略 / 风险画像。

### 5.5 发给 Data Agent 的问题模板

```text
请对 10 个短窗口内未发现发布行为的 Web 扫码登录类 ATO 样本做轻量只读取证分析。

目标：
不要扩展时间窗，先确认这些样本是否存在其他下游行为。

时间窗口：
2026-05-04 00:00:00 ~ 2026-05-05 23:59:59。

请分别检查：
1. 点赞、关注、评论、私信是否异常。
2. 是否存在接口访问、内容/关系链/资产访问异常。
3. 是否参与活动、领取奖励或发生提现/权益动作。
4. 是否发生直播间互动、站外导流、私域触达。
5. 是否发生账号资料变更、养号、换绑、改密、找回。
6. 是否命中相关风险策略或画像。
7. 如果均无发现，请说明是“短窗口未观察到下游动作”，不要解释为无风险。

注意：
Data Agent 只输出数据发现和缺失证据。
不要输出最终风控定性。
```

### 5.6 降级规则

- 无下游行为发现：标记为 `login_control_without_observed_downstream_abuse`。
- 数据域缺失：标记 `downstream_behavior_uncovered`。
- 只有低频互动：不能直接判断作恶。
- 只有策略 monitor：不能作为强打击证据。

## 6. Plan P2：7~10 天长周期扩窗

### 6.1 触发条件

仅在以下情况触发：

- P0 已确认 Web 扫码 ATO，但 P1 无法解释下游行为。
- 用户自述 / 人工备注强指向后续封禁或发布，但短窗口未覆盖。
- 需要验证发布、删除、封禁是否发生在后续日期。
- 需要做批量回捞召回率评估。

### 6.2 时间窗口

```text
2026-05-04 00:00:00 ~ 2026-05-14 23:59:59
```

### 6.3 查询目标

- 发布 / 删除 / 隐藏 / 封禁。
- 内容风险策略。
- 社交封禁。
- 申诉 / 解封。
- 活动 / 互动 / 接口访问长期行为。

### 6.4 降级规则

- 扩窗仍无下游动作：仍不能反向排除 ATO，只能说明“长窗口未观察到下游作恶”。
- 权限不足：不得强结论。
- SQL-only：不进入 evidence。

## 7. 是否需要现在再跑 7~10 天 Data Agent

建议：否。

当前更优先：

```text
P0 稳定 Web 扫码登录发生方式
P1 对下游作恶做分支轻量探查
P2 再按需扩窗
```

## 8. 当前可以明确沉淀的规则

- ATO 发生方式和下游作恶方式必须拆开。
- Web 扫码登录类 ATO 可以独立成类。
- 发布异常内容不是 ATO 成立必要条件。
- 无发布行为不能反向排除 ATO。
- 发布色情 / 招嫖必须有内容证据，不能只靠人工标签。
- 短窗口未发现下游动作，只能说明“尚未观测到”，不能说明无风险。

## 9. 仍需后续数据验证

- 15 个样本中 Web 扫码 / 账号接管风险策略命中 / web_% / 无历史环境的逐样本命中。
- 5 个有发布样本的内容风险。
- 10 个无发布样本是否存在互动、接口访问、活动、导流、养号等其他下游动作。
- 长窗口是否补充发现发布、删除、封禁。

## 10. 是否建议回写 account_security_expert_skill

暂不回写，先作为 review / eval 规则沉淀。

原因：
- 本轮仍是 15 个样本的小批量验证。
- 下游作恶分支尚未验证。
- 具体覆盖率不应写入 Skill。

后续如果 P0/P1 结论稳定，可轻量回写通用规则：
- ATO 发生方式与下游作恶方式拆分。
- Web 扫码登录类 ATO 不依赖发布行为。
- 无发布不是非盗号反证。
- 发布内容必须由内容证据支持。
