# RTA 渠道抢量劫持沉淀

## 背景

用户反馈：站外投放抢量分析不能只看点击和激活，年度总结材料里有“商店 RTA 信息”相关链路，应纳入渠道抢量劫持识别。

## 核心结论

渠道抢量的核心不是点击异常，而是渠道没有真实参与用户触达，却通过转发、拼接或伪造 RTA/曝光/点击/归因信号，抢走自然量、商店量或其他渠道的归因和结算。

## 本质标识

- 正常渠道：媒体下发 RTA 信息，广告真实曝光，用户真实点击，经商店下载、安装、激活后形成连续归因链路。
- 抢量渠道：不真实影响用户，只在归因前后插入可记账信号，或把不同来源的 RTA、点击、设备、激活拼成一条假链路。
- 最小区分点：RTA、曝光、点击、商店下载、激活、端内归因是否属于同一条真实用户链路。

## 核心手法

| 手法 | 核心破绽 | 验证动作 |
|---|---|---|
| 直接转发 RTA 信号 | 数据不全 | 推动上报全量真实信息，补齐曝光、点击、下载上下文 |
| 拼接多 RTA 信号 | 数据关联异常 | 做 IP、机型、设备、媒体、时间、广告位一致性校验 |
| 自有 ADX SDK 伪造点击 | 非真实点击 | 用自然 SDK 验证真实点击周期 |
| 点击注入/点击洪泛 | 抢最后归因 | 查 CTIT、点击次数、点击曲线、归因窗口占坑 |
| 渠道参数/商店链路污染 | 归因口径被覆盖 | 比对商店下载来源、渠道参数、MMP 归因 |

## 统计策略

单 adid：
- CTIT 异常；
- 点击次数过多；
- 点击曲线失刺或异常平滑；
- RTA 高比例重合。

多 adid：
- adid 团组设备相似度高；
- 多 adid 触达设备占比高；
- 首次触达占比低；
- 作案设备下 adid 扩散。

## 应用链路

```text
媒体下发 RTA 信息
→ 广告曝光
→ 代理上传真实点击
→ 端内归因统计
→ CPA 调价
→ CPA 结算
→ 结算后诉讼
```
