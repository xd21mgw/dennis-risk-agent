# ATO 客诉结构化沉淀质量验收

## 1. 验收结论

当前 5 份结构化输出可以作为 Dennis Risk Agent 后续账号安全 / ATO 回归、批量匹量和 Data Agent 取证模板的基础资产。

结论等级：可用，但不能单独作为完整账号安全评估集。

主要原因：
- 已正确区分 Sheet1 / Sheet2 / info 的样本定位。
- 已沉淀标签体系、典型路径、匿名回归 case 和 Data Agent query_intent 模板。
- 已保留“用户自述 / 人工备注 / 数据待验证”的边界。
- 已避免暴露完整 user_id。
- 主要不足是 Sheet2 正例集中，容易过拟合近期欺诈盗号样本，需要 Sheet1 反例和历史样本补齐。

## 4. 主要风险

1. Sheet2 正例集中，不能单独代表账号安全全量风险。
2. 人工备注中“已回捞 / 未回扫 / 来源线索”混在 `盗号具体原因`，后续若直接解析容易误当事实。
3. 作恶类型集中在色情 / 招嫖，缺其他下游作恶类型。
4. token 泄露、租借账号、历史 case、误伤样本量不足。
5. 现有 case 资产能用于回归，但不能作为最终策略效果评估集。

## 5. 是否适合回写 Skill

建议轻量回写 account_security_expert_skill 的通用规则：

- 地推扫码欺诈路径。
- 钓鱼欺诈路径。
- 短信验证码泄露路径。
- token/session 泄露路径。
- 用户申诉 / 人工备注不是事实，只能作为线索。
- 非盗号、历史 case、不确定样本的反证规则。

不建议回写：

- 具体 user_id。
- 单次 Excel 的具体分布。
- 个别人工备注原文。
- 具体作恶内容细节。
- 某一批样本中的具体来源字符串。

## 6. 是否需要先跑 Data Agent 批量验证

建议先跑小批量 Data Agent 验证，再决定是否大范围回写。

优先验证：
- Sheet2 地推扫码正例 5-10 条。
- Sheet2 钓鱼 / web 短信验证码登录正例 5-10 条。
- Sheet1 非盗号 / 不确定 / 历史 case 5-10 条。
- token 泄露 / CP token 下发线索 3-5 条。

验证目标：
- 人工标签是否能被登录 / 授权 / token / 发布链路支撑。
- 回捞 / 未回扫能否被数据验证。
- Sheet1 反例是否能有效降低误判。

## 7. 最终验收结论

当前结构化资产可以进入：

- ATO 离线回归。
- Data Agent 批量取证设计。
- 账号安全 Skill 后续轻量回写候选。
- 批量 case registry 种子样本。

但不应单独用于：

- 完整账号安全评估集。
- 误伤率评估。
- 长周期稳定性评估。
- 自动化处罚或策略上线依据。
