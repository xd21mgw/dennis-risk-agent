# Sheet2 样本标签分层修正建议

## 1. 修正背景

本批 15 个 Sheet2 高置信地推 / 扫码样本经 Data Agent 短窗口只读取证后发现：

- ASYNC_WEB_LOGIN 覆盖 13/15，支持 Web 扫码登录类 ATO 方向。
- 仅 5/15 在 2026-05-04 ~ 2026-05-05 短窗口内有发布行为。
- 10/15 在短窗口内未发现发布行为。
- caption 和 upload_timestamp 权限不足，无法验证内容类型和短时间集中发布。
- 发布行为相关特征覆盖率低，不适合作为独立回捞主特征。

业务先验进一步说明：盗号后的下游作恶不一定是发布异常内容，也可能是点赞、关注、评论、私信、爬虫、资产窃取、活动套利、直播间截流、账号交易、养号、转生，或者仅登录控制但尚未观测到明显作恶。

因此标签体系必须拆成两层：

```text
ATO 发生方式
→ ATO 后下游作恶方式
```

## 2. 第一层：ATO 发生方式

第一层描述账号控制权如何被获得，不描述下游作恶。

| 一级标签 | 含义 | 本批适用性 |
|---|---|---|
| Web 扫码登录类 ATO | 扫码 / OAuth / Web 异步登录导致账号登录态被接管 | 本批 15 个样本优先沉淀为此类 |
| 地推扫码 / 助力诱导类 ATO | 线下地推、送礼、助力、关注、拿手机等诱导完成扫码或授权 | 本批人工线索强，但需用 Web 扫码登录证据验证 |
| 钓鱼 / 验证码泄露类 ATO | 钓鱼链接、会员领取、任务链接、短信验证码泄露导致登录 | Sheet2 其他样本适用，本批不是主线 |
| token/session 泄露类 ATO | token 下发、复用、置换、多端冲突导致登录态被接管 | 本批未形成主证据 |
| 账号租借 / 交易类 | 用户主动或半主动交出账号、实名、登录能力 | 作为 ATO 反证或边界类 |
| 非盗号 / 历史 / 不确定 | 反例、历史 case、证据不足、误报 | 回归集需要配平 |

## 3. 第二层：ATO 后下游作恶方式

第二层描述账号被控制后做了什么。它不是 ATO 成立的必要条件。

| 二级标签 | 含义 | 取证要求 |
|---|---|---|
| 发布色情 / 招嫖 / 导流内容 | 发布色情、招嫖、网址、导流等内容 | 发布记录 + caption / 内容识别 / 内容风险策略 |
| 批量点赞 / 关注 / 评论 / 私信 | 使用账号做社交互动或骚扰 | 点赞、关注、评论、私信行为日志 |
| 爬虫 / 接口访问 / 资产窃取 | 使用登录态访问内容、关系链、库存、价格、账号信息等资产 | 接口访问、资产访问、前后端链路 |
| 活动套利 / 抢福利 | 使用账号参与活动、领取奖励、提现或转移权益 | 活动参与、奖励、提现、邀请关系 |
| 直播间截流 / 私域导流 | 使用账号在直播间、私信、评论、主页等触达并导流 | 触达链路、私信/关注/搜索、站外承接 |
| 账号交易 / 养号 / 转生 | 接管后转卖、养号、换绑、改资料、转生 | 换绑、改密、资料变更、登录主体变化 |
| 仅登录控制，尚未观测到明显作恶 | 已有登录态接管或异常登录，但短窗口内未见下游动作 | 登录/授权/策略证据，且下游行为查询为空 |
| 未验证 / 权限不足 | 下游行为受权限或数据覆盖限制无法判断 | caption、upload_timestamp、实时链路或行为日志缺失 |

## 4. 本批 15 个样本的标签修正

### 4.1 发生方式

本批 15 个样本应优先沉淀为：

```text
Web 扫码登录类 ATO
```

可补充场景线索：

```text
地推扫码 / 助力诱导类 ATO 线索
```

理由：
- ASYNC_WEB_LOGIN 覆盖 13/15。
- Web 扫码 + stealAccount 策略 + web_% 设备覆盖 40%+。
- 扫码 + 地区不匹配 + 无历史环境覆盖 33%+。

### 4.2 下游作恶方式

5 个样本可标记：

```text
Web 扫码登录类 ATO
→ 有发布行为子集
→ 内容类型未验证 / 权限不足
```

说明：
- 有发布行为。
- caption 无权限，不能验证色情 / 招嫖内容。
- upload_timestamp 无权限，不能验证短时间集中发布。

其余 10 个样本应标记：

```text
Web 扫码登录类 ATO
→ 短窗口未发现发布
→ 不等于无作恶
→ 下游作恶方式待验证
```

说明：
- 不应强行打“发布异常内容”标签。
- 也不能把“无发布”作为非盗号反证。
- 下游可能是点赞、关注、评论、私信、爬虫、活动套利、导流、养号，或尚未发生明显作恶。

## 5. 关键规则

### 5.1 ATO 成立不依赖发布行为

```text
发布异常内容不是 ATO 成立的必要条件。
```

ATO 的核心是账号控制权或登录态被异常获得。发布内容只是其中一种下游作恶方式。

### 5.2 无发布不能反向排除 ATO

```text
短窗口未发现发布 ≠ 没有盗号，也 ≠ 没有下游作恶。
```

可能原因：
- 下游作恶发生在窗口外。
- 下游不是发布，而是点赞、关注、私信、接口访问、活动套利等。
- 数据权限或日志覆盖不足。
- 黑产仅完成登录控制，尚未动作。

### 5.3 发布标签必须降级为子标签

以下都只能作为下游作恶子标签，不应作为 ATO 一级标签：

- 发布异常内容。
- 色情 / 招嫖内容。
- 短时间集中发布。
- 批量刷屏。
- 发布后删除 / 隐藏。

### 5.4 人工内容标签不是事实

以下只能作为人工线索：

- `色情视频-网址`
- `招嫖视频-微信`
- `招嫖视频-钱`
- `已回捞`
- `扫码后发布`

需要 caption、内容识别、内容策略、发布记录、回捞记录验证后才能升为数据发现。

## 6. 降级与分层规则

如果有 Web 扫码 / 异步登录证据，但无下游动作：

```text
Web 扫码登录类 ATO / 仅登录控制，尚未观测到明显作恶
```

如果有发布但无内容权限：

```text
Web 扫码登录类 ATO / 有发布行为 / 内容类型未验证
```

如果有人工色情/招嫖标签但无 caption 或内容策略：

```text
Web 扫码登录类 ATO / 下游作恶人工线索 / 内容未验证
```

如果只有人工标签或用户自述：

```text
manual_hint_only / evidence_pending
```

## 7. 对回归集的影响

应新增或保留四类回归样本：

1. Web 扫码登录类正例：命中扫码 / Web 登录 / 策略 / 新设备等登录链路。
2. Web 扫码登录但短窗口无发布：验证“无发布不是反证”。
3. 有发布但内容不可验证：验证“发布不是内容事实”。
4. 下游作恶方式未验证：验证不会把未知下游强行归因到发布。

## 8. 结论

本批样本标签应从：

```text
地推/扫码盗号后发布异常内容
```

修正为：

```text
ATO 发生方式：Web 扫码登录类 ATO
下游作恶方式：
├── 5 个：有发布行为，内容类型未验证
└── 10 个：短窗口未发现发布，不等于无作恶
```

这能避免两个过拟合：
- 把所有 Web 扫码 ATO 绑定到发布异常。
- 把短窗口无发布误当作非盗号反证。
