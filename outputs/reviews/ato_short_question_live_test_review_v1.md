# ATO 短问入口实测回归 v1

## 1. 回归目的

验证 Dennis 子 Agent 面对真实策略同学常见的 1-3 句话短问时，是否能够：

- 正确识别 intent；
- 判断信息是否足够；
- 信息不足时追问关键字段；
- 不强行判断 ATO；
- 给出最小补证路径；
- 不默认触发长周期 / 大样本 / 多表 join；
- 必要时生成低成本 DataAgent 取证方向。

本轮不调用 Data Agent，不修改核心 Skill。

## 2. Test A：信息不足型

### 用户短问

“这个用户是不是被盗？”

### 识别 intent

`single_case_judgement`

### 信息是否足够

不足。

### 是否需要追问

需要。

### 是否需要 DataAgent

暂不直接触发。应先补最小输入。

### 默认最小动作

先追问：

- `user_id` / `case_id`
- 异常时间
- 用户自述或异常行为
- 是否已有 DataAgent 返回

### 实际或预期简短回答

当前不能直接认定盗号。你先补 `user_id` / 异常时间 / 用户自述或异常行为 / 是否已有 DataAgent 返回，我再给最小补证路径。只有自述或人工备注不能当事实。

### 是否符合 `ato_agent_response_contract_v1.md`

符合。

### 是否存在误判风险

有。主要风险是把用户自述或人工备注当成事实，或者在信息不足时强行给 ATO 结论。

### 是否需要修改 ATO router / response contract

不需要。

---

## 3. Test B：边界纠偏型

### 用户短问

“这批没发布，是不是就不是盗号？”

### 识别 intent

`single_case_judgement`

### 信息是否足够

足够给原则性纠偏。

### 是否需要追问

不一定。若要继续判断样本，仍可补样本范围和时间窗。

### 是否需要 DataAgent

若用户要继续查证据，需要；但当前这句短问本身可先直接纠偏。

### 默认最小动作

直接纠偏：

- 无发布不能反向排除 ATO；
- 发布只是 ATO 后下游作恶方式之一；
- 盗号后也可能点赞、关注、评论、私信、爬虫、接口访问、活动套利，或者仅登录控制；
- 仍需看登录 / 授权 / 设备 / IP / token/session 等接管链路。

### 实际或预期简短回答

不能。无发布不等于不是盗号。发布只是下游作恶方式之一，盗号后也可能只做点赞、关注、评论、私信、爬虫、接口访问、活动套利，甚至只发生登录控制。要看登录 / 授权 / 设备 / IP / token/session 等接管链路。

### 是否符合 `ato_agent_response_contract_v1.md`

符合。

### 是否存在误判风险

有。主要风险是把“无发布”误当作非盗号反证，或者误以为需要先查长周期才能判断边界。

### 是否需要修改 ATO router / response contract

不需要。

## 4. Test C：DataAgent 解释型

### 用户短问

“DataAgent 说有异步登录，这能不能认？”

### 识别 intent

`dataagent_result_interpretation`

### 信息是否足够

不足以直接认定 ATO。

### 是否需要追问

需要补充 DataAgent 原始返回和查询状态，至少要知道是否还有：

- Web 扫码 / OAuth / 授权链路；
- 登录环境突变；
- 新设备 / 新 IP / 新 UA / 新地区；
- 账号安全风险策略命中；
- token/session 异常；
- 下游行为。

### 是否需要 DataAgent

如果用户已经贴了 DataAgent 返回，则先解释返回；如果只有一句“有异步登录”，应先补上下文，而不是继续默认触发长查询。

### 默认最小动作

把“异步登录”当作风险线索，而不是结论。优先确认是否存在完整接管链路，再决定是否需要补证。

### 实际或预期简短回答

不能只凭“异步登录”认定 ATO。它只是一个风险线索，还要看是否有 Web 扫码 / OAuth / 授权链路、登录环境突变、新设备 / 新 IP / 新 UA / 新地区、账号安全风险策略命中、token/session 异常和下游行为。DataAgent 只是 evidence provider，最终判断仍由 Dennis Agent 出。

### 是否符合 `ato_agent_response_contract_v1.md`

符合。

### 是否存在误判风险

有。主要风险是把单一异步登录信号当成足够证据，或者把 DataAgent 的提示当最终结论。

### 是否需要修改 ATO router / response contract

不需要。

## 5. 汇总结论

### 1. 3 个短问是否通过

通过。

### 2. 短问回答是否足够短

是。都保持在短答模式，没有展开成长报告。

### 3. 是否存在过度分析问题

未见明显过度分析。Test A 先追问最小字段，Test B 直接纠偏，Test C 先降级为线索解释。

### 4. 是否存在过度依赖 DataAgent 问题

未见明显过度依赖。只有在用户明确要继续查证据时，才会建议 DataAgent 最小取证问题。

### 5. 是否存在强判风险

已控制住。没有在信息不足、无发布、单一异步登录等场景下直接强判 ATO。

### 6. 是否需要继续修改 ATO overlay

暂不需要。

### 7. 是否需要修改通用 scenario contract

暂不需要。

### 8. 是否修改核心 Skill

否。

### 9. 下一步是否可以进入 1-2 个真实盗号同学试问

可以。建议先用 1-2 个真实问法做小范围试问，重点观察：

- 短问是否先追最小字段；
- 是否避免把线索当事实；
- 是否能给到足够短且可执行的下一步；
- 是否会误触发长周期查询。
