# Case BI-006 回归评审

## 原始问题

一个风险 case 如何拆作恶方、上游资源、中游执行、下游变现？

## Skill 路由

- 主控 Skill：risk_chain_reconstruction_skill
- 辅助 Skill：attack_type_classification_skill、evidence_decomposition_skill、risk_governance_design_skill、business_domain_map_skill

## 回答

一句话判断：拆黑产本质不能从“异常现象”开始定性，要把 case 还原成作恶方、资源、执行、变现、平台损害和治理断点，最后再判断主风险类型和混合风险。

领域归类：黑灰产基建。

风险类型：通用混合攻击分析框架，可覆盖协议、群控、破解包、真人众包、小号、渠道套利、规则漏洞等。

标准拆解框架：

```text
作恶方
→ 上游资源
→ 目标获取
→ 攻击入口
→ 中游执行
→ 下游变现
→ 平台损害
→ 治理断点
→ 迁移观察
```

关键问题：
- 作恶方是谁：个体羊毛党、任务平台、群控团队、数据商、账号商、渠道商、竞品、内部/合作方泄漏。
- 上游资源是什么：账号、设备、IP、token、实名、支付账户、代理渠道、风险 App、目标名单、接口知识。
- 中游如何执行：协议直打、群控真机、破解包绕采集、真人众包、规则套利、渠道抢量、混合接力。
- 下游如何变现：提现、补贴、流量指标、账号出售、数据售卖、导流成交、渠道结算、竞品情报。
- 平台哪个环节被利用：注册、登录、展示、搜索、任务、发奖、结算、提现、私信、合作方接口。
- 哪个节点最适合治理：优先选收益链路、核心入口、强身份/设备绑定、结算扣除和产品机制漏洞。
- 如何抬升黑产成本：提高账号/设备/验证/任务/结算成本，降低单账号收益和复用效率。
- 如何观察迁移：看协议降后是否转群控、群控打后是否转真人、收益冻结后是否换提现主体。

证据体系：
- 强证据：完整链路可闭合，账号-设备-IP-目标-收益形成团组，外部情报或下游结果能与内部行为匹配。
- 中证据：部分链路闭合，如执行路径和收益聚集明确，但上游资源来源未确认。
- 弱证据：只有高频、聚集、低质、投诉、报价变化。
- 反证 / 误判：正常运营、热点传播、合法自动化、渠道口径差异、埋点缺失、内部测试、普通用户规则套利。

补证动作：
- 用事件时间线还原首次异常、规模化、收益发生、处置后迁移。
- 拉通账号、设备、IP、行为、业务结果、支付/提现、外部情报。
- 对每条链路标注“已证实 / 高怀疑 / 未证明”。
- 补缺口：上游来源、执行工具、收益归集、外部承接、正常业务解释。

治理方案：
- 短期止血：针对收益和高风险入口做冻结、限权、限额、延迟结算。
- 中期治理：把 case 抽象为攻击类型、资源类型、业务场景三层策略。
- 长期能力：建设黑灰产基建画像，包括账号池、设备池、代理池、风险 App、提现主体和渠道质量。

灰度策略：
- 高置信链路闭合才强处置。
- 链路不完整时先加采、限额、延迟结算。
- 对合法自动化、运营矩阵、合作方访问做授权登记和审计。
- 每次策略上线都记录黑产迁移和业务损伤。

评估指标：
- 黑产发生量、链路闭合率、收益拦截/回收金额、策略准确率、漏过量、误伤率、迁移路径、黑产成本变化、业务钱效。

可沉淀资产：
- 风险链路模板、黑产资源图谱、case 复盘卡片、治理断点库、迁移监控看板、测试 case 生成规则。
