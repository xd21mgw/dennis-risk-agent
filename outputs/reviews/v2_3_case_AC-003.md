# v2.3 Executable 回归：AC-003

## Case 信息

- Case：AC-003
- 问题：如何明确一个攻击是单纯协议类攻击，而不是群控、破解包或真人众包？
- 目标 Skill：protocol_attack_expert_skill

## 路由

- 主控 Skill：protocol_attack_expert_skill
- 辅助 Skill：attack_type_classification_skill、evidence_decomposition_skill
- 触发原因：用户要做“单纯协议”定性，并显式要求排除群控、破解包、真人众包。

## 输入充分性

输入是判定问题而非具体 case，数据不足以定性某个攻击，但足以输出单纯协议的执行判定规则、反证边界和最小补证动作。

## 判断规则命中

命中 protocol_attack_expert_skill 判断规则第 1 条：如果服务端请求无对应页面/事件链，接口调用顺序不符合正常 App 路径，且强目标接口直接命中，则判断为高置信单纯协议。

同时命中第 6、7、8、9 条排除约束：端行为完整且调度异常转群控；SDK/包异常转破解包；只有高频不得判协议；合法自动化或埋点缺失需降级。

## 一句话判断

单纯协议必须证明请求脱离正常端侧执行链，同时排除端行为缺失不是埋点问题、破解包绕采集、群控真机或真人众包造成的。

## 证据分层

强证据：
- 服务端请求无对应页面曝光、点击、冷启动、初始化事件；
- 接口调用顺序不符合 App 正常路径；
- 强目标接口被直接命中；
- 参数缺端生成痕迹，签名复用或时效异常；
- token 与设备/IP/UA/SDK 环境冲突；
- 请求可被脚本稳定复现。

中证据：
- 接口序列过短；
- 设备身份存在但行为链不完整；
- refresh token 或签名刷新链路异常；
- 同模板请求多账号复用；
- 业务收益动作紧随接口直达。

弱证据：
- 高频请求；
- IP 聚集；
- 单接口 QPS 上涨；
- UA 相似；
- 账号画像低质。

## 反证与误判

- 埋点缺失或采集口径错误；
- 端行为完整但被群控统一调度；
- 破解包绕 SDK 采集导致“像协议”；
- 真人众包有真实端行为但任务化；
- 合法商家/机构自动化；
- 弱网重试、版本差异或网关采样缺失。

## 补证动作

- 前后端 join：服务端请求与页面曝光、点击、冷启动、SDK 事件关联；
- SDK 日志：确认是否采集缺失、版本差异或绕采集；
- token/设备/IP/UA 一致性校验；
- 接口序列还原：是否跳过上游页面路径；
- 签名生成链路：是否复用、过期、缺端生成痕迹；
- 强目标跳转：是否直接命中奖励、下载、资产、登录等目标接口；
- 合法自动化审计：授权、限额、来源、用途。

## 治理方案

- 高置信单纯协议：敏感接口强拦、签名升级、上下文绑定、token 失效；
- 中置信协议：限流、挑战、二次验证、加采；
- 低置信异常：监控、灰度、补 SDK 和端侧日志；
- 合法自动化：登记、授权、配额、审计，不一刀切打击。

## 灰度策略

先覆盖强目标敏感接口和高置信无端请求；中置信仅挑战或限流；保留合法自动化白名单；上线前后监控误伤、客诉、接口成功率和黑产迁移到群控/真人的比例。

## 评估指标

无端请求占比、前后端冲突率、接口固化命中、协议发生量、漏过量、误伤率、客诉、合法自动化误杀量、迁移到群控/真人比例。
