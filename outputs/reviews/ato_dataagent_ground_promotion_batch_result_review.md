# ATO 地推/扫码批量 Data Agent 只读取证结果解析

## 1. 原始 Data Agent 返回摘要

样本范围：
- 《二次核查盗号客诉分析.xlsx》Sheet2 中 15 个高置信地推 / 扫码类盗号样本。
- 查询时间窗口：2026-05-04 ~ 2026-05-05。
- Data Agent 角色：evidence provider，不做最终风控裁判。

核心返回：
- 仅 5/15 样本在窗口内存在发布行为，占 33%。
- 10/15 样本在窗口内未发现发布行为，占 66%+。
- 共 9 条作品，平均每个有发布样本约 1.8 条；无批量刷屏特征。
- 发布平台以 Android 为主，7/9，占 77.8%；PC Web 为 2/9。
- 作品均在 2026-05-04 ~ 2026-05-05 日期内发布。
- caption 无权限，无法验证是否色情 / 招嫖内容。
- upload_timestamp 无权限，无法验证短时间集中发布。
- ASYNC_WEB_LOGIN 覆盖 13/15，占 86.7%，与扫码登录链路高度吻合。
- 0 条换绑 / 改密 / token 被踢事件。
- 个别样本有社交封禁 1 个、注销尝试 1 个。

## 2. data_findings

数据发现：
- 本批样本更稳定的共性是 Web 扫码 / 异步 Web 登录，而不是发布行为。
- ASYNC_WEB_LOGIN 覆盖率 86.7%，是本批最强的批量共性。
- 发布行为覆盖率仅 33%，不支持把全部 15 个样本归为“扫码后发布异常内容”。
- 已发现发布的 5 个样本可作为“有发布行为子集”，但内容类型不可验证。
- 其余 10 个样本应标记为“扫码登录异常，窗口内未发现发布”，不能强行打发布异常标签。
- 换绑、改密、token 被踢在本窗口内均为 0，不支持把本批归为换绑 / 改密 / token 踢出型 ATO。

## 3. provider_conclusion_hint

Data Agent 的结论性表达只能进入 provider_conclusion_hint：

```text
数据支持“扫码登录类盗号”批量回捞特征。

建议扩展时间窗至 7~10 天。
建议分层分析：有发布 5 个 vs 无发布 10 个。
高精准特征组合可用于回捞“Web 扫码登录类盗号”，不限定发布内容类。
```

## 4. strong_evidence

强证据：
- ASYNC_WEB_LOGIN 覆盖 13/15，占 86.7%，与扫码 / Web 授权登录链路高度一致。
- Web 扫码 + stealAccount 策略 + web_% 设备组合覆盖 40%+，可作为高精准 Web 扫码登录类 ATO 回捞特征。
- 扫码 + 地区不匹配 + 无历史环境组合覆盖 33%+，具备较低误伤的账号接管线索。

边界：
- 这些强证据支持“Web 扫码登录类 ATO”，不直接支持“全部样本均发生发布异常内容”。

## 5. medium_evidence

中证据：
- 5/15 样本存在发布行为，可支持“有发布行为子集”。
- 9 条作品均在查询窗口内发布，说明部分样本存在登录后下游动作。
- Android 发布占 77.8%，提示部分发布可能发生在移动端环境，但仍需结合登录 / 授权 / 设备链路判断。
- 个别样本出现社交封禁、注销尝试，可作为后续分层补证线索。

## 6. weak_evidence

弱证据：
- 人工标签倾向“扫码后发布色情 / 招嫖内容”。
- Sheet2 用户自述普遍包含扫码、地推、助力、送礼等线索。
- 作恶类型字段中的色情 / 招嫖标签。

说明：
- 以上仍属于人工表格线索或用户自述，不是本次 Data Agent 已验证的数据事实。

## 7. counter_evidence

反证 / 修正证据：
- 10/15 样本在 2026-05-04 ~ 2026-05-05 窗口内未发现发布行为。
- 66%+ 无发布，直接反驳“15 个样本全部扫码后发布异常内容”的强标签。
- 共 9 条作品，无批量刷屏特征，不能支持批量内容轰炸判断。
- caption 无权限，不能证明作品是色情 / 招嫖内容。
- upload_timestamp 无权限，不能证明短时间集中发布。
- 0 条换绑 / 改密 / token 被踢，不支持把本批归为换绑、改密或 token 踢出型。

## 8. missing_evidence

缺失证据：
- caption / 内容文本，无法验证色情 / 招嫖内容类型。
- upload_timestamp，无法验证分钟级集中发布。
- 内容风险策略命中，无法验证内容是否被模型或策略判为色情 / 招嫖。
- 发布后删除 / 隐藏 / 封禁完整链路。
- 05-04 ~ 05-05 之外的发布行为。
- 实时扫码流程、二维码内容、实时设备指纹。
- token/session 生命周期。

## 9. quality_risks

质量风险：
- 时间窗口仅 2 天，可能漏掉 05-04 之前或 05-05 之后的发布、删除、封禁。
- 发布字段权限不足，导致发布内容与集中发布时间无法验证。
- 人工标签可能混入“仅扫码登录未发布”类样本。
- ASYNC_WEB_LOGIN 是登录链路证据，不等同下游发布或内容违规证据。
- 样本来自 Sheet2 高置信正例池，缺少反例对照，不能单独估计误伤。

## 10. provider_limitations

Data Agent-only 限制：
- 只能覆盖离线 / Hive / 聚合取证。
- 不能充分覆盖实时扫码流程。
- 不能充分覆盖实时设备指纹。
- 不能充分覆盖 token/session 全生命周期。
- caption、upload_timestamp 权限限制会影响内容类结论。
- provider_conclusion_hint 不等于最终人工定性。

## 11. dennis_final_judgement

Dennis 主 Agent 判断：

```text
本批 15 个样本当前最多可稳定归为“Web 扫码登录类 ATO 高置信候选”，不应整体归为“扫码后发布异常内容类 ATO”。
```

具体判断：
- Web 扫码登录 / 异步 Web 登录是本批最稳定主线。
- 发布行为只覆盖 5 个样本，应拆成“有发布行为子集”。
- 10 个无发布样本应降级为“扫码登录异常，窗口内未发现发布”，等待扩展时间窗验证。
- 色情 / 招嫖作恶标签当前只能作为人工线索，不能作为数据事实。
- 发布相关回捞特征不适合作为独立回捞条件；更适合用 Web 扫码 + stealAccount 策略 + web_% 设备 / 无历史环境 / 地区不匹配做主特征。

结论等级：
- 批量层面：`partial_support_for_web_scan_ato`
- 发布异常内容层面：`insufficient_support_for_full_batch_publish_abuse`
- 需要人工复核：true
