# v2.3 cracked_app_expert_skill 执行型升级说明

## 修改摘要

已将 `cracked_app_expert_skill.md` 从 v2.1 短结构升级为 v2.3 executable-deep 结构，补齐 0-10 章：

- Skill 定位
- 触发条件
- 输入格式
- 专家认知
- 判断规则
- 证据体系
- 输出格式
- 治理闭环
- 禁止行为
- 质量校验
- 失败处理

本次升级重点解决 MIX-010 暴露的问题：破解包绕 SDK 会让 protocol Skill 看到“前端无日志”，但本质可能是客户端完整性问题，不能直接按单纯协议处置。

## 新增判断规则

1. 无前端日志或 SDK 日志缺失，且包签名、版本/渠道、SDK 模块、安全模块、dex/so/assets 任一工件异常时，优先进入破解包判断，不直接判协议。
2. 无端行为、接口序列异常、强目标接口直达，但没有包签名、SDK、版本、渠道或样本证据时，进入协议补证。
3. 官方签名、官方版本、官方渠道也同样缺日志或采集异常时，优先考虑官方包埋点缺失、SDK 采集口径、网关采样或版本灰度问题。
4. 端行为存在且 SDK 日志可信，但同批启动/停止、路径节奏一致、设备/账号/收益成团时，进入群控判断。
5. 存在插件、辅助功能、动态加载 dex/so/assets、hook、root、脚本控制或外挂 UI 时，进入插件辅助或破解包 + 插件混合攻击判断。
6. 包签名异常、同包名不同签名、非官方渠道分发、Manifest/权限/导出组件异常，且风险请求集中来自该类包时，判断为中高置信破解包。
7. 安全模块被替换、SDK 缺失、方法级短链证明关键安全/采集方法被绕过，且风险请求与异常包闭合时，判断为高置信破解包。
8. 只有前端无日志、低质账号、IP 聚集、接口 QPS 上升，而无包工件证据时，不得定性破解包，只能多分支补证。
9. 存在官方测试包、灰度包、企业内部分发、渠道包差异、采集降级、兼容性问题等反证时，必须降级或转授权/埋点治理。

## 与 protocol_attack 的边界

- protocol 的核心是请求脱离端侧执行链：无端链路、接口序列异常、强目标接口直达、参数/签名/token/设备链路冲突。
- cracked app 的核心是客户端工件或采集/安全模块被改造：包签名、版本/渠道、SDK、安全模块、dex/so/assets、Manifest、runtime、方法级短链异常。
- 前端无日志不是协议强证据。若伴随包签名/SDK/版本/安全模块异常，应先走破解包；若完全没有包证据，再走协议补证。
- 官方包也缺日志时，优先考虑埋点缺失、SDK 采集口径、网关采样或版本灰度，不应强判协议或破解包。

## 与 group_control 的边界

- group control 的核心是统一调度：同批启动/停止、路径节奏一致、账号-设备-IP-收益成团。
- cracked app 的核心是客户端被改造：工件、签名、SDK、安全模块、runtime 或方法级证据异常。
- 如果端行为存在且 SDK 日志可信，但设备/路径/收益明显成团，应优先群控。
- 如果群控设备使用异常签名包、SDK 缺失包或动态加载插件，则属于群控 + 破解包混合攻击，需要两个 Skill 联动。

## 仍需补充的真实字段

后续落地还需要接入或约定字段，不在本次 Skill 中编造：

- 包签名：包名、签名摘要、证书指纹、签名校验结果。
- 版本 / 渠道：versionCode、versionName、channel_id、灰度批次、分发来源。
- Manifest / 权限 / 导出组件：权限列表、exported activity/service/receiver/provider、deeplink。
- 工件 diff：dex hash、so hash、assets hash、安全模块版本、SDK 模块版本。
- SDK 覆盖：端 SDK 初始化、曝光、点击、冷启动、设备指纹、风控事件覆盖率。
- runtime：前台 activity、截图、窗口栈、行为轨迹、hook/root/调试状态。
- 方法级短链：关键采集/验签/设备指纹/风控方法调用链、绕过点、返回值异常。
- 风险关联：风险请求、异常包、设备、账号、行为、收益、外部分发样本的 join key。

## 回归结论

升级后 cracked_app_expert_skill 已能承接 MIX-010 类型 case：破解包绕 SDK 导致前端无日志、服务端强目标接口直达。当前稳定判断应是“协议/破解包多分支，先证明包签名、SDK、hook、工件异常，再定混合协议”，而不是直接判单纯协议。
