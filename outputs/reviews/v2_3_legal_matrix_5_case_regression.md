# v2.3 合法矩阵边界 5 Case 回归

## 回归目标

基于 `legal_operation_matrix_playbook_v2_3.md`，验证合法批量运营、MCN / 商家 / 达人矩阵、官方工具、授权工具，与群控、协议、导流、账号安全之间的边界是否清晰。

## Case 1：AS-007 商家和黑产都会捅接口登录

### 是否触发 legal_operation_matrix_playbook

触发。该 case 明确是“商家接口化登录”和“黑产接口滥用”混在一起，属于合法自动化和协议攻击的边界问题。

### 主控 Skill

account_security_expert_skill

### 辅助 Skill

protocol_attack_expert_skill、risk_governance_design_skill、legal_operation_matrix_playbook_v2_3

### 合法矩阵判断字段

- 授权主体：商家、店铺、服务商、ISV。
- 账号范围：店铺账号、员工号、子账号、代运营账号。
- 工具来源：商家后台、开放平台 app_id、授权 ISV、自研工具。
- 操作人：员工、服务商、客服、代运营。
- 操作目的：登录、店铺经营、客服、订单处理。
- 调用接口：登录接口、token 刷新、店铺管理接口。
- 敏感动作：换绑、提现、支付、发券、批量私信。
- 收益主体：店铺、服务商、异常第三方。
- 业务登记信息：授权单、合同、app_id、工具备案。
- 历史违规记录：导流、欺诈、支付风险、撞库记录。

### 当前属于

证据不足时属于“合法矩阵 / 协议滥用待审计”；有授权、有登记、有范围、有审计时属于合法矩阵；无授权且规避登录规则时进入非授权黑产或协议判断。

### 不能一刀切的原因

商家站点登录可能是真实经营需求，一刀切会影响经营、客服和订单处理；但继续无条件豁免会让黑产借商家通道绕过登录风控。

### 局部治理动作

- 授权登记和 app_id 绑定。
- 登录 / token / 店铺管理接口范围绑定。
- 高风险动作 step-up。
- 非授权接口收紧。
- 操作人和工具审计。
- 对越权接口局部限权，不全量封禁商家主体。

### 需要补证

授权主体、工具来源、app_id、调用接口、操作人、登录环境、敏感动作、收益主体、历史违规记录。

### 业务影响

误拦会影响商家经营和客服效率；过度豁免会扩大撞库、token 滥用、支付/提现和导流风险。

### 是否需要回写 Skill

建议回写引用：account_security_expert_skill 和 protocol_attack_expert_skill 可在合法自动化分支中显式引用该 playbook。

## Case 2：ADV-004 商家/达人批量登录或接口化运营

### 是否触发 legal_operation_matrix_playbook

触发。批量登录和接口化运营本身不能直接判协议或账号风险，必须先做合法自动化审计。

### 主控 Skill

account_security_expert_skill

### 辅助 Skill

protocol_attack_expert_skill、risk_governance_design_skill、legal_operation_matrix_playbook_v2_3

### 合法矩阵判断字段

- 授权主体：商家、达人、MCN、机构。
- 账号范围：达人号、店铺号、企业号、员工号。
- 工具来源：官方工具、授权 ISV、MCN 工具、未知工具。
- 操作人：达人运营、客服、代运营、服务商。
- 操作目的：内容发布、直播运营、经营管理、客服。
- 调用接口：登录、发布、私信、互动、投放。
- 敏感动作：私信、关注、换绑、提现、结算、批量投放。
- 收益主体：达人、MCN、店铺、服务商。
- 业务登记信息：MCN 绑定、商家授权、工具备案。
- 历史违规记录：导流、骚扰、欺诈、异常投放。

### 当前属于

有授权、有登记、有范围、有审计时属于合法矩阵；工具来源不明、收益主体异常或敏感动作集中时进入高风险审计。

### 不能一刀切的原因

达人/商家/MCN 本身需要批量管理账号和内容，批量登录是业务常态；但批量身份不能豁免导流、欺诈、支付和结算风险。

### 局部治理动作

- 授权矩阵登记。
- 账号范围和工具范围绑定。
- 敏感动作二次验证。
- 局部账号、局部工具、局部接口限权。
- 操作人审计。
- 未知工具迁移到官方工具。

### 需要补证

MCN/商家授权关系、工具 app_id、账号范围、操作人、接口范围、敏感动作、收益主体、投诉和违规历史。

### 业务影响

误判为黑产会损伤达人和商家运营效率；误判为完全合法会放过矩阵化导流、骚扰和支付风险。

### 是否需要回写 Skill

建议回写引用：group_control_expert_skill、protocol_attack_expert_skill、account_security_expert_skill 都可引用 playbook 作为合法矩阵反证入口。

## Case 3：直播/达人/MCN 批量私信和互动

### 是否触发 legal_operation_matrix_playbook

触发。该 case 是 MCN/达人合法运营、批量互动、导流违规和账号矩阵的交叉场景。

### 主控 Skill

traffic_diversion_interception_skill

### 辅助 Skill

account_security_expert_skill、group_control_expert_skill、legal_operation_matrix_playbook_v2_3

### 合法矩阵判断字段

- 授权主体：达人、MCN、机构。
- 账号范围：达人矩阵账号、企业号、运营号。
- 工具来源：官方私信工具、MCN 管理工具、未知群发工具。
- 操作人：运营、客服、主播助理、服务商。
- 操作目的：粉丝运营、直播通知、售后、活动通知。
- 调用接口：私信、关注、评论、互动、直播通知。
- 敏感动作：批量私信、站外联系方式、导流话术、骚扰触达。
- 收益主体：达人、MCN、站外私域、第三方群。
- 业务登记信息：MCN 绑定、私信工具授权、运营登记。
- 历史违规记录：导流、骚扰、诈骗、私域引流。

### 当前属于

若私信内容在授权范围内且有审计，属于合法矩阵；若出现站外承接、导流话术、骚扰投诉，属于超范围局部违规；若无授权且工具来源不明，进入非授权黑产/导流判断。

### 不能一刀切的原因

粉丝运营和直播通知有合法业务价值；但批量私信很容易变成站外承接、骚扰或诈骗触达，必须按内容和触达链路局部治理。

### 局部治理动作

- 私信内容审核和导流关键词治理。
- 私信频率、陌生人触达、关注后私信冷却。
- 对违规账号、违规操作人、违规工具局部限权。
- 正常 MCN/达人账号保留运营能力。
- 站外证据回流到导流风险策略。

### 需要补证

私信内容、站外承接证据、操作人、工具来源、账号范围、MCN 授权、触达对象、投诉、历史违规。

### 业务影响

一刀切会伤害粉丝运营、直播提醒和售后服务；放任则会造成私域导流、骚扰、诈骗和平台流量流失。

### 是否需要回写 Skill

建议回写引用：traffic_diversion_interception_skill 可以在合法矩阵反证和局部导流治理中引用该 playbook。

## Case 4：商家批量发布/投放/结算，部分账号出现支付或欺诈风险

### 是否触发 legal_operation_matrix_playbook

触发。批量发布、投放、结算属于合法经营常见动作，但支付和欺诈风险需要局部账号安全治理。

### 主控 Skill

account_security_expert_skill

### 辅助 Skill

risk_governance_design_skill、activity_anti_cheating_expert_skill、legal_operation_matrix_playbook_v2_3

### 合法矩阵判断字段

- 授权主体：商家、店铺、服务商、机构。
- 账号范围：店铺主账号、子账号、员工号、投放账号。
- 工具来源：商家后台、投放平台、授权 ISV。
- 操作人：商家员工、服务商、运营。
- 操作目的：商品发布、广告投放、订单处理、结算。
- 调用接口：发布、投放、支付、提现、结算、发券。
- 敏感动作：支付、提现、结算、发券、大额投放。
- 收益主体：店铺、结算账户、异常收款主体。
- 业务登记信息：商家资质、合同、结算账户备案。
- 历史违规记录：欺诈订单、支付争议、异常退款、导流。

### 当前属于

主体和工具合法时，基础批量经营属于合法矩阵；出现支付或欺诈风险时，属于超范围局部违规或高风险审计，不应全量打掉商家矩阵。

### 不能一刀切的原因

发布、投放、结算是商家核心经营能力；但支付、提现和结算直接影响资金安全，必须对异常账号、操作人、接口和收益主体局部收紧。

### 局部治理动作

- 敏感动作二次验证。
- 结算复核、提现冷却、大额操作审批。
- 局部账号或操作人限权。
- 异常收益主体冻结或复核。
- 非授权工具收紧。
- 保留正常发布和客服能力。

### 需要补证

商家资质、结算账户、操作人、投放/发布日志、支付/提现链路、异常订单、收益主体、历史违规记录。

### 业务影响

误伤会影响商家收入、投放效率和结算体验；放过会造成欺诈交易、支付争议、资损和监管风险。

### 是否需要回写 Skill

建议回写引用：account_security_expert_skill 的支付/提现/敏感动作分支可引用该 playbook；activity_anti_cheating 可在渠道投放/结算类 case 辅助引用。

## Case 5：合法工具授权后，被超范围用于私信导流或活动套利

### 是否触发 legal_operation_matrix_playbook

触发。该 case 正是“授权不等于豁免”的边界：主体或工具合法，但用途超范围。

### 主控 Skill

traffic_diversion_interception_skill 或 activity_anti_cheating_expert_skill，取决于核心损伤：

- 私信站外承接为主：traffic_diversion_interception_skill。
- 活动奖励/结算套利为主：activity_anti_cheating_expert_skill。

### 辅助 Skill

legal_operation_matrix_playbook_v2_3、account_security_expert_skill、protocol_attack_expert_skill

### 合法矩阵判断字段

- 授权主体：被授权商家、达人、MCN、ISV。
- 账号范围：授权账号和实际操作账号是否一致。
- 工具来源：授权工具、官方 app_id、第三方工具。
- 操作人：是否可审计。
- 操作目的：原授权目的 vs 实际私信导流 / 活动套利。
- 调用接口：是否调用未授权私信、互动、领奖、结算接口。
- 敏感动作：私信、站外联系方式、活动领奖、发券、结算。
- 收益主体：站外私域、异常提现主体、套利账户。
- 业务登记信息：授权范围、接口范围、工具备案。
- 历史违规记录：导流、骚扰、活动套利、结算扣罚。

### 当前属于

超范围局部违规；若系统性规避平台规则、收益主体异常、非授权接口调用闭合，则升级为非授权黑产或混合攻击。

### 不能一刀切的原因

授权工具仍可能承载大量正常业务操作；但超范围私信导流或活动套利不能因为“有授权”而豁免。

### 局部治理动作

- 收紧超范围接口。
- 对私信导流账号局部限权。
- 对活动套利动作延迟发奖、结算复核或扣除。
- 敏感动作二次验证。
- 操作人和工具审计。
- 对工具授权范围重新登记。
- 复发主体提高处罚梯度。

### 需要补证

授权范围、实际调用接口、私信/活动内容、站外承接、奖励/结算链路、收益主体、操作人、工具 app_id、历史违规。

### 业务影响

误伤会影响授权工具生态和正常经营；放过会让授权工具成为导流、骚扰和活动套利通道。

### 是否需要回写 Skill

建议回写引用：traffic_diversion_interception_skill 和 activity_anti_cheating_expert_skill 可在“合法矩阵内局部违规”场景引用该 playbook。

## 总结

### 1. playbook 是否能减少群控/协议误判

能。它明确把“批量行为”拆成授权主体、账号范围、工具来源、操作人、操作目的、调用接口、敏感动作、收益主体和审计记录，而不是直接按群控或协议处理。

减少误判的关键点：

- 批量登录不直接等于群控。
- 接口化调用不直接等于协议。
- 有授权不等于完全豁免。
- 局部导流、欺诈、支付风险按局部治理，不全量打掉矩阵。
- 无授权且规避平台规则时，再转群控/协议/账号安全。

### 2. 是否需要把 playbook 引用写入 group_control、protocol、account_security、traffic_diversion

建议写入，但不是必须立即大改。

优先级：

1. account_security_expert_skill：最高优先级。商家/达人/机构批量登录、代管、支付/结算风险与账号安全强相关。
2. protocol_attack_expert_skill：高优先级。接口化运营最容易被误判为协议攻击。
3. traffic_diversion_interception_skill：高优先级。合法矩阵内的私信、互动、站外承接需要局部导流治理。
4. group_control_expert_skill：中优先级。可作为合法矩阵反证入口，避免“批量账号/设备”被直接判群控。

建议不是把 playbook 全文复制到 Skill，而是在各 Skill 的反证、转交和治理闭环中引用：

- “如存在商家/达人/MCN/ISV/客服工具授权矩阵，先按 legal_operation_matrix_playbook_v2_3 做授权、范围、审计和局部违规判断。”

### 3. 是否需要补充字段级查数模板

需要。playbook 目前定义了判断字段，但还没有字段级查数模板。建议新增一个轻量模板，覆盖：

- 授权主体表 / 登记信息；
- 账号范围绑定表；
- 工具 / app_id / ISV 授权表；
- 操作人审计日志；
- 调用接口日志；
- 敏感动作日志；
- 收益主体 / 结算账户；
- 历史违规记录；
- 导流 / 欺诈 / 支付风险命中；
- 申诉和恢复记录。

字段级模板的价值是把“合法矩阵判断”从专家口径变成可执行查数动作，避免线上评审时仍停留在原则判断。
