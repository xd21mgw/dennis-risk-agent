# ATO Expected Evidence and Boundaries v1

## 0. 目标

定义 v2.4 Data Agent-only ATO 只读试点的证据体系和边界。Data Agent 输出只能作为 `provider_conclusion_hint` 和数据发现来源，Dennis Agent 才负责基于证据、反证、缺口和质量风险生成最终研判，人工复核负责最终确认。

## 1. 强证据

- 异常登录后短时间内发生违规发布 / 资料变更 / 换绑 / 改密 / 找回。
- 登录方式与历史习惯明显不同，例如平时微信 / 验证码，本次密码登录或扫码 / OAuth。
- 新设备 / 异地 / 非常用 IP / 非常用地区登录，并且与敏感动作存在时间链路。
- token / session 被踢、复用、异常切换或多端冲突线索。
- 风控策略命中盗号 / 钓鱼 / 扫码 / 密码泄露 / 短信泄露。
- 回扫记录与人工备注一致，且能和时间窗口内登录、token、敏感动作链路对齐。
- 发布行为发生在用户声称不在线 / 睡眠 / 上学等时段，且登录环境异常。
- 密码登录 + 新设备 + 风控命中 + 发布链路闭合。
- OAuth / 扫码授权 + Web 新设备 + token 生成 + 发布链路闭合。
- 策略名明确包含 `stealAccount`、盗号、扫码盗号、Web 扫码无历史设备等，且与行为链路一致。

强证据成立要求至少有“接管入口证据 + 账号控制权变化或环境突变 + 下游敏感动作链路”中的两类闭合。单条风险标签、单条申诉文本或单个异常登录不能单独作为强证据。

stealAccount 类策略命中是强策略证据，但仍需保留边界：策略命中不等于最终人工定性；若 `params`、发布内容、实时链路缺失，必须写入 `permission_notes`、`missing_evidence` 和 `quality_risks`。

## 2. 中证据

- 登录环境有变化，但缺历史基线。
- 存在设备 / IP 变化，但无法确认是否本人新设备。
- 存在发布行为，但缺登录链路闭合。
- 存在风险画像，但缺策略明细。
- 存在疑似钓鱼域名 / 扫码来源备注，但 Data Agent 无法直接验证外部来源。
- 存在 token/session 异常摘要，但缺实时链路、端侧指纹或策略引擎明细。

## 3. 弱证据

- 用户申诉文本。
- 用户称“我当时没上线 / 在睡觉 / 在上学”。
- 只有违规发布结果，没有异常登录链路。
- 只有人工备注，没有数据支撑。
- 只有风险标签，没有后验链路。
- 只有 Data Agent 生成的 SQL 或模型推测，没有实际查询结果。

## 4. 反证

- 登录设备 / IP / 地区与历史常用一致。
- 登录方式与历史一致。
- 发布行为前后没有异常登录或 token/session 变化。
- 有本人常用设备持续在线。
- 风险画像 / 策略命中缺失且行为链路正常。
- 用户申诉与数据时间不一致。
- 人工备注中的风险链路在数据侧无法找到支撑。
- 账号资料、登录态、绑定关系和敏感动作在时间窗口内无异常变化。
- 申诉称被盗但没有异常登录、没有授权链路、没有 token/session 接管、没有 ATO 风险标签。
- 发布行为存在但无法和异常登录或登录态接管链路闭合。
- 地区不一致可被本人移动、常用设备或正常找回解释。

## 5. 结论等级

### 明确支持盗号嫌疑

适用条件：
- 数据发现闭合了异常登录或登录态异常、环境突变、敏感动作或违规发布链路；
- 关键反证未发现，或已有足够数据解释反证；
- 人工备注或用户描述只作为旁证，不是唯一依据。

Data Agent-only 阶段一般不直接输出该等级为最终结论，只能给 `provider_conclusion_hint`。Dennis Agent 需要结合缺失证据和人工复核确认。

### 高度疑似盗号

适用条件：
- 有较强异常登录、token/session、设备/IP/地区或敏感动作链路；
- 但缺实时登录链路、实时设备指纹、策略引擎明细、外部钓鱼来源或部分反证。

### 证据不足

适用条件：
- 只有申诉、人工备注、风险画像或违规发布结果；
- 关键链路缺失、无权限、SQL-only、empty_result、failed、时间窗口不完整；
- 无法区分本人操作、新设备正常登录、埋点/口径缺失或账号接管。
- 申诉称被盗但数据无法验证异常登录。
- 有发布行为但没有异常登录或登录态接管链路。
- 有地区不一致但不能排除正常移动。
- 无登录记录时，不得解释为无风险，也不得直接支持 ATO。
- 正常解释未排除时，结论停留 `insufficient_support`。
- 密码重置后找回、注销尝试、发布行为需要结合登录链路和设备归属判断，不能单独支持 ATO。

### 反向排除 / 更像本人操作或证据不支持

适用条件：
- 登录环境、登录方式、设备/IP/地区与历史常用一致；
- 敏感动作与常用设备持续在线链路一致；
- 未发现 token/session、换绑、改密、找回或下游行为突变；
- 用户申诉时间与数据链路明显不一致。

## 6. Data Agent-only Provider Limitations

缺以下任一类证据时，必须写入 `provider_limitations`，并限制结论强度：

- 实时登录链路。
- 实时设备指纹。
- 实时策略引擎决策明细。
- 在线 token/session 冲突明细。
- 外部钓鱼、扫码、地推来源证据。
- 账号关系图或团伙扩散在线查询。

## 7. 不能做的判断

- 不得因为用户申诉直接判断盗号。
- 不得把人工备注当作数据事实。
- 不得把风险标签当作事实标签。
- 不得把 SQL-only 当作已查数结果。
- 不得把 empty_result 当作无风险。
- 不得把无登录记录当作无风险。
- 不得把发布行为存在直接当作 ATO 成立。
- 不得把地区不一致单独当作 ATO 成立。
- 不得把密码重置、找回或注销尝试单独当作 ATO 成立。
- 不得在 no_permission / partial / failed 时强结论。
- 不得输出处罚、冻结、扣除、封禁、自动解封或策略上线建议。
