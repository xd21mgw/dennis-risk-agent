# Real User Crowdsourcing Runtime Summary v1

## 一、场景定位

真人众包关注的是“真实人参与，但目标是任务化、组织化、黑产化”的执行模式。
它常见于地推、任务群、拉群、代刷、代操作等场景。
本场景默认轻量支持，不默认调 DataAgent。

## 二、核心判断问题

- 真人参与是不是被任务化了。
- 行为是不是被组织和分工了。
- 是否存在外部收益驱动和批量执行节奏。

## 三、场景本质

本质是在防“真人被组织起来做批量任务”，而不是防正常用户行为。
区别点不在于人是否真实，而在于目标是否被任务化、行为是否被组织化、收益是否被外部驱动。

## 四、典型攻击路径

1. 众包平台派单。
2. 地推 / 拉群统一组织。
3. 任务群批量执行。
4. 真人扫码、真人输入、真人点击完成关键动作。
5. 账号分工、设备分工、地域分工。
6. 通过正常真人动作掩盖黑产目标。
7. 与群控、协议、导流混合。

## 五、强证据

- 行为真实，但目标高度任务化。
- 设备 / 账号 / 地域呈组织化分工。
- 同批任务节奏一致。
- 奖励、佣金、结算、派单链路明显。
- 任务完成路径与正常用户行为差异明显。

## 六、中证据 / 弱证据

中证据：

- 同一批人做相似动作。
- 参与路径相似但个体设备不同。
- 有任务群迹象但链路未闭合。

弱证据：

- 真人动作本身。
- 单次扫码、单次点击、单次输入。
- 用户自述。

这些不能单独定性真人众包。

## 七、反证与误判边界

- 正常用户参与活动、正常客服协助、正常商家代运营都可能具有组织化外观。
- 真人众包与群控、协议、自然用户的边界都容易混淆。
- 只看“是真人”无法排除黑产。
- 只看“动作像”无法强判任务化。

## 八、低成本取证方向

- 先看任务来源和组织关系。
- 再看设备 / 账号 / 地域分工。
- 再看奖励、佣金、派单、结算链路。
- 再看是否存在团组和批量执行节奏。
- 优先查短窗代表样本。

## 九、治理方法

### 识别

- 任务化行为识别。
- 组织关系识别。
- 分工和节奏识别。

### 拦截 / 限制

- 对任务化路径做限权、验证、频控。
- 对高风险派单做阈值和白名单管理。

### 体验或业务损伤控制

- 对正常活动用户、正常协助链路做降级兜底。

### 人工复核

- 对地推、任务群、争议导流、争议协助样本做人工确认。

### 复盘沉淀

- 复盘任务入口。
- 复盘派单与收益链路。
- 复盘真人众包和正常用户边界。

高风险动作必须人工确认，不能自动处罚、封禁、冻结、上线策略。

## 十、短问回复话术

1. “这是正常用户还是真人众包？”  
要看是不是被组织成任务在做，不是只看真人身份。

2. “地推扫码算不算真人众包？”  
有可能，要看是否存在派单、奖励和统一组织。

3. “真人点击很多就是黑产吗？”  
不一定，得看是否任务化和是否有组织关系。

4. “群控和真人众包怎么分？”  
群控更偏统一设备调度，真人众包更偏任务化真人执行。

5. “用户自己帮忙操作算众包吗？”  
不一定，得看规模、组织性和收益链。

## 十一、DataAgent 默认边界

- 本场景默认不直接调 DataAgent。
- 用户明确要求“查数 / 调 DataAgent / 生成查询问题”时，才生成 DataAgent 取证方向。
- 高成本查询必须用户确认。
- SQL-only / partial / timeout 不能强结论。

## 十二、默认输出结构 / 升级条件 / 当前边界

默认输出结构：

- 当前判断。
- 为什么。
- 还缺什么证据。
- 建议怎么取证。
- 建议怎么治理。
- 是否需要 DataAgent。

何时升级完整 Skill：

- 当问题进入任务群、派单、地推、组织化执行或治理评审。
- 当要区分真人众包、群控、自然用户时。

何时允许查数 / 调 DataAgent：

- 用户明确要求查数 / 拉样本 / 看日志 / 验证数据。
- 需要验证任务链路、组织关系、奖励结算时。
- 高成本查询必须用户确认。

当前不应直接下结论的边界：

- 单次扫码。
- 单次点击。
- 单次输入。

## 十三、禁止行为

- 不基于单一真人行为强判。
- 不基于单一组织迹象强判。
- 不把样本比例、具体策略名、具体 IP、具体时间窗沉淀为长期本质规则。
- 不默认查数。
- 不自动处罚 / 封禁 / 冻结 / 上线策略。
