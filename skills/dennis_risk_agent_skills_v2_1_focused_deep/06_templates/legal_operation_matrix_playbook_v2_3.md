# Legal Operation Matrix Playbook v2.3

## 0. 目标

本 Playbook 用于解决合法批量运营、MCN / 商家 / 达人矩阵、官方工具、授权工具、客服 / 运营代管，与黑产群控、协议攻击、导流违规、账号安全风险之间边界不清的问题。

核心原则：

- 批量不等于黑产。
- 授权不等于豁免。
- 合法矩阵看授权、登记、范围、审计和业务合理性。
- 局部违规按局部风险治理，不因矩阵身份全量放过，也不因局部风险一刀切全打。

## 1. 适用场景

适用于以下业务和风险交叉场景：

- 商家批量登录、批量上架、批量改价、批量回复、批量投放。
- 达人 / MCN 矩阵运营，包括多账号内容发布、直播运营、粉丝互动、私信触达。
- 官方工具 / 授权工具，包括开放平台、商家后台、达人后台、ISV、客服工具、运营工具。
- 客服 / 运营代管，包括企业号、机构号、店铺号、达人号的代理操作。
- 批量发布、批量私信、批量互动、批量投放、批量结算。
- 与群控、协议、导流、账号安全交叉的场景：
  - 批量登录像群控；
  - 接口化调用像协议；
  - 批量私信像导流；
  - 多账号代管像账号接管；
  - 收益结算异常像活动/渠道套利。

不适用场景：

- 明确无授权、无业务合理性、纯规避平台规则的黑产批量作恶，应转群控、协议、导流或账号安全 Skill。
- 明确账号被盗、token 泄露、撞库 ATO，应转账号安全 Skill。
- 明确接口脱端、签名/token/参数异常，应转协议 Skill。

## 2. 判断字段

判断合法矩阵时，至少检查以下字段或同等含义的数据：

| 字段 | 需要回答的问题 | 风险含义 |
|---|---|---|
| 授权主体 | 谁被授权操作？商家、达人、MCN、机构、ISV、客服还是运营？ | 无主体或主体不一致，风险升高 |
| 账号范围 | 授权覆盖哪些账号、店铺、达人号、企业号？ | 超范围操作进入局部违规 |
| 工具来源 | 官方工具、开放平台、授权 ISV、自研工具，还是未知工具？ | 未知工具或外挂工具需高风险审计 |
| 操作人 | 谁在操作？是否可追溯到员工、客服、运营、服务商？ | 无操作人审计，不能直接白化 |
| 操作目的 | 上架、客服、投放、内容发布、结算、私信触达，是否业务合理？ | 目的与主体不匹配，风险升高 |
| 调用接口 | 调用了哪些接口、动作、权限？ | 非授权接口或敏感接口越权需收紧 |
| 敏感动作 | 换绑、提现、支付、私信、批量关注、导流、结算、发券等 | 敏感动作需二次验证或审计 |
| 收益主体 | 收益、结算、佣金、提现流向谁？ | 收益主体异常可能是挂靠或黑产 |
| 业务登记信息 | 是否有授权单、合同、开放平台 app_id、工具备案、白名单？ | 无登记不应直接判合法矩阵 |
| 历史违规记录 | 主体、工具、账号、操作人是否有导流、欺诈、骚扰、支付风险历史？ | 历史高风险主体应降权或加强审计 |

## 3. 判断规则

按顺序判断；证据不足时不得强结论。

1. 如果有授权主体、有业务登记、有账号范围、有工具来源、有操作审计，且操作目的和调用接口在授权范围内，优先判断为合法运营矩阵。

2. 如果有授权、有登记，但操作超出账号范围、接口范围、动作范围或时间范围，判断为合法矩阵下的局部超范围风险，进入局部违规治理，不直接全量封禁矩阵。

3. 如果无授权、无登记、工具来源不明，并且存在规避平台规则、批量敏感动作、收益异常、账号关系异常、导流或欺诈证据，转入黑产 / 群控 / 协议 / 账号安全判断。

4. 如果存在合法运营身份，但触发导流、骚扰、欺诈、支付、提现、结算等局部风险，按局部风险处置；不得因为有授权就放过风险，也不得因为局部违规一刀切全打矩阵。

5. 如果工具来源不明、收益主体异常、账号关系异常、操作人不可追溯、调用接口超授权、敏感动作集中，进入高风险审计分支。

6. 如果批量行为有完整端行为但设备 / 路径 / 收益被统一调度，且无法提供授权和审计，组合 group_control_expert_skill 判断群控。

7. 如果批量行为主要是接口直达、无端链路、签名/token/参数异常，且不在授权接口范围内，组合 protocol_attack_expert_skill 判断协议滥用。

8. 如果批量私信、关注、搜索添加、站外承接、主页签名等导流链路闭合，组合 traffic_diversion_interception_skill 做导流局部治理。

9. 如果出现登录环境突变、token 跨环境、换绑、支付/提现或账号接管迹象，组合 account_security_expert_skill 做账号安全治理。

10. 如果只有批量发布、批量互动、批量登录等表象，缺少授权信息和风险证据，只能进入补证和审计，不得直接定义黑产。

## 4. 治理策略

### 4.1 授权登记

- 建立主体登记：商家、达人、MCN、机构、ISV、客服、运营。
- 绑定账号范围：店铺、达人号、企业号、员工号、客服号。
- 绑定工具来源：官方工具、开放平台 app_id、授权 ISV、自研工具。
- 明确操作目的：客服、投放、发布、经营、结算、售后。

### 4.2 官方工具

- 优先引导合法矩阵使用官方工具或授权工具。
- 官方工具内置操作审计、权限边界、频控和敏感动作 step-up。
- 对非官方工具提供迁移路径，不直接让业务断崖式停摆。

### 4.3 调用范围绑定

- 绑定接口范围、动作范围、账号范围、IP / 设备 / app_id 范围。
- 对越权接口、未登记接口、非业务必要接口收紧。
- 对敏感接口增加上下文绑定和审计。

### 4.4 敏感动作二次验证

敏感动作包括但不限于：

- 换绑、登录态迁移、token 刷新；
- 支付、提现、结算、发券；
- 批量私信、批量关注、批量评论；
- 大规模投放、改价、下架、删除内容；
- 站外联系方式发布。

治理方式：

- 操作人确认；
- 管理员审批；
- 二次验证；
- 冷却期；
- 限额；
- 风险提示。

### 4.5 违规局部限权

- 局部账号违规，优先限局部账号。
- 局部工具违规，优先限工具调用范围。
- 局部接口违规，优先收紧该接口。
- 局部操作人违规，优先暂停操作人权限。
- 只有主体系统性规避平台规则时，才升级主体级处置。

### 4.6 审计日志

审计日志至少包含：

- 授权主体；
- 操作账号；
- 操作人；
- 工具 / app_id；
- 调用接口；
- 请求来源；
- 操作时间；
- 操作对象；
- 敏感动作；
- 收益主体；
- 审批链路；
- 风险命中。

### 4.7 处罚梯度

| 风险等级 | 条件 | 处置 |
|---|---|---|
| 低风险 | 授权内轻微异常 | 提醒、加采、审计 |
| 中风险 | 超范围、敏感动作异常、轻度骚扰 | 局部限权、二次验证、冷却期 |
| 高风险 | 导流、欺诈、支付风险、收益异常 | 冻结敏感动作、局部封禁、结算复核 |
| 严重风险 | 无授权工具、系统性规避、黑产证据闭合 | 主体级处置、工具封禁、账号矩阵联动 |

### 4.8 申诉和恢复

- 提供主体、工具、账号、操作人四个维度的申诉入口。
- 恢复前要求补登记、补审计、补授权范围。
- 复发主体提高审计等级和敏感动作门槛。

### 4.9 非授权工具收紧

- 未知工具先进入审计和调用范围收紧。
- 无业务合理性且规避平台规则的工具，进入高风险处置。
- 对可迁移的业务工具，提供官方工具替代方案。

## 6. 禁止行为

- 禁止把合法矩阵一刀切当群控。
- 禁止因为有授权就放过导流、欺诈、骚扰、支付、提现、结算风险。
- 禁止把所有批量行为都定义为黑产。
- 禁止无授权台账时直接给永久白名单。
- 禁止只看工具身份，不看操作人、接口范围、敏感动作和收益主体。
- 禁止局部违规直接扩大到全主体处置，除非有系统性规避证据。
- 禁止只做封禁，不给申诉、恢复和官方工具迁移路径。

## 7. 与相关 Skill 的边界

- 与 group_control_expert_skill：群控核心是统一调度和规避规则；合法矩阵核心是授权、范围、审计和业务合理性。
- 与 protocol_attack_expert_skill：协议攻击核心是接口脱端和参数/签名/token 异常；合法工具接口化调用必须看授权接口范围和审计。
- 与 traffic_diversion_interception_skill：导流截流看目标获取、触达、站外承接、变现；合法矩阵内出现导流，按局部导流风险处置。
- 与 account_security_expert_skill：账号安全看盗号、token 泄露、换绑、支付/提现、账号接管；代管和批量登录需要先校验授权主体和操作人。

## 8. 评估指标

- 授权主体覆盖率；
- 工具登记覆盖率；
- 审计日志完整率；
- 超范围调用率；
- 敏感动作 step-up 命中率；
- 局部违规复发率；
- 非授权工具收紧量；
- 误伤商家 / 达人 / MCN 数；
- 申诉恢复成功率；
- 导流 / 欺诈 / 支付风险下降量。
