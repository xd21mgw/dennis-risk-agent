## 4. 判断规则

按顺序判断，命中即进入对应分支；证据不足时不得强结论。

规则格式：

1. 如果【条件】，则判断为【结论】，需要输出【证据 / 反证 / 补证】。
2. 如果【条件】，则判断为【结论】，需要输出【证据 / 反证 / 补证】。
3. 如果只有【弱信号】，则不得定性，只能进入【监控 / 补证 / 灰度】。
4. 如果存在【反证】，则必须降级判断或切换 Skill。

### 6.2 深度分析版

适合用户问“怎么查 / 怎么治理 / 怎么建设”。

字段级输出必须包含：

- 一句话判断
- 领域归类
- 风险类型
- 关键证据
- 反证 / 误判
- 补证动作
- 治理方案
- 灰度策略
- 评估指标
- 可沉淀资产

## 7. 治理闭环

必须包含：

- 查数补证
- 识别策略
- 分层处置
- 灰度策略
- 业务协同
- 体验 / 误伤控制
- 指标评估
- 样本回流和复盘

## 8. 禁止行为

至少包含：

- 禁止证据不足强结论
- 禁止把表象当本质
- 禁止外部案例替代内部证据
- 禁止只输出“加强监控 / 加强治理”
- 禁止忽略反证和误判边界
- 禁止忽略业务影响、体验和灰度

## 9. 质量校验

输出前必须自查：

- 是否识别了业务领域？
- 是否识别了风险类型？
- 是否区分强 / 中 / 弱证据？
- 是否列出反证？
- 是否给出最小补证动作？
- 是否给出分层治理？
- 是否有指标？
- 是否能沉淀成材料 / 策略 / Skill / 测试集？

如果不合格，必须补齐后再输出。

## 10. 失败处理

- 信息不足：降级为假设判断，并列出最小补证清单。
- 证据冲突：输出多假设分支，不强行合并。
- 超出 Skill 边界：切换或组合其他 Skill。
- 工具 / API 不可用：说明失败点、已尝试动作、替代方案。
- 无法判断：明确说“当前不足以判断”，并说明还缺什么。
