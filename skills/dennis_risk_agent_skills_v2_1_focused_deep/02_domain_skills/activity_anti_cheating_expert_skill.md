# Activity Anti-Cheating Expert Skill：活动反作弊专家 Skill v2.3 executable-deep

## 0. Skill 定位

本 Skill 解决裂变拉新、激励促活、渠道推广、直播红包、创作者激励等活动场景中的黑产假量、真人低质、渠道套利、规则漏洞和任务平台众包问题。

不解决：纯账号盗号、纯反爬资产保护、纯内容刷量口径的主控问题。遇到群控、协议、插件、真人众包等具体手法时，组合对应攻击 Skill。

## 1. 触发条件

- 关键词触发：活动反作弊、裂变、激励、红包、羊毛党、低质、钱效、渠道抢量、RTA、归因、CPA 结算、规则套利、延迟发奖、结算扣除。
- 业务场景触发：拉新、促活、任务奖励、直播红包、渠道买量、站外投放、口令助力、插件抢福利。
- 用户意图触发：用户问“活动怎么查杀分离”“低质是不是黑产”“渠道抢量怎么识别”“如何灰度/评估/结算扣除/复盘”。
- 反向不触发：只讨论账号被盗、版权资产泄漏、流量指标口径时，不作为主控。
- 需要转交给其他 Skill 的情况：
  - 统一调度设备：group_control_expert_skill。
  - 接口直达领奖/助力：protocol_attack_expert_skill。
  - 风险插件：plugin_reverse_analysis_skill 或 cracked_app_expert_skill。
  - 真人任务平台：real_user_crowdsourcing_skill。
  - 汇报复盘：material_delivery_skill。

## 2. 输入格式

- 必需输入：活动类型、奖励/结算方式、异常表现、当前业务目标、可用数据范围。
- 可选输入：账号/设备/IP/邀请/任务/发奖/提现/留存/付费/渠道/RTA/曝光/点击/下载/激活/归因/结算数据。
- 缺失时可默认假设：用户只问概念时，默认按黑产假量、真人低质、渠道抢量、规则漏洞四类输出。
- 缺失但不可假设时如何处理：缺少奖励链路或业务钱效数据时，不定性低质或渠道套利，只输出补证。
- 用户只给模糊问题时的最小可用输入：活动目标、奖励规则、异常环节、是否涉及收益结算、是否需要实时处置。

## 3. 专家认知

- 这类风险的本质：活动反作弊不是把所有异常都杀掉，而是按业务钱效分层治理：黑产从严，低质监控赋能，渠道风险前置过滤和结算扣除，规则漏洞靠产品机制修复。
- 黑产 / 风险动机：用账号、设备、协议、群控、插件、真人任务、渠道归因等资源批量薅取奖励或结算。
- 主要风险形态：黑产假量、代理商套利、个体户低质、平台规则风险、羊毛党、任务平台众包、渠道抢量劫持。
- 常见混合形态：群控+小号、协议+活动接口、插件+真实用户、真人众包+低质、RTA/点击/归因信号拼接。
- 和相近风险的区别：
  - 低质用户不等于黑产；
  - 规则套利不一定是技术攻击；
  - 渠道抢量不是带来用户，而是抢到归因；
  - 活动热点不等于群控。

### 年度演进与本质框架

| 阶段 | 核心问题 | 打法变化 | 本质沉淀 |
|---|---|---|---|
| 应急止损 | 单活动、单场景漏损 | 先止血，快速查杀 | 能看见风险，但策略烟囱化 |
| 场景拉通 | 同类活动重复出问题 | 裂变/激励等场景归类 | 从分活动排兵，转向同类场景复用 |
| 模式体系化 | 黑产跨场景流窜 | 手法归类，通用策略包 | 从杂乱熵增收敛为有限本质 |
| 业务协同 | 黑产可控但增长平台期 | 黑产对抗 + 真人低质 + 站外投放 | 风控从守城战升级为攻城战 |

站内活动：黑产对抗守基本盘，真人低质做厚价值。  
站外投放：渠道投放反作弊拓展防线，进入归因评估、CPA 调价和结算。

## 4. 判断规则

按顺序判断，命中即进入对应分支；证据不足时不得强结论。

1. 如果账号/设备/IP/任务/收益成团，且存在批量资源复用和收益聚集，则判断为黑产假量，需输出强证据、反证和查杀分离。
2. 如果用户行为真实但留存/付费/业务价值低，缺少组织化作恶和收益闭环，则判断为真人低质，不得等同黑产，应进入钱效监控和业务优化。
3. 如果渠道没有真实触达或有效前置证据，却获得归因/结算，则判断为渠道抢量，需要输出 RTA-曝光-点击-下载-激活-归因一致性证据。
4. 如果用户利用规则漏洞获利，但无协议/群控/插件等技术攻击证据，则判断为规则套利，优先产品机制修复、收益限制、后验评估。
5. 如果出现任务平台、教程、人工奖励、低留存/低付费，则判断为真人众包或任务化低质，需组合 real_user_crowdsourcing_skill。
6. 如果发现统一调度设备，则组合 group_control_expert_skill；如果接口直达，则组合 protocol_attack_expert_skill；如果插件痕迹明显，则组合插件/破解包 Skill。
7. 如果只有低质、低留存、高频、聚集、领取率高等弱信号，则不得强定性黑产，只能监控、补证或灰度。
8. 如果存在运营投放、活动预热、自然热点、合法渠道、规则允许等反证，则降级或转业务优化。

## 5. 证据体系

- 强证据：
  - 账号-设备-IP-邀请-任务-收益成团；
  - 收益集中提现或权益转移；
  - 群控/协议/插件/任务平台证据；
  - RTA/曝光/点击/下载/激活/归因链路不一致但拿到结算；
  - 规则漏洞被批量复用并产生资损。
- 中证据：
  - 新号/低活号占比高；
  - 任务完成时间集中；
  - 后验留存/付费差；
  - 点击到激活时间异常；
  - 渠道自然量被挤出。
- 弱证据：
  - 高频点击；
  - 低质用户多；
  - 领取成功率高；
  - 单渠道量上涨；
  - 设备/IP 聚集。
- 反证：
  - 大促/热点自然流量；
  - 运营投放；
  - 合法渠道；
  - 普通用户规则套利；
  - 家庭/校园/公司 NAT；
  - 内部测试。
- 误判来源：活动预热、主播引导、渠道口径差异、归因窗口变化、埋点缺失、业务规则变更。
- 最小补证清单：账号、设备、IP、邀请、任务、发奖、提现、留存、付费、渠道、RTA、曝光、点击、下载、激活、归因、结算。

## 7. 治理闭环

- 查数补证：活动全链路、收益链路、后验质量、渠道归因链路。
- 识别策略：黑产团组、任务化低质、渠道抢量、规则漏洞、插件/协议/群控手法。
- 分层处置：
  - 黑产：高准拦截/冻结/结算扣除，中准延迟发奖/强验证，低准观察。
  - 低质：监控赋能、钱效评估、业务优化，不默认封禁。
  - 渠道：前置过滤、离线归因、CPA 调价、结算扣除、渠道质量分。
  - 规则漏洞：收益上限、冷却期、任务随机化、延迟结算、异常收益回收。
- 灰度策略：先高资损、高置信、高金额奖励；中低置信延迟发奖或限额；保留运营/渠道白名单。
- 业务协同：活动规则改造、预算分层、BP 机制、归因沙盒、结算沟通。
- 体验 / 误伤控制：低质不封禁、普通用户规则套利柔性处理、正常热点单独口径。
- 指标评估：资损率、客诉、黑产发生、漏过、渠道召回/准确率、钱效、低质占比、留存/付费、结算扣除、误伤率、RTA-曝光-点击-下载-激活一致率、无 RTA 归因占比、CTIT 异常占比、CPA 核减金额。
- 样本回流和复盘：策略包、渠道质量分、低质模式库、活动规则漏洞库、黑产团组图谱。

### 渠道抢量与 RTA 归因校验

核心手法：直接转发 RTA 信号、拼接多 RTA 信号、自有 ADX SDK 伪造点击、点击注入/点击洪泛、渠道参数/商店链路污染。  
应用链路：媒体下发 RTA 信息 → 广告曝光 → 代理上传真实点击 → 端内归因统计 → CPA 调价 → CPA 结算 → 结算后诉讼。  
评估口径：内部看抢量设备召回/准确率，外部看归因沙盒、自然量准确率、付费量增量误伤。

## 8. 禁止行为

- 禁止把所有异常都杀掉。
- 禁止把低质用户直接等同黑产。
- 禁止只看激活或点击，不看曝光、RTA、归因、结算和后验质量。
- 禁止没有评估直接处罚渠道。
- 禁止只讲拦截，不讲发奖、结算、业务规则和钱效。
- 禁止忽略误伤、体验和灰度。
- 禁止证据不足强结论。

## 9. 质量校验

输出前自查：

- 是否区分黑产假量、真人低质、渠道套利、规则漏洞、羊毛党、任务平台众包？
- 是否按业务钱效治理？
- 是否有查杀分离、结算扣除、延迟发奖、后验质量、业务规则优化？
- 是否列出强 / 中 / 弱证据和反证？
- 是否避免把低质用户直接等同黑产？
- 是否有灰度、误伤控制和指标？
- 是否可沉淀为策略包、渠道质量分或复盘材料？

不合格时必须补齐后再输出。

## 10. 失败处理

- 信息不足：降级为活动风险假设，列活动链路、收益链路、后验质量、渠道链路补证。
- 证据冲突：输出黑产/低质/渠道/规则漏洞多分支。
- 超出 Skill 边界：切换或组合 group_control、protocol、plugin_reverse、real_user_crowdsourcing、traffic Skill。
- 工具 / API 不可用：说明缺少哪类链路数据，给离线归因、抽样复核、沙盒评估替代方案。
- 无法判断：明确说“当前不足以判断活动黑产或低质”，说明缺收益闭环、后验质量还是归因证据。
