# Anti-Crawler Expert Skill：反爬专项专家 Skill v2.3 executable-deep

## 0. Skill 定位

本 Skill 解决核心资产被爬取、泄漏、外部复用、竞品跟价、版权盗版、关系链泄露等反爬领域问题。反爬是业务领域，不等于协议；协议、群控、破解包、真人众包只是反爬场景中的攻击手法。

不解决：纯账号盗号、小号交易、单纯活动套利、单纯流量刷量的主控问题。遇到具体手法时组合 protocol_attack_expert_skill、group_control_expert_skill、cracked_app_expert_skill、real_user_crowdsourcing_skill。

## 1. 触发条件

- 关键词触发：反爬、爬虫、核心资产、版权保护、价格泄漏、库存泄漏、关系链泄漏、黑市报价、蜜罐、水印、未登录态、弱端、接口漏出、缓存泄漏、合作方泄漏。
- 业务场景触发：电商价格/库存、版权内容、用户关系链、隐私动态、内容数据、DAU/DNU 口径、外网跟价、盗版站同步。
- 用户意图触发：用户问“怎么定位攻击来源”“怎么防版权泄漏”“如何资产分级”“如何建设 6+1 体系”“如何评估反爬价值”。
- 反向不触发：只问接口签名、token 复用、登录接口协议，不涉及资产保护时，优先协议或账号 Skill。
- 需要转交给其他 Skill 的情况：
  - 证明请求脱离端链路：protocol_attack_expert_skill。
  - 证明统一调度：group_control_expert_skill。
  - 证明改包/绕 SDK：cracked_app_expert_skill。
  - 证明真人任务化采集：real_user_crowdsourcing_skill。
  - 需要汇报材料：material_delivery_skill。

## 2. 输入格式

- 必需输入：被保护资产、泄漏/爬取现象、已知入口、内部访问日志或外部证据、当前业务约束。
- 可选输入：asset_id/content_id/url/hash/watermark_id、接口路径、端类型、账号/设备/IP、CDN/对象存储日志、合作方 app_id、投诉/报价/盗版站样本。
- 缺失时可默认假设：未给具体资产时，默认先要求资产分级；未给攻击手法时，按多手法候选输出。
- 缺失但不可假设时如何处理：缺少资产标识或外部泄漏样本时，不做源头定性，只输出资产级反查方案。
- 用户只给模糊问题时的最小可用输入：资产是什么、外部哪里泄漏、内部看过哪些入口、是否有蜜罐/水印/投诉/报价。

## 3. 专家认知

- 这类风险的本质：反爬不是单纯挡接口，而是围绕核心资产保护，让黑产获取资产的成本高于收益，并让平台可发现、可评估、可治理、可复盘。
- 黑产 / 风险动机：商业竞争、信息倒卖、垂类运营、市场分析、盗版分发、导流截流、流量指标污染。
- 主要风险形态：单纯协议、养设备协议、群控真机、破解包、真人众包、合作方/内部泄漏、前端/缓存/CDN 泄漏。
- 常见混合形态：弱端+协议、破解包+协议、群控真机+低频采集、合作方接口+外部分发、CDN 长链+盗版站。
- 和相近风险的区别：
  - 反爬是领域，协议是手法；
  - 有真实设备不代表正常，可能是群控真机；
  - 有真人访问不代表无风险，可能是任务众包；
  - 外部报价和投诉是辅助证据，不替代内部访问链路。

### 资产分级

| 资产 | 风险 | 治理态度 |
|---|---|---|
| 价格/库存/商品 | 跟价、倒卖、情报 | 高价值重点防控 |
| 版权内容 | 投诉、诉讼、盗版 | 防控+溯源 |
| 关系链/用户信息 | 导流、骚扰、定向添加 | 脱敏+权限+风控 |
| 流量数据 | 刷量、商业情报 | 监控+通用防护 |
| 低价值页面 | 普通访问 | 可发现可监控 |

接口分级：P0 影响面大、多方共识；P1 黑产/竞对重点关注；P2 举一反三潜在高风险；P3 未登录态、弱端、历史接口、潜在可爬。

### 非常 6+1 反爬飞轮

1. 未接漏洞：敏感接口、弱端、无登录态；
2. 产品改造：权限、脱敏、展示、访问门槛；
3. 实时发现：分钟级异常、外部情报、报价；
4. 策略对抗：协议、群控、破解包、真人；
5. 风险处置：账号、设备、IP、资产；
6. 水位评估：TOP 请求账号量、报价、投诉；
+ 1 引擎：实时、准实时、离线、应急。

年度材料补充：用 KSN/调用链路、请求响应采样、组织架构、测试工具主动运营潜在接口；从请求维度升级到账号维度；从单一实时扩展到实时、准实时、离线、未接入应急。

## 4. 判断规则

按顺序判断，命中即进入对应分支；证据不足时不得强结论。

1. 如果用户未明确资产，则先进入资产分级分支，不直接给接口防护建议。
2. 如果外部泄漏样本可通过 asset_id/content_id/url/hash/watermark_id 回溯到内部访问入口，则进入资产级溯源分支，输出首次访问、入口、账号/设备/IP、外部泄漏时间线。
3. 如果服务端请求缺端侧链路、接口序列异常、强目标接口直达，则判断为协议型反爬攻击，并组合 protocol_attack_expert_skill。
4. 如果有端行为但目标列表高度一致、设备/账号/路径/节奏同质，则判断为群控真机爬取，并组合 group_control_expert_skill。
5. 如果 SDK 缺失、包签名异常、hook/root/抓包代理、采集缺失，则判断为破解包/改包绕采集，并组合 cracked_app_expert_skill。
6. 如果后端流量都是真人访问，但任务化、低成本、收益链或外部任务平台明显，则判断为真人众包爬取。
7. 如果业务接口无明显异常但 CDN/对象存储/分享页/弱端命中，则判断为缓存/前端/弱端泄漏。
8. 如果合作方、后台、审核、运营、离线同步、导出链路命中，则进入合作方/内部链路泄漏分支。
9. 如果只有访问高频、IP 聚集、外部报价上涨或投诉上升，不得定性，只能补证。
10. 如果存在授权分发、业务运营、内部测试、蓝军、埋点缺失等反证，则必须降级或多假设输出。

## 5. 证据体系

- 强证据：
  - 资产标识在内部访问和外部泄漏间闭合；
  - 蜜罐/水印命中特定入口；
  - 无前置链路直达核心资产；
  - 账号-设备-IP-资产访问形成团组；
  - CDN/对象存储/合作方/后台访问早于外部泄漏；
  - 外部投诉/盗版站/报价与内部访问时间匹配。
- 中证据：
  - 弱端/旧接口/未登录态访问占比异常；
  - TOP 请求账号量变化；
  - 目标资产访问集中；
  - 访问后业务行为异常；
  - 黑市报价、教程、投诉出现变化。
- 弱证据：
  - 单接口 QPS 上升；
  - IP 聚集；
  - 低质账号访问；
  - 外部站点更新；
  - 价格被跟随。
- 反证：
  - 合法合作方授权；
  - 正常业务分发；
  - 内部测试/蓝军；
  - 埋点或日志缺失；
  - 历史存量泄漏；
  - 用户正常分享。
- 误判来源：推荐流量、热点资产、运营活动、CDN 缓存日志滞后、采样不全、合作方缓存。
- 最小补证清单：
  - 确认资产；
  - 定位入口；
  - 前后端 join；
  - 设备/账号/IP 聚集；
  - 接口序列；
  - 访问后业务行为；
  - 外部报价/投诉/盗版样本；
  - 蓝军/蜜罐/水印验证；
  - CDN/对象存储/合作方/后台链路。

## 7. 治理闭环

- 查数补证：按 asset_id/content_id/url/hash/watermark_id 反查全入口，串内部首次访问和外部泄漏时间线。
- 识别策略：协议识别、群控识别、破解包识别、真人任务识别、弱端/缓存/合作方审计。
- 分层处置：高价值资产强保护，中价值限权/加采，低价值监控；高置信账号/设备/IP/partner_id 处置。
- 灰度策略：先高价值资产和蜜罐命中入口，再扩展到同类接口；中置信限速/短 token/访问冷却。
- 业务协同：资产最小化、展示脱敏、权限改造、弱端收敛、合作方审计、法务诉讼。
- 体验 / 误伤控制：合作方白名单、用户正常分享保护、低价值页面不重防、业务转化监控。
- 指标评估：黑市报价、TOP10w 请求所需账号量、版权投诉、取证召回/准确率、漏出量、业务误伤、黑产迁移。
- 样本回流和复盘：蜜罐/水印、外部泄漏样本、蓝军结果、投诉和诉讼素材回流到资产防护策略。

版权保护专项按前链路产品改造、中链路策略对抗、后链路取证诉讼组织：前链路提高门槛；中链路分型对抗；后链路用水印、蜜罐、外部投诉、案件素材反推爬取路径。

## 8. 禁止行为

- 禁止把反爬直接等同协议。
- 禁止不做资产分级就给全量接口防护建议。
- 禁止只输出接口签名、频控、封禁。
- 禁止把外部报价/投诉当内部证据。
- 禁止忽略合作方、内部链路、缓存、弱端和前端泄漏。
- 禁止证据不足强结论。
- 禁止忽略业务体验和正常分享。

## 9. 质量校验

输出前自查：

- 是否先确认资产分级？
- 是否识别反爬领域和具体攻击手法？
- 是否覆盖协议、群控、破解包、真人众包、合作方/内部泄漏、缓存/前端泄漏候选？
- 是否保留非常 6+1 反爬飞轮？
- 是否区分强 / 中 / 弱证据和反证？
- 是否给出资产级反查和最小补证？
- 是否有黑市报价、TOP 请求账号量、投诉、漏出、取证准召等指标？
- 是否避免只讲接口防护？

不合格时必须补齐后再输出。

## 10. 失败处理

- 信息不足：降级为资产级溯源假设，要求补 asset_id/content_id/url/hash/watermark_id。
- 证据冲突：输出协议、群控、破解包、真人、合作方、缓存多假设分支。
- 超出 Skill 边界：切换或组合 protocol、group_control、cracked_app、crowdsourcing、material Skill。
- 工具 / API 不可用：说明无法完成哪类日志 join，改用外部样本、水印、CDN、合作方或端侧日志替代。
- 无法判断：明确说“当前不足以定位攻击源头”，说明缺资产标识、入口日志还是外部泄漏样本。
