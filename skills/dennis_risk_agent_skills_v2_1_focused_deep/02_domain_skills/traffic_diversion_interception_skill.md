# Traffic Diversion & Interception Skill：导流截流治理 Skill v2.3 executable-deep

## 0. Skill 定位

本 Skill 解决直播、内容、主页、评论、粉丝关系、私信、搜索等场景中的导流截流风险。导流截流的本质是“目标获取 → 触达 → 站外承接 → 变现”的链路型风险，不是单点内容违规，也不默认等同反爬、协议或账号盗号。

不解决：核心资产被批量爬取的主控问题、服务端请求脱端的协议问题、账号被接管的盗号问题。遇到这些情况应组合 anti_crawler_expert_skill、protocol_attack_expert_skill、account_security_expert_skill，但只有补齐对应证据后才切换主控。

## 1. 触发条件

- 关键词触发：导流、截流、站外添加、私域、站外群、微信/QQ、直播间被添加、评论区引流、搜索添加、私信触达、主页签名、粉丝列表、动态暴露、昵称 ID。
- 业务场景触发：直播间用户被站外添加、粉丝被私信引导、评论区留联系方式、达人/主播流量被截走、用户 ID 或昵称被搜索后触达、主页/动态/粉丝列表暴露目标。
- 用户意图触发：用户问“用户为什么被站外添加”“是不是被爬了”“怎么治理直播间导流”“怎么防截流”“怎么还原站外承接链路”。
- 反向不触发：只有接口高频、无端请求、价格/版权/库存泄漏时，不作为主控；只有账号换绑、支付/提现异常时，不作为主控。
- 需要转交给其他 Skill 的情况：
  - 证明用户信息或关系链被批量自动化获取：组合 anti_crawler_expert_skill。
  - 证明请求脱离端侧链路：组合 protocol_attack_expert_skill。
  - 证明账号被接管或 token 泄露：组合 account_security_expert_skill。
  - 证明统一调度账号矩阵触达：组合 group_control_expert_skill。
  - 批量私信、批量互动、客服/运营触达、达人/MCN 运营：先引用 `06_templates/legal_operation_matrix_playbook_v2_3.md` 判断是否授权触达，再决定是否进入导流局部治理。

## 2. 输入格式

- 必需输入：业务场景、被触达对象、疑似信息暴露入口、触达方式、是否有站外承接证据。
- 可选输入：直播间/内容/评论/主页/动态/粉丝列表样本，用户 ID/昵称/数字 ID，搜索日志，关注/私信日志，站外联系方式、群、落地页、话术，账号/设备/IP/时间线。
- 缺失时可默认假设：用户只说“直播间用户被站外添加”时，默认先按导流截流链路排查，不默认反爬或协议。
- 缺失但不可假设时如何处理：缺少站外承接证据时，不定性黑产导流；缺少批量采集证据时，不定性反爬。
- 用户只给模糊问题时的最小可用输入：哪个场景、谁被添加、对方如何找到目标、通过什么方式触达、站外去了哪里。

## 3. 专家认知

- 这类风险的本质：导流截流不是“某条评论违规”，而是黑灰产或竞对先从平台展示面获取目标，再通过搜索、关注、私信、评论、站外账号匹配等方式触达，最后导入微信/QQ/群/落地页/私域完成变现。
- 黑产 / 风险动机：抢主播/达人流量、私域转化、诈骗、色情/博彩引流、竞品获客、粉丝关系截流、交易导流。
- 主要风险形态：
  - 展示面目标获取：直播间公开信息、用户 ID、昵称、评论、榜单、粉丝列表、动态、主页签名。
  - 搜索触达：按昵称、数字 ID、评论关键词、头像、地理或内容线索搜索添加。
  - 私信/关注触达：关注后私信、批量评论、主页挂联系方式、引导加群。
  - 站外承接：微信/QQ/群、落地页、私域工具、竞品账号、诈骗话术。
  - 账号矩阵导流：多账号复用话术、设备/IP/昵称模板、主页签名模板。
- 常见混合形态：导流+群控私信、导流+真人搜索添加、导流+反爬关系链获取、导流+账号交易、导流+内容违规。
- 和相近风险的区别：
  - 反爬关注核心资产被批量低成本获取；导流截流关注目标获取后的触达和站外承接。
  - 协议关注请求脱离端侧链路；导流截流即使全是真人端行为也可能成立。
  - 账号安全关注账号被接管；导流截流关注正常用户被外部触达和流量被截走。
  - 正常社交有用户意愿和关系上下文，导流截流有目标化触达、话术模板和站外承接。

## 4. 判断规则

按顺序判断，命中即进入对应分支；证据不足时不得强结论。

1. 如果用户 ID/昵称/评论/粉丝列表/动态/主页等信息暴露入口，与搜索/关注/私信/站外添加时间线闭合，且存在站外承接证据，则判断为高置信导流截流链路。
2. 如果直播间或内容互动后，被触达对象集中收到搜索添加、关注、私信或站外邀请，但站外承接未闭合，则判断为中置信导流截流嫌疑，需要补站外证据和账号矩阵证据。
3. 如果存在多账号复用话术、主页签名、站外联系方式、设备/IP/注册来源相似，则判断为账号矩阵导流，需要组合 group_control 或 account Skill 做账号侧治理。
4. 如果批量私信、批量互动、客服/运营触达或达人/MCN 运营存在授权主体、账号范围、工具来源、操作人和审计记录，先按 `06_templates/legal_operation_matrix_playbook_v2_3.md` 判断授权触达；有授权但用于站外导流、骚扰、欺诈时，按局部风险治理，不一刀切处置整个矩阵。
5. 如果仅有“用户被添加”但无站外承接、无批量触达、无信息暴露入口闭合，则不得定性黑产导流，只能补证或观察。
6. 如果有批量访问关系链、粉丝列表、用户资料的自动化证据，才组合反爬；没有爬虫证据时不得触发反爬强结论。
7. 如果有无端请求、接口直达、签名/token 异常，才组合协议；只有站外添加不得判断协议。
8. 如果触达来自普通关注、正常社交、用户主动外联、主播合规引导、单个账号偶发行为，则降级或转业务/社区治理。
9. 如果缺少日志或工具不可用，输出“当前不足以判断导流截流”，说明缺信息暴露入口、触达方式还是站外承接证据。

## 5. 证据体系

- 强证据：
  - 信息暴露入口与站外添加时间线闭合；
  - 搜索日志显示按用户 ID、昵称、评论关键词或头像线索定位；
  - 关注/私信/评论后出现微信/QQ/群/落地页承接；
  - 多个受害用户指向同一站外账号、群或话术；
  - 黑产账号矩阵复用主页签名、昵称模板、话术、设备/IP；
  - 站外承接后出现诈骗、交易、竞品获客或私域变现。
- 中证据：
  - 直播互动后短时间被陌生账号添加；
  - 评论区、主页、动态、粉丝列表暴露可搜索标识；
  - 触达账号低质或新号占比高；
  - 私信命中导流关键词；
  - 多直播间/内容复用相似触达路径。
- 弱证据：
  - 单个用户被站外添加；
  - 单条评论疑似留联系方式；
  - 单账号关注很多用户；
  - 用户投诉“像被加了”但无样本；
  - 直播间流量下降。
- 反证：
  - 正常社交互动；
  - 普通关注；
  - 用户主动外联；
  - 主播或商家合规引导；
  - 达人/MCN/客服/运营授权触达，且无站外导流或骚扰证据；
  - 无站外承接证据；
  - 单个账号偶发行为；
  - 平台外公开信息来源。
- 误判来源：粉丝正常加好友、用户自行留联系方式、跨平台同名搜索、运营活动、主播福利群、客服合规触达。
- 最小补证清单：
  - 信息暴露入口；
  - 目标获取路径；
  - 触达方式；
  - 站外承接证据；
  - 黑产账号矩阵；
  - 时间线；
  - 正常社交和用户主动外联反证。

## 7. 治理闭环

- 查数补证：展示面、搜索、关注、私信、评论、站外样本、账号设备关系和时间线 join。
- 合法矩阵前置补证：批量私信、批量互动、客服/运营触达、达人/MCN 运营先按 `06_templates/legal_operation_matrix_playbook_v2_3.md` 补授权主体、账号范围、工具来源、操作人、操作目的、敏感动作、收益主体和历史违规。
- 识别策略：信息暴露入口识别、搜索添加识别、私信导流识别、站外联系方式识别、账号矩阵识别。
- 分层处置：
  - 高准：导流账号封禁/限权、私信限制、站外链接和联系方式处置、账号矩阵联动。
  - 中准：私信冷却、关注限频、搜索限制、评论折叠、人工复核。
  - 低准：用户提醒、主播教育、加采、观察。
- 产品治理：用户 ID/昵称/评论/粉丝列表/动态/主页敏感信息脱敏，搜索限制，陌生人触达门槛，私信风控。
- 业务协同：主播教育、合规引导规范、站外证据回流、客服取证、社区治理联动。
- 体验 / 误伤控制：保护正常社交、普通关注、用户主动外联和合规运营触达；对单个偶发账号不做矩阵处置。
- 指标评估：站外添加投诉量、导流私信量、站外承接命中、账号矩阵命中、正常私信误伤、主播/用户客诉、触达成功率下降、黑产迁移路径。
- 样本回流和复盘：沉淀信息暴露入口库、导流话术库、站外承接样本、账号矩阵图谱、产品治理清单。

## 8. 禁止行为

- 禁止把直播间用户被站外添加默认归为反爬或协议。
- 禁止没有爬虫证据时触发反爬强结论。
- 禁止只有单个添加行为就定性黑产导流。
- 禁止把授权客服/运营/达人/MCN 的正常批量触达直接定义为导流黑产。
- 禁止因为有授权就放过站外导流、骚扰或欺诈触达。
- 禁止忽略正常社交、普通关注和用户主动外联。
- 禁止只封账号，不治理信息暴露、搜索、私信和站外承接链路。
- 禁止把外部站外截图当作内部证据，必须回到平台内目标获取和触达链路。

## 9. 质量校验

输出前自查：

- 是否说明导流截流的链路本质？
- 是否列出信息暴露入口、目标获取路径、触达方式、站外承接证据和黑产账号矩阵？
- 是否明确没有爬虫证据时不归反爬，没有无端请求时不归协议？
- 是否列出正常社交、普通关注、用户主动外联、无站外承接、单账号偶发等反证？
- 是否给出脱敏、搜索限制、私信风控、主播教育、用户提醒、站外证据回流等治理动作？
- 是否有灰度、误伤控制和指标评估？

不合格时必须补齐后再输出。

## 10. 失败处理

- 信息不足：降级为“导流截流嫌疑”，列信息暴露入口、触达方式和站外承接补证。
- 证据冲突：输出正常社交、主动外联、导流截流、反爬、协议多分支。
- 超出 Skill 边界：只有批量资产获取证据才切 anti-crawler；只有无端请求证据才切 protocol；只有账号接管证据才切 account_security。
- 工具 / API 不可用：说明无法完成哪类 join，改用用户投诉、站外样本、搜索日志、私信日志、账号矩阵抽样替代。
- 无法判断：明确说“当前不足以判断导流截流”，并说明缺信息暴露入口、目标获取路径、触达方式还是站外承接证据。
