# Batch Case Cluster Interpretation Rules v1

## 0. 总原则

批量聚类结果不是风险结论。Dennis 风控 Agent 必须解释“为什么这些 case 被聚在一起”，并判断共性来自风险链路还是业务机制。

必须回答：

- 最大共性是什么？
- 是资源共性、行为共性、链路共性、收益共性、入口共性、后验共性还是业务共性？
- 共性是否足以支持同源、同链路或统一治理？
- 哪些 case 应该拆出去？
- 哪些反证必须优先排除？

## 1. 五类批量结论

### 1.1 同源同链路

定义：多个 case 复用同一批关键资源，并走相似攻击链路，治理入口可以合并。

常见证据：

- 设备/IP/token/包/账号关系复用。
- 接口序列、行为路径或触达链路一致。
- 同批启动/停止或任务窗口一致。
- 收益主体、站外承接或提现链路聚集。
- 合法矩阵、活动、实验、版本等反证已排除。

治理倾向：打团组、打工具、打入口、打收益主体，可做统一策略。

### 1.2 同源不同链路

定义：多个 case 复用同一资源或主体，但在不同业务场景作恶。

常见证据：

- 共享设备/IP/账号/收益主体。
- 行为链路不同，例如一批参与活动、一批导流、一批爬取。
- 资源复用强，但业务入口不同。

治理倾向：以资源主体治理为主，业务场景分别补策略。

### 1.3 不同源同机制

定义：case 不共享攻击资源，但被同一业务规则、入口、版本、实验或活动机制诱发相似表现。

常见证据：

- 同一活动规则导致相同任务路径。
- 同一版本导致埋点缺失。
- 同一实验导致指标波动。
- 同一入口暴露导致多个主体可利用。
- 无明显资源复用或收益聚集。

治理倾向：修规则、修入口、修口径，不按团伙打。

### 1.4 表象相似

定义：case 只在高频、低质、缺日志、时间相近、地理聚集等表象上相似，没有关键链路或资源共性。

治理倾向：分案处理、监控、补证，不做统一处罚。

### 1.5 证据不足

定义：输入对象、时间窗口、行为口径、收益口径或反证缺失，无法判断是否同源或同机制。

治理倾向：输出下一轮 `query_intent`，补最小共性证据。

## 2. 证据强度解释

强共性证据：

- 跨 case 复用同一关键资源，并与风险动作直接相连。
- 跨 case 共享完整攻击链路。
- 跨 case 收益主体或站外承接闭合。
- 关键反证已排除。

中共性证据：

- 行为路径相似。
- 时间同步或任务窗口集中。
- 入口相同但主体不同。
- 后验质量同向异常。

弱共性证据：

- 高频、低质、缺日志。
- 同一时间段、同一活动、同一地理区域。
- 单一 IP 段或公共网络。
- 单一看板指标异常。

反证：

- 合法运营矩阵。
- 业务活动或开抢机制。
- 实验/版本/口径变化。
- 埋点/SLA/权限问题。
- 自然热点或达人传播。
- 正常社交/用户主动外联。

## 3. 易误判规则

- 多 case 同时高频，不等于同一攻击团伙。
- 多 case 同一活动，不等于活动黑产。
- 多 case 前端无日志，不等于协议团伙，可能是版本或埋点问题。
- 多 case 设备聚集，不等于群控，可能是合法矩阵或企业网络。
- 多 case 后验低质，不等于黑产，可能是渠道或活动质量问题。
- 多 case 私信/关注异常，不等于导流黑产，必须看站外承接。
- 多 case CTIT 异常，不等于渠道作弊，必须排除归因规则和预算变化。

## 5. 降级规则

- 如果只有弱共性证据：结论降级为“表象相似”或“证据不足”。
- 如果业务共性解释更强：结论改为“不同源同机制”。
- 如果关键反证缺失：不得输出“同源同链路明确判断”。
- 如果 Data Agent 返回 partial / failed / no_permission：必须降级，并输出缺失证据。
- 如果统一治理会造成高误伤：必须拆分高置信和待补证分群。
