# Data Agent 能力画像 v1

## 1. Data Agent 是什么

Data Agent 是快手内部数据平台的智能助手，定位是承接数据查询、数据资产检索、SQL 生成、看板分析、AB 实验分析、画像标签和人群圈选等数据工作。

在 Dennis 风控 Agent 体系中，Data Agent 不是风险专家，也不是策略决策器，而是数据能力提供方：

- Data Agent 负责取数、找表、SQL、看板、AB、画像、人群圈选。
- Dennis 风控 Agent 负责风险理解、Skill 路由、证据需求、结果解释、结论等级、治理建议。

当前 Codex 阶段不能真实调用 Data Agent，只能基于用户问题生成 `query_intent`、查询模板、解释规则和结论阈值。未来内部平台阶段，才把 `query_intent` 转成真实 Data Agent 调用。

## 2. 适用场景

Data Agent 适用于涉及快手内部数据平台、数据资产、指标、看板、SQL、实验和画像的人机协作场景，包括：

1. 数据查询与取数：查业务指标、生成查询语句、从数仓取数。
2. 数据集分析：基于数据集编号做周同比、占比、归因、漏斗、累计等分析。
3. 数据表检索与解读：找某类业务表，理解表结构、字段含义、分区、权限和血缘。
4. 看板与多维分析：分析 KwaiBI、天策、天玑、多维分析链接中的指标、趋势和异常归因。
5. 查询诊断与优化：诊断 SQL 慢查询、性能瓶颈、扫描量、join 方式和查询规范。
6. KwaiBI 数据资产检索：查找看板、数据集、指标定义和相关资产。
7. 权限与运维：查询数据权限、任务状态、数据血缘和访问申请路径。
8. AB 实验分析：基于 AB 实验链接或实验名称做组间对比、CUPED、DiD、LR 指标、推全决策、异常检测、实验报告和趋势图分析。
9. 达芬奇画像与人群圈选：画像标签检索、标签口径解读、标签规则圈包、SQL 圈包、分群包创建与管理。

## 3. 触发条件

当用户问题包含以下任一类型需求时，应进入 Data Agent 能力画像分支：

- 需要查业务指标、监控数据、KPI、统计数据、业务报表。
- 需要生成 SQL、解释 SQL、优化 SQL 或诊断慢查询。
- 需要找表、理解表结构、字段含义、分区、血缘、权限。
- 需要分析数据集编号、数据集指标、周同比、占比、归因、漏斗。
- 提供 KwaiBI、天策、天玑、多维分析、AB 实验平台等链接。
- 询问看板指标、趋势、异常归因、指标口径。
- 需要搜索看板、数据集、指标定义或数据资产。
- 需要 AB 实验分析、CUPED、DiD、组间对比、推全决策、实验报告。
- 需要用户画像、画像标签、标签口径、人群圈选、圈包、分群包。
- 需要访问公司内部应用或内部数据平台获取数据。

典型触发关键词包括：

- 数据平台：`KwaiBI`、`天策`、`天玑`、`多维分析`、`数据集`、`dataset`、`数仓表`、`Hive 表`、`看板`、`dashboard`。
- 数据分析：`日活`、`成交额`、`GMV`、`周同比`、`占比`、`归因`、`漏斗`、`指标口径`、`趋势`、`异常归因`。
- SQL / 表：`SQL`、`查询语句`、`取数`、`找表`、`表结构`、`字段含义`、`分区`、`血缘`、`查询太慢`、`SQL 优化`。
- AB 实验：`AB实验`、`abtest`、`CUPED`、`DiD`、`组间对比`、`推全`、`实验报告`、`LR 指标`。
- 画像圈选：`达芬奇`、`画像标签`、`标签查询`、`标签口径`、`人群圈选`、`圈包`、`分群包`、`标签规则`。

## 4. 支持的平台 / 链接类型

Data Agent 能力画像覆盖以下平台或链接类型。当前文档只记录平台能力，不提供真实 API 调用方式。

| 平台 / 链接类型 | 典型域名或特征 | 支持能力 |
|---|---|---|
| KwaiBI | `kwaibi.corp.kuaishou.com` | 看板分析、数据集查询、指标定义、数据资产检索 |
| 天策 | `tc.corp.kuaishou.com` | 看板分析、业务趋势、异常归因 |
| 天玑 | `adsdata.corp.kuaishou.com` | 看板分析、广告或投放相关多维分析 |
| 多维分析 / OLAP | KwaiBI OLAP、多维分析链接 | 维度下钻、趋势分析、归因分析 |
| AB 实验平台 | `abtest.corp.kuaishou.com` | 实验信息、组间对比、CUPED、DiD、推全建议、实验报告 |
| 数据集 | datasetId、数据集编号 | 周同比、占比、累计、归因、漏斗等分析 |
| 数仓 / Hive 表 | 表名、字段、分区、血缘 | 找表、表结构、字段含义、权限、血缘 |
| 达芬奇画像 | 画像标签、标签规则、圈包 | 标签检索、标签口径、规则圈包、SQL 圈包、分群包 |

涉及 `corp.`、`internal.` 等内部系统域名，并且问题目标是数据访问、看板解读、指标查询、实验分析、画像圈选或权限运维时，应优先识别为 Data Agent 能力相关。

## 5. 核心能力范围

Data Agent 的核心能力范围包括：

1. 数据查询与 SQL 生成
   - 自然语言转 SQL。
   - 根据问题推荐可能的数据表。
   - 生成取数口径、查询条件、聚合维度和时间范围。

2. 智能表检索
   - 按业务主题、指标、字段、数据域检索 Hive 表。
   - 推荐相关核心表或候选表。
   - 解释表用途、分区、字段和数据血缘。

3. 表详情解读
   - 解释表结构、字段含义、分区状态、权限、上下游血缘。
   - 判断某张表是否适合作为某个查询意图的候选资产。

4. 看板与多维分析
   - 支持 KwaiBI、天策、天玑、多维分析链接。
   - 读取看板指标、筛选条件、维度、趋势和异常点。
   - 支持趋势分析、维度归因、异常归因和口径解释。

5. SQL 诊断与优化
   - 分析慢查询、性能瓶颈、扫描范围、join 方式、分区过滤和查询规范。
   - 给出查询优化建议。

6. SQL 逻辑解读
   - 解释复杂 SQL 的业务含义、计算链路和指标口径。
   - 辅助确认 SQL 是否匹配用户查询意图。

7. 数据资产检索
   - 检索 Hive 表、看板、数据集、指标定义等数据资产。

8. 权限与运维
   - 解释数据权限、任务状态、任务血缘、权限申请或访问路径。

9. AB 实验分析
   - 基于实验链接或实验名称分析实验信息。
   - 支持组间对比、CUPED、DiD、LR 指标、推全决策、异常检测、实验报告、趋势图等。

10. 达芬奇画像与人群圈选
    - 检索画像标签。
    - 解读标签口径和定义。
    - 支持标签规则或 SQL 方式圈选人群。
    - 支持分群包创建和管理能力画像。

| 问题类型 | 用户表达示例 | Dennis Agent 应生成的 Data Agent 意图 |

## 7. 不支持场景

以下场景不应交给 Data Agent：

1. 非数据平台相关的代码问题或通用技术咨询。
2. 不涉及内部数据、SQL、表、看板、实验、画像、圈包的普通风控研判。
3. 要求 Data Agent 直接给出风控最终定性、处罚、冻结、扣除、封禁、策略上线。
4. 要求编造真实表名、字段名、接口路径、内部 API、平台返回结果。
5. HRBI 相关敏感数据，例如 `hrbi.corp.kuaishou.com`。这类需求应说明：HRBI 是敏感数据，暂不支持通过 Data Agent 访问，如有需求请联系 HR 团队。
6. 用户没有提供足够业务上下文，却要求直接输出真实 SQL 结果。当前 Codex 阶段只能输出查询意图、候选口径和补充信息清单。

## 8. 与 Dennis 风控 Agent 的职责边界

Dennis 风控 Agent 与 Data Agent 的边界必须清晰：

| 环节 | Dennis 风控 Agent | Data Agent |
|---|---|---|
| 业务理解 | 判断风险领域、业务目标、攻击假设、治理目标 | 不负责最终风险理解 |
| Skill 路由 | 选择主控 Skill 和辅助 Skill | 不参与风控 Skill 路由 |
| 证据需求 | 定义强 / 中 / 弱证据、反证、补证动作 | 根据数据意图取数、找表、生成 SQL |
| 数据执行 | 当前 Codex 阶段不真实执行数据查询 | 未来内部平台阶段执行查询或分析 |
| 结果解释 | 把数据结果解释为风险结论等级 | 提供数据结果、看板分析、SQL 结果 |
| 风险定性 | 给出最多能下的结论，控制过度自信 | 不直接定性黑产、协议、群控、盗号 |
| 治理建议 | 给出灰度、限权、拦截、监控、回流、评估指标 | 不负责处罚、冻结、扣款、策略上线 |

原则：

- Data Agent 可以回答“数据怎么看、怎么查、查到了什么”。
- Dennis 风控 Agent 才回答“这说明什么风险、结论强度如何、该怎么治理”。
- Data Agent 输出不能直接等同于风控证据闭环，必须经过 Dennis 风控 Agent 的反证、误伤和业务边界校验。

## 9. 当前 Codex 阶段如何使用

当前 Codex 阶段不能真实调用 Data Agent，也不能假装已经访问内部系统或拿到结果。正确使用方式是生成结构化的数据需求说明，供未来平台或人工执行。

### 9.1 输出 query_intent

当用户问题需要 Data Agent 能力时，Dennis 风控 Agent 应输出：

```yaml
query_intent:
  intent_type: "<dataset_metric_analysis | sql_generation_and_data_query | table_search | table_profile_explain | dashboard_analysis | olap_diagnosis | sql_diagnosis_optimization | sql_logic_explain | data_asset_search | data_permission_ops | ab_experiment_analysis | profile_tag_and_audience_selection>"
  business_question: "<用户真实要回答的业务问题>"
  risk_context: "<对应风险领域、攻击假设、治理目标>"
  required_metrics:
    - "<需要观察的指标>"
  dimensions:
    - "<需要下钻的维度>"
  time_window: "<时间范围；未知则写待补充>"
  filters:
    - "<业务筛选条件；未知则写待补充>"
  evidence_purpose: "<强证据 / 中证据 / 反证 / 监控指标 / 治理评估>"
  expected_output: "<SQL模板 | 看板解读 | 表候选 | AB分析 | 人群圈选方案 | 指标解释>"
```

### 9.2 输出查询模板

当前阶段只允许输出查询模板或字段需求，不得编造真实表名和字段名。模板应表达：

- 需要的数据域。
- 需要的实体粒度，例如用户、设备、账号、IP、token、包、订单、直播间、商品、实验组。
- 需要的时间窗口。
- 需要的 join 关系。
- 需要的分层指标。
- 需要的反证指标。
- 结论阈值的建议口径。

### 9.3 输出解释规则

Dennis 风控 Agent 应说明 Data Agent 返回后如何解释：

- 哪些结果可以作为强证据。
- 哪些结果只能作为中证据或弱信号。
- 哪些结果是反证。
- 哪些结果代表口径、埋点、样本或权限问题。
- 结果缺失时如何降级判断。

### 9.4 输出结论阈值

当前阶段可以输出“阈值设计原则”，但不能伪造内部真实阈值。阈值应表达为：

- 相对基线，例如较历史均值、同类人群、同周期、实验对照组异常。
- 多证据组合，例如单指标异常不足以定性，需设备、账号、行为、收益或链路组合。
- 分层处置门槛，例如监控、加采、二次验证、局部限权、强拦截。
- 误伤约束，例如白名单、授权矩阵、正常业务高峰、埋点缺失、实验流量。

## 10. 未来内部平台阶段如何接入

未来如果 Dennis 风控 Agent 运行在可访问内部平台的环境中，可以把当前 `query_intent` 转成真实 Data Agent 调用。

建议接入流程：

1. Dennis 风控 Agent 识别业务领域、风险类型和证据缺口。
2. 生成结构化 `query_intent`，保留用户原始问题和完整上下文。
3. 平台侧把 `query_intent` 转换为 Data Agent API 请求。
4. Data Agent 负责找表、生成 SQL、执行查询、分析看板、分析实验或圈选人群。
5. Data Agent 返回数据结果、SQL、表信息、看板分析或 AB 分析。
6. Dennis 风控 Agent 对结果做风险解释：
   - 结论等级；
   - 强 / 中 / 弱证据；
   - 反证与误判；
   - 治理动作；
   - 灰度策略；
   - 评估指标。
7. 如果结果不足，Dennis 风控 Agent 继续生成下一轮补证 `query_intent`。

未来平台阶段的接入约束：

- 必须保留用户原始问题，不改写核心诉求。
- 包含 URL 的问题，应把链接作为上下文传入。
- 包含 SQL 代码的问题，应保留 SQL 原文。
- 涉及权限、敏感数据或高风险处置时，需要平台权限控制和审计。
- Data Agent 返回结果不应绕过 Dennis 风控 Agent 直接触发处罚或策略上线。

## 11. 禁止行为

1. 禁止在当前 Codex 阶段声称已经调用 Data Agent。
2. 禁止编造 Data Agent API、认证方式、接口路径、请求参数或返回结构。
3. 禁止编造真实表名、字段名、分区、数据血缘、看板内容、AB 实验结果或画像标签结果。
4. 禁止让 Data Agent 直接承担风控最终定性。
5. 禁止让 Data Agent 直接执行处罚、冻结、扣除、封禁、策略上线。
6. 禁止把单个数据指标异常直接解释成黑产、协议、群控、盗号或作弊强结论。
7. 禁止跳过反证，例如埋点缺失、口径差异、权限缺失、样本偏差、合法运营、实验流量、业务活动。
8. 禁止把 HRBI 等敏感数据需求交给 Data Agent。
9. 禁止在没有用户授权和平台能力的情况下导出、圈选或管理真实人群包。
10. 禁止为了满足格式而输出看似精确但无法验证的 SQL、阈值或治理结论。
