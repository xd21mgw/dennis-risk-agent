# Batch Case Commonality Query Map v1

## 0. 使用原则

本文件定义“一批 case 找共性”时应该怎么问 Data Agent。当前 Codex 阶段只生成查询意图，不调用真实 Data Agent。

批量共性不按 Skill 组织，而按共性证据类型组织：

- 资源共性
- 行为共性
- 链路共性
- 收益共性
- 入口共性
- 后验共性
- 业务共性
- 处置反馈共性

## 1. 资源共性

适用风险：协议、群控、token 泄露、ATO、破解包、渠道作弊。

Data Agent 查询目标：判断多个 case 是否复用设备、IP、UA、token、客户端包、账号关系、渠道资源。

```yaml
query_intent:
  intent_id: "batch_resource_commonality_001"
  risk_question: "这批 case 是否复用同一批攻击资源"
  target_evidence: "资源共性"
  commonality_goal:
    classify_as: "同源同链路"
    compare_level: "对象级"
  applicable_skill:
    primary: "evidence_decomposition_skill"
    auxiliary:
      - "risk_chain_reconstruction_skill"
      - "attack_type_classification_skill"
  minimum_inputs:
    required: ["case_id列表", "观测时间窗口", "账号/设备/IP/token/包/渠道中至少一种对象集合"]
    optional: ["历史处置结果", "合法矩阵信息"]
    missing: []
  query_dimensions:
    entities: ["case", "账号", "设备", "IP", "UA", "token", "客户端包", "渠道"]
    group_by: ["对象复用", "资源团组", "跨case出现次数", "时间稳定性"]
    joins: ["case样本", "设备环境", "登录态", "客户端包信息", "渠道归因信息"]
  time_window:
    baseline: "待补充"
    observation: "待补充"
    granularity: "小时或天"
  expected_outputs: ["资源复用图", "跨case共享资源", "团组稳定性", "授权/业务反证"]
  interpretation_notes:
    strong_evidence_if: ["多个 case 复用高风险关键资源，且业务反证排除"]
    weak_signal_if: ["只共享时间窗口或泛化地理/IP段"]
    counter_evidence_if: ["企业网络、合法矩阵、公共出口、同版本发布可解释"]
  conclusion_threshold:
    sufficient_for: "高度疑似"
    must_combine_with: ["行为共性或链路共性"]
  safety_boundary:
    false_positive_risks: ["企业网络", "公共 Wi-Fi", "合法运营矩阵", "同版本发布"]
    prohibited_actions: ["不得仅凭 IP 或设备聚集统一处罚"]
```

## 2. 行为共性

适用风险：群控、真人众包、活动黑产、低质流量、导流触达。

查询目标：判断多个 case 是否共享路径、节奏、同批启停、任务完成窗口。

最小输入：case 列表、行为事件口径、观测窗口。

推荐维度：路径模板、停留时长、时间间隔、启动/停止窗口、任务完成窗口、自然用户对照。

期望返回：路径相似度、模板命中、时间同步、自然/活动高峰反证。

解释规则：路径相似是中证据；若叠加资源共性、收益共性或任务平台线索才升级。活动规则、教程传播、自然热点可能造成行为相似。

## 3. 链路共性

适用风险：协议、破解包、反爬、导流截流、token 泄露。

查询目标：判断多个 case 是否共享前后端链路缺失、接口序列、SDK 缺失、搜索/私信/站外承接链路。

最小输入：case 列表、链路事件口径、目标业务动作。

推荐维度：接口序列、页面/事件链路、SDK 覆盖、客户端包、搜索/关注/私信链路、站外承接。

期望返回：链路模板、缺失节点、跨 case 复用链路、链路反证。

解释规则：链路共性比行为共性更强，但必须排除埋点缺失、官方包问题、合法工具和授权触达。

## 4. 收益共性

适用风险：活动黑产、群控、真人众包、渠道套利、导流变现。

查询目标：判断多个 case 是否共享奖励、提现、佣金、结算、站外收益主体。

最小输入：case 列表、收益类型、时间窗口。

推荐维度：奖励主体、提现主体、佣金主体、结算主体、站外承接主体、历史复用。

期望返回：收益集中度、跨 case 收益复用、收益链路图、合法主体反证。

解释规则：收益共性通常是强组织化证据；但商家、MCN、机构等合法主体也会有收益聚集，必须先做合法矩阵判断。

## 5. 入口共性

适用风险：反爬、导流截流、协议入口滥用、活动规则漏洞。

查询目标：判断多个 case 是否来自同一资产入口、信息暴露入口、活动规则入口、直播间/评论/搜索入口。

最小输入：case 列表、入口类型、观测窗口。

推荐维度：接口/页面、直播间、评论、昵称/ID、活动规则、搜索、粉丝列表、动态、私信。

期望返回：入口贡献、入口到风险动作转化、入口反证。

解释规则：同一入口可支持“同机制”判断，不一定是同团伙；若入口共性叠加资源/行为/收益共性，才支持同源同链路。

## 6. 后验共性

适用风险：活动低质、渠道低质、DAU/DNU 异常、流量作弊。

查询目标：判断多个 case 是否共享留存、付费、复访、退款、投诉、长期价值异常。

最小输入：case 列表、后验指标口径、对照人群。

推荐维度：留存、付费、复访、活跃深度、退款、投诉、实验组/对照组、渠道/活动。

期望返回：后验质量差异、趋势、分层贡献、对照组。

解释规则：后验低质是业务质量证据，不自动等于黑产；必须结合资源、链路或收益组织化证据。

## 7. 业务共性

适用风险：误判排除、合法矩阵、活动机制、实验/版本/口径变化。

查询目标：判断多个 case 的相似是否由同一业务机制导致。

最小输入：case 列表、业务日历、版本/实验/活动/授权信息。

推荐维度：活动、实验、版本、运营排期、授权主体、工具来源、口径变更、SLA。

期望返回：业务解释匹配度、反证摘要、需要排除的 case。

解释规则：业务共性优先作为反证或“不同源同机制”证据，防止把正常业务机制误判为黑产。

## 8. 处置反馈共性

适用风险：策略效果评估、误伤评估、团伙迁移。

查询目标：判断多个 case 在处置后的反馈是否一致，例如命中、申诉、回流、迁移、复发。

最小输入：case 列表、处置动作、处置时间、后验窗口。

推荐维度：处置动作、申诉、复发、迁移、业务损伤、风险回落。

期望返回：治理有效性、误伤信号、迁移方向。

解释规则：处置反馈用于治理闭环，不是攻击定性的原始证据；需要和前置证据一起解释。
