# 风控证据到 Data Agent 查询映射 v1

## 0. 使用原则

本文件按证据类型组织，不按 Skill 组织。Dennis 风控 Agent 先判断需要补什么证据，再生成对应 `query_intent`。当前 Codex 阶段不调用 Data Agent，只生成查询意图、查询模板和解释规则。

每类证据都遵循：

- 适用风险
- Data Agent 查询目标
- `query_intent` 示例
- 最小输入
- 推荐查询维度
- 期望返回类型
- 返回后如何解释
- 证据不足时如何降级

## 1. 前后端链路一致性

适用风险：协议攻击、破解包、埋点缺失、反爬接口滥用。

Data Agent 查询目标：对比服务端请求、前端事件、页面路径、端侧上下文是否形成合理链路。

```yaml
query_intent:
  intent_id: "frontend_backend_consistency_001"
  risk_question: "服务端请求是否脱离正常端链路"
  target_evidence: "前后端链路一致性"
  applicable_skill:
    primary: "protocol_attack_expert_skill"
    auxiliary: ["cracked_app_expert_skill", "evidence_decomposition_skill"]
  minimum_inputs:
    required: ["时间窗口", "目标接口或业务动作", "对象粒度"]
    optional: ["客户端版本", "渠道", "页面事件口径"]
    missing: []
  query_dimensions:
    entities: ["用户", "账号", "设备", "请求", "前端事件"]
    group_by: ["接口动作", "客户端版本", "渠道", "对象分群"]
    joins: ["服务端请求日志", "前端事件日志", "端侧上下文日志"]
  time_window:
    baseline: "待补充"
    observation: "待补充"
    granularity: "小时或天"
  expected_outputs: ["链路覆盖率", "无前端事件请求占比", "版本/渠道分布", "异常样本"]
  interpretation_notes:
    strong_evidence_if: ["关键接口大量请求无前置页面/事件链，且排除采集口径问题"]
    weak_signal_if: ["仅前端日志缺失，未排除埋点、采样、版本差异"]
    counter_evidence_if: ["官方版本同样缺日志或特定埋点整体缺失"]
  conclusion_threshold:
    sufficient_for: "高度疑似"
    must_combine_with: ["接口序列固化", "token/device/ip/ua 一致性", "包或 SDK 证据"]
  safety_boundary:
    false_positive_risks: ["埋点缺失", "SDK 采样", "网关采样", "官方版本问题"]
    prohibited_actions: ["不得仅凭前端无日志直接定协议"]
```

最小输入：时间窗口、业务动作或接口语义、对象粒度、前端事件口径。

推荐查询维度：客户端版本、渠道、设备类型、账号分群、请求动作、页面路径。

期望返回类型：覆盖率、缺失率、趋势、异常分布、样本列表、口径说明。

返回后如何解释：链路缺失只是链路冲突；只有排除埋点/版本/采样并叠加接口直达、序列固化或 token 异常，才接近协议证据。

证据不足时如何降级：降级为“链路冲突待补证”，优先补 SDK 日志覆盖和包完整性。

## 2. SDK 日志覆盖

适用风险：破解包、协议攻击、埋点缺失、插件辅助。

Data Agent 查询目标：观察端 SDK 日志覆盖率、缺失分布、版本/渠道/包特征关联。

```yaml
query_intent:
  intent_id: "sdk_log_coverage_001"
  risk_question: "前端或 SDK 日志缺失是否由破解包或采集异常导致"
  target_evidence: "SDK 日志覆盖"
  applicable_skill:
    primary: "cracked_app_expert_skill"
    auxiliary: ["protocol_attack_expert_skill"]
  minimum_inputs:
    required: ["时间窗口", "客户端版本/渠道语义", "风险请求集合"]
    optional: ["包签名口径", "安全模块状态口径"]
    missing: []
  query_dimensions:
    entities: ["设备", "账号", "客户端包", "SDK日志", "风险请求"]
    group_by: ["版本", "渠道", "包签名状态", "SDK模块状态"]
    joins: ["端 SDK 日志", "包信息", "服务端风险请求"]
  time_window:
    baseline: "待补充"
    observation: "待补充"
    granularity: "天"
  expected_outputs: ["SDK覆盖率", "缺失分布", "风险请求与异常包关联", "官方版本对照"]
  interpretation_notes:
    strong_evidence_if: ["风险请求集中于签名/版本/SDK异常包"]
    weak_signal_if: ["只看到日志缺失，没有包或版本证据"]
    counter_evidence_if: ["官方包同版本同样缺失"]
  conclusion_threshold:
    sufficient_for: "高度疑似"
    must_combine_with: ["包签名/版本/安全模块异常", "端行为或请求链路证据"]
  safety_boundary:
    false_positive_risks: ["官方埋点缺失", "日志延迟", "采样口径变化"]
    prohibited_actions: ["不得把 SDK 缺失直接等同协议"]
```

证据不足时如何降级：降级为“端采集异常待排查”，不进入强拦截。

## 3. token / device / ip / ua 一致性

适用风险：token 泄露、协议攻击、ATO、撞库、账号安全。

Data Agent 查询目标：检查 token 与设备、IP、UA、登录态迁移、敏感动作之间的一致性。

最小输入：时间窗口、账号或 token 语义集合、敏感动作、登录事件口径。

推荐查询维度：账号、设备、IP 段、UA、客户端版本、地理跨度、登录前后链路、敏感动作。

期望返回类型：跨设备使用分布、并发冲突、地理冲突、UA/SDK 冲突、敏感动作后置链路。

返回后如何解释：token 在新设备/IP/UA 上无登录迁移和验证链路，并伴随敏感动作，才是强风险；单纯漫游、多设备登录或企业网络不是强证据。

证据不足时如何降级：降级为“登录态异常监控”，补登录迁移、验证链路和用户确认。

## 4. 接口序列固化

适用风险：协议攻击、自动化脚本、反爬接口滥用。

Data Agent 查询目标：分析接口调用顺序、参数模式、时间间隔是否高度固化。

最小输入：风险请求集合、时间窗口、业务动作链路。

推荐查询维度：接口动作、调用顺序、间隔分布、账号/设备/IP 聚类、成功率。

期望返回类型：序列模板、重复率、间隔分布、正常链路对照。

返回后如何解释：高重复接口序列叠加无端链路、签名/token 异常才接近协议；仅自动化运营或官方工具也可能产生固定序列。

证据不足时如何降级：补合法矩阵、官方工具和端链路证据。

## 5. 设备团组

适用风险：群控、设备农场、小号养号、活动黑产。

Data Agent 查询目标：观察设备、账号、IP、环境、收益是否形成稳定团组。

最小输入：时间窗口、目标账号/设备集合、业务场景。

推荐查询维度：设备、账号、IP、环境、地理、注册时间、登录时间、收益主体。

期望返回类型：团组规模、连接图、共享资源、稳定性、历史复用。

返回后如何解释：设备团组只是群控中证据；还需行为路径、同批调度和收益链闭合。

证据不足时如何降级：降级为“设备聚集异常”，补调度和收益证据。

## 6. 行为路径相似

适用风险：群控、真人众包、活动套利、低质流量。

Data Agent 查询目标：分析行为路径、点击序列、停留时长、任务完成路径是否高度相似。

最小输入：业务动作、路径事件口径、时间窗口、对象集合。

推荐查询维度：路径模板、停留时长、完成时间、设备/账号分群、收益结果。

期望返回类型：路径相似度分布、模板命中率、自然用户对照。

返回后如何解释：路径相似不能单独定群控；真人人群在教程任务下也会相似。需要结合设备调度或任务平台/收益链。

证据不足时如何降级：降级为“行为模板化”，补设备调度和任务化证据。

## 7. 同批启动 / 停止

适用风险：群控、批量自动化、活动黑产。

Data Agent 查询目标：检查账号/设备是否在异常集中窗口同批启动、停止、切换任务。

最小输入：观测窗口、启动/停止事件口径、对象集合。

推荐查询维度：分钟级时间桶、设备团组、账号团组、任务动作、收益。

期望返回类型：同批启动峰值、同步率、批次稳定性、自然高峰对照。

返回后如何解释：同批启停是群控强证据之一，但需排除活动开抢、直播开播、官方任务、运营排班。

证据不足时如何降级：降级为“批次同步异常”，补业务日历和合法矩阵。

## 8. 收益聚集

适用风险：群控、真人众包、活动黑产、渠道套利、导流变现。

Data Agent 查询目标：观察奖励、提现、佣金、订单、结算是否向少量主体聚集。

最小输入：收益类型、时间窗口、对象集合。

推荐查询维度：账号、设备、支付/提现主体、商家/达人/机构、活动、渠道。

期望返回类型：收益集中度、关联图、提现路径、历史复用。

返回后如何解释：收益聚集是组织化证据；但商家/MCN/机构合法矩阵也会聚集，需先看授权主体和范围。

证据不足时如何降级：降级为“收益异常待审计”，补授权和业务登记。

## 9. 账号生命周期

适用风险：小号、养号、ATO、活动黑产、真人众包。

Data Agent 查询目标：分析注册、登录、首活、首单、任务完成、沉默、换绑、注销等生命周期。

最小输入：账号集合、时间窗口、关键业务动作。

推荐查询维度：注册来源、首活路径、登录环境、任务完成窗口、留存、付费、敏感动作。

期望返回类型：生命周期分布、短链账号占比、历史质量、异常动作链。

返回后如何解释：短生命周期与低留存是低质或套利信号，不等于黑产；需结合组织化和收益链。

证据不足时如何降级：降级为“低质/异常生命周期”。

## 10. 活动奖励 / 提现

适用风险：活动黑产、活动低质、真人众包、群控。

Data Agent 查询目标：分析奖励获得、提现、核销、退款、退货、留存和付费后验质量。

最小输入：活动 ID 或活动语义、时间窗口、奖励规则。

推荐查询维度：账号、设备、任务路径、奖励金额、提现主体、后验留存/付费。

期望返回类型：奖励聚集、提现聚集、任务窗口、后验质量、异常批次。

返回后如何解释：低钱效不是黑产；奖励/提现聚集叠加任务平台、设备团组或路径模板才支持黑产。

证据不足时如何降级：按活动低质或钱效治理，不做黑产强结论。

## 11. CTIT / 渠道归因

适用风险：渠道抢量、归因劫持、渠道套利、流量反作弊。

Data Agent 查询目标：分析点击到安装/激活/转化的时间间隔、渠道分布、自然量变化和后验质量。

最小输入：渠道、投放活动、时间窗口、归因口径。

推荐查询维度：渠道、媒体、广告位、CTIT 桶、设备、地理、自然量、后验质量。

期望返回类型：CTIT 分布、异常短/长尾、渠道对照、自然量跷跷板、留存/付费。

返回后如何解释：CTIT 异常只是归因异常信号；需结合自然量、后验质量、设备/IP/UA 和渠道行为证据。

证据不足时如何降级：降级为“渠道归因异常”，先做监控和结算复核。

## 12. 自然量跷跷板

适用风险：渠道抢量、归因劫持、渠道质量异常。

Data Agent 查询目标：观察某渠道增长是否伴随自然量或其他渠道异常下跌。

最小输入：渠道列表、时间窗口、归因规则变更信息。

推荐查询维度：渠道、自然/付费来源、时间桶、转化漏斗、后验质量。

期望返回类型：渠道份额变化、自然量变化、总量变化、后验质量。

返回后如何解释：跷跷板支持抢量假设，但也可能由预算、活动、版本、归因口径变化导致。

证据不足时如何降级：补投放排期、归因规则和实验/活动信息。

## 13. 新客真实性

适用风险：活动反作弊、渠道反作弊、低质流量、小号。

Data Agent 查询目标：判断新客是否具备自然新用户的注册、活跃、留存、付费和设备历史。

最小输入：新客定义、时间窗口、活动/渠道口径。

推荐查询维度：注册来源、设备历史、账号历史、留存、付费、回访、行为深度。

期望返回类型：新客质量分布、异常短链、设备复用、后验质量。

返回后如何解释：新客质量低不等于作弊；设备复用、收益链和任务窗口闭合才提高置信。

证据不足时如何降级：低质新客治理和投放优化。

## 14. 后验质量

适用风险：活动低质、渠道低质、流量作弊、黑产套利。

Data Agent 查询目标：分析留存、活跃深度、付费、退款、投诉、复访等后验质量。

最小输入：目标人群、对照人群、时间窗口、质量指标口径。

推荐查询维度：渠道、活动、设备分群、账号分群、风险标签、实验组。

期望返回类型：质量差异、趋势、显著性、分层贡献。

返回后如何解释：后验质量差是业务价值问题，不自动等于黑产；要区分低质、套利和攻击。

证据不足时如何降级：业务钱效和监控治理。

## 15. 信息暴露入口

适用风险：导流截流、反爬资产泄漏、隐私暴露。

Data Agent 查询目标：定位用户 ID、昵称、评论、粉丝列表、动态、私信、搜索等目标信息暴露入口。

最小输入：被触达用户集合、场景、时间窗口。

推荐查询维度：入口页面、信息类型、访问主体、访问频次、后续触达动作。

期望返回类型：暴露入口分布、访问链路、异常访问者、入口贡献。

返回后如何解释：暴露入口是导流链路上游；没有批量抓取证据时不直接判反爬。

证据不足时如何降级：按信息暴露和导流风险补证。

## 16. 搜索 / 关注 / 私信链路

适用风险：导流截流、骚扰、账号安全、合法矩阵超范围。

Data Agent 查询目标：重建从目标获取到搜索、关注、私信、站外添加的触达链路。

最小输入：触达场景、用户/账号集合、时间窗口。

推荐查询维度：搜索词、关注动作、私信动作、触达账号、目标用户、授权主体。

期望返回类型：链路转化率、批量触达分布、触达内容类型、账号矩阵。

返回后如何解释：私信/关注异常不一定是黑产；正常社交、客服、达人运营、用户主动外联都可能存在。

证据不足时如何降级：补站外承接和授权触达证据。

## 17. 站外承接

适用风险：导流截流、诈骗、私域引流、违规营销。

Data Agent 查询目标：识别站外联系方式、外链、二维码、社群、私域承接或投诉反馈链路。

最小输入：触达账号、内容样本、时间窗口、投诉或举报线索。

推荐查询维度：内容类型、账号矩阵、目标用户、承接方式、收益或投诉。

期望返回类型：站外承接证据、账号矩阵、内容模板、投诉/举报关联。

返回后如何解释：站外承接闭合是导流强证据；单次偶发或无承接证据只能中弱信号。

证据不足时如何降级：先做内容加采、用户提醒和站外证据回流。

## 18. 授权主体 / 合法矩阵

适用风险：合法矩阵、群控误判、协议误判、导流局部违规、账号安全误判。

Data Agent 查询目标：校验授权主体、账号范围、工具来源、操作人、操作目的、敏感动作、收益主体和历史违规。

最小输入：主体或账号集合、工具来源语义、时间窗口、操作场景。

推荐查询维度：授权主体、账号范围、工具/app、操作人、动作范围、收益主体、违规历史。

期望返回类型：授权匹配情况、超范围动作、审计链路、局部风险。

返回后如何解释：有授权优先合法矩阵；有授权但超范围是局部违规；无授权且规避平台规则才转攻击判断。

证据不足时如何降级：进入审计补证，不一刀切封禁。

## 19. AB 实验结果

适用风险：策略评估、DAU/DNU 异常、误伤评估、治理效果评估。

Data Agent 查询目标：分析实验组/对照组在风险、业务、误伤和长期指标上的差异。

最小输入：实验名称或链接、指标口径、时间窗口、分组信息。

推荐查询维度：实验组、对照组、用户分层、风险分层、业务指标、LR 指标。

期望返回类型：组间差异、显著性、CUPED/DiD、异常检测、推全建议。

返回后如何解释：实验效果是治理评估，不直接证明攻击存在；DAU/DNU 异常需先排口径、实验和流量结构。

证据不足时如何降级：补数据口径和实验配置核验。

## 20. 画像 / 人群圈选

适用风险：策略灰度、误伤控制、人群分层、低质治理。

Data Agent 查询目标：基于画像标签或规则圈选待监控、灰度、复核或对照人群。

最小输入：人群定义、业务目标、排除条件、时间窗口。

推荐查询维度：画像标签、风险分层、业务价值、活跃/付费/留存、授权身份。

期望返回类型：人群包定义、标签口径、覆盖规模、质量分布、排除条件。

返回后如何解释：画像用于分层和灰度，不是风险定性本身；必须保留申诉和复核。

证据不足时如何降级：输出候选人群定义，等待平台执行和评估。
