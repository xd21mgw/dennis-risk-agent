# Batch Case Governance Playbook v1

## 0. 目标

本文件定义批量 case 找到共性后的治理打法。核心是区分“可以合并治理的共性”和“只能分案处理的表象相似”，避免过度打击。

## 1. 治理选择原则

1. 同源同链路：优先统一治理。
2. 同源不同链路：统一打资源，分场景补策略。
3. 不同源同机制：修业务机制，不按团伙打。
4. 表象相似：分案处理，补证观察。
5. 证据不足：不处罚，先补证。

## 2. 打团组

适用：

- 设备/账号/IP/token/包资源复用明显。
- 同批启停、路径模板和收益聚集闭合。
- 合法矩阵和业务反证已排除。

动作：

- 团组限速、二次验证、敏感动作冷却。
- 团组级灰度拦截。
- 团组标签回流。
- 复发和迁移监控。

误伤控制：

- 拆出合法矩阵、企业网络、测试流量。
- 保留申诉和回滚。

## 3. 打入口

适用：

- 多个 case 来自同一资产入口、信息暴露入口、活动规则入口或接口入口。
- 资源不一定同源，但机制相同。

动作：

- 入口脱敏。
- 搜索限制。
- 接口频控和上下文校验。
- 活动规则补洞。
- 私信/评论/关注等触达入口限频。

误伤控制：

- 评估正常用户路径和业务依赖。
- 先对高风险入口灰度。

## 4. 打工具 / 包 / 版本

适用：

- 多 case 集中在异常客户端包、SDK 缺失、插件、自动化工具或特定版本。

动作：

- 包完整性校验。
- 风险版本限制。
- 强制升级。
- SDK 覆盖修复。
- 非授权工具收紧。

误伤控制：

- 排除官方版本埋点缺失。
- 保留版本回滚和白名单。

## 5. 打收益主体

适用：

- 奖励、提现、佣金、结算、站外承接或私域收益主体跨 case 复用。

动作：

- 延迟发奖。
- 提现/结算复核。
- 局部冻结敏感收益。
- 收益主体审计。
- 回收违规收益。

误伤控制：

- 先判断合法商家、MCN、机构、达人矩阵。
- 局部限权优先于主体级封禁。

## 6. 打渠道

适用：

- CTIT、自然量跷跷板、后验质量和点击/设备异常在渠道维度闭合。

动作：

- 渠道结算复核。
- 分渠道限量。
- 调整归因窗口或归因规则。
- 渠道沟通和申诉。

误伤控制：

- 排除预算、活动、版本、媒体策略、归因口径变化。
- 不因单个 CTIT 异常直接拒付。

## 7. 打规则 / 业务机制

适用：

- 不同源同机制。
- 活动规则、入口暴露、实验配置、版本埋点或口径变化导致多个 case 相似。

动作：

- 修规则。
- 修埋点。
- 修口径。
- 增加业务提示。
- 调整活动门槛和奖励节奏。

误伤控制：

- 不把用户或商家当黑产处置。
- 以业务优化和监控为主。

## 8. 分群治理模板

```text
A 类：高置信同源同链路
- 动作：灰度拦截 / 限权 / 复核
- 需要：人工抽样确认

B 类：同源但链路未完全闭合
- 动作：加采 / 限速 / 监控
- 需要：补收益或链路证据

C 类：不同源同机制
- 动作：修入口 / 修规则 / 修口径
- 需要：业务侧协同

D 类：表象相似或证据不足
- 动作：分案处理 / 继续观察
- 需要：补最小证据
```

## 9. 评估指标

- 风险命中率。
- 误伤率和申诉率。
- 团组复发率。
- 迁移率。
- 入口风险回落。
- 收益挽回或损失控制。
- 正常业务转化影响。
- 人工复核通过率。

## 10. 禁止行为

- 禁止把批量聚类直接转成全量处罚。
- 禁止把低质共性当黑产共性。
- 禁止跳过合法矩阵和业务活动反证。
- 禁止只打账号，不修入口、规则或工具。
- 禁止没有灰度、回滚、申诉和复核机制。
