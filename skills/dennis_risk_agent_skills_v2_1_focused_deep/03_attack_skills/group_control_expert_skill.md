# Group Control Expert Skill：群控专项专家 Skill v2.3 executable-deep

## 0. Skill 定位

本 Skill 解决“是否为群控、是哪类群控、如何补证、如何治理”的问题。核心判断不是设备多、账号多或访问高频，而是是否存在统一调度。

不解决：无端链路接口直打的单纯协议问题、客户端被改造的破解包问题、真人任务平台众包问题、合法运营矩阵管理问题。遇到这些情况应切换或组合 protocol_attack_expert_skill、cracked_app_expert_skill、real_user_crowdsourcing_skill、risk_governance_design_skill。

## 1. 触发条件

- 关键词触发：群控、云手机、真机农场、模拟器、改机、多开、中控、批量设备、设备团组、账号矩阵、同批启动、抢红包、批量领取、批量爬取。
- 业务场景触发：活动套利、直播红包、裂变拉新、注册小号、刷粉刷赞刷播放、核心资产爬取、私信导流、批量登录/养号。
- 用户意图触发：用户问“群控怎么区分”“是不是群控”“群控怎么查/打/灰度/评估”“群控和协议/真人/破解包怎么区分”。
- 反向不触发：只有高频、IP 聚集、账号多、设备多、单接口异常，但没有调度、路径、关系、收益证据时，不直接触发强群控结论。
- 需要转交给其他 Skill 的情况：
  - 无端行为、接口直达、签名/token/参数异常为主：转 protocol_attack_expert_skill。
  - 官方包采集缺失、包签名/SDK/运行环境异常为主：转 cracked_app_expert_skill。
  - 真人任务平台、人工完成验证、行为离散但任务化为主：转 real_user_crowdsourcing_skill。
  - 设备/账号批量行为可能是商家、达人、MCN、机构运营：先引用 `06_templates/legal_operation_matrix_playbook_v2_3.md` 判断授权主体、账号范围、工具来源、操作人、操作目的、敏感动作和收益主体。

## 2. 输入格式

- 必需输入：业务场景、异常动作、账号/设备/IP/行为/收益中至少两类证据、当前处置目标。
- 可选输入：设备指纹、端侧事件、启动/停止时间、页面路径、点击节奏、邀请关系、提现/支付主体、外部情报、合法运营名单。
- 缺失时可默认假设：若用户只问概念，默认输出群控本质、证据分层和最小补证动作；若未给业务场景，默认按通用群控判断。
- 缺失但不可假设时如何处理：缺少设备/账号/行为/收益任何可 join 线索时，不下定性，只输出补证清单。
- 用户只给模糊问题时的最小可用输入：异常发生在哪个场景、涉及什么动作、是否有账号/设备/IP/收益聚集、是否有端侧行为链。

## 3. 专家认知

- 这类风险的本质：群控不是“很多设备一起动”，而是黑产通过中控系统、云手机、真机农场、模拟器、改机、插件或脚本，批量调度账号/设备完成特定业务目标。判断群控的关键不是“量大”，而是“统一调度”。
- 黑产 / 风险动机：比纯协议更像真实客户端，比真人成本低，可绕过简单频控，可批量完成任务和收益变现，可跨活动、反爬、账号、导流多场景复用。
- 主要风险形态：
  - 云手机群控：云端环境批量运行，环境相似，常见于活动、导流、刷量。
  - 真机农场：大量真实设备托管，脚本/中控调度，常见于高价值活动、反爬。
  - 模拟器群控：低成本环境，指纹相似，常见于注册、小号、激励。
  - 改机群控：修改设备参数，复用设备资源，常见于注册、活动、账号。
  - 插件辅助群控：外挂/辅助功能自动操作，常见于抢红包、私信、爬取。
  - 真人+群控：真人做关键验证，群控批量执行，常见于登录、验证、提现。
  - 账号矩阵群控：多账号在少量环境中被调度，常见于刷量、导流、养号。
- 常见混合形态：群控+协议、群控+破解包、群控+真人验证、群控+小号、群控+收益归集。
- 和相近风险的区别：
  - 协议：协议缺端行为，群控通常有端行为但调度异常。
  - 真人众包：真人众包行为更离散，群控节奏/路径/设备更同质。
  - 破解包：破解包是客户端改造，群控是批量调度，两者可混合。
  - 合法矩阵：合法矩阵有授权和业务合理性，群控以规避平台规则获利。
  - 自然热点：自然热点有随机性，群控有同批、同路径、同收益目标。

## 4. 判断规则

按顺序判断，命中即进入对应分支；证据不足时不得强结论。

1. 如果存在同批启动/停止、路径/节奏/任务顺序高度一致、账号-设备-IP-收益成团，且收益或业务目标集中，则判断为高置信群控，需要输出强证据、反证排除、团组治理。
2. 如果设备环境高度相似、多账号共设备或设备轮换、目标动作集中，但收益链路未闭合，则判断为中高置信群控嫌疑，需要补设备、关系、收益和合法矩阵反证。
3. 如果有真实端行为但目标资产/任务高度一致，且多设备被疑似统一调度，则判断为群控真机/云手机方向，需要组合业务领域 Skill 做资产或活动侧补证。
4. 如果无端侧链路、接口顺序异常、强目标接口直达，则优先切换到协议判断，不因“批量”直接判群控。
5. 如果发现包签名、SDK 缺失、hook/root/改包等客户端完整性问题，则切换到破解包判断，并保留群控混合可能。
6. 如果行为由真人完成、设备分散、节奏离散，但任务平台、教程、奖励链路明显，则切换到真人众包判断。
7. 如果只有高频、设备聚集、账号聚集、IP 聚集、单接口异常，则不得定性群控，只能进入监控、加采、灰度。
8. 如果存在商家、达人、MCN、机构运营可能，先引用 `06_templates/legal_operation_matrix_playbook_v2_3.md` 做合法矩阵前置判断；有授权、有登记、有范围、有审计时不得因批量行为直接判群控；无授权、工具来源异常、操作目的规避平台规则、收益主体异常、设备/路径/收益成团后，再进入群控判断。
9. 如果存在合法运营矩阵、活动自然传播、埋点缺失、测试/蓝军、NAT 等反证，则必须降级或输出多假设分支。

## 5. 证据体系

- 强证据：
  - 同批启动/停止；
  - 设备环境高度相似；
  - 多账号共设备或设备轮换；
  - 页面路径、点击节奏、任务顺序高度一致；
  - 账号-设备-IP-收益形成团组；
  - 收益集中流向少量主体；
  - 发现插件、中控、自动化痕迹。
- 中证据：
  - 同 IP 段集中；
  - 账号画像低质；
  - 任务完成时间窗口集中；
  - 同业务动作重复；
  - 多场景复用同批账号/设备。
- 弱证据：
  - 高频访问；
  - 设备聚集；
  - 账号聚集；
  - 单接口异常；
  - 某活动命中率高。
- 反证：
  - 合法运营矩阵；
  - 商家/达人/MCN/机构授权运营，且账号范围、工具来源、操作人、操作目的和收益主体可审计；
  - 活动自然传播；
  - 埋点缺失；
  - 协议攻击；
  - 真人众包；
  - 公司测试/蓝军；
  - NAT、校园/企业网络。
- 误判来源：热点活动、主播预告、运营投放、家庭/校园/公司 NAT、端侧采集缺失、业务路径改版。
- 最小补证清单：
  - 设备侧：设备指纹、环境相似度、模拟器/云手机/改机特征。
  - 账号侧：注册、登录、活跃、任务、提现链路。
  - 行为侧：页面路径、点击节奏、停留、跳转、任务顺序。
  - 关系侧：IP、代理、地理、邀请、支付、提现、收货关系。
  - 收益侧：券、红包、佣金、提现、刷量收益、权益回收。
  - 边界侧：按 `06_templates/legal_operation_matrix_playbook_v2_3.md` 补合法运营授权、账号范围、工具来源、操作人、操作目的、敏感动作、收益主体，以及协议/破解包/真人众包混合证据。

## 7. 治理闭环

- 查数补证：设备、账号、行为、关系、收益五侧 join，先证明调度和收益闭环。
- 识别策略：设备团组、行为节奏、收益聚集、目标列表重合、同批启动/停止。
- 分层处置：
  - 高准：账号封禁、设备处置、收益冻结、提现拦截、任务权益回收。
  - 中准：限权、限额、延迟发奖、强验证、设备验证、人工审核。
  - 低准：观察、降权、加采、进入监控池、样本回流。
- 灰度策略：先高资损/高价值场景和高置信团组，中置信延迟/限额/验证，低置信只加采。
- 业务协同：降低单用户获利上限、引入冷却期、渠道/活动规则改造、异常收益回收。
- 体验 / 误伤控制：合法矩阵白名单、测试/蓝军标记、热点活动单独口径、NAT 降权处理。
- 指标评估：群控发生量、漏过量、准确率、召回率、误伤率、资损变化、客诉变化、黑产成本、迁移路径、策略稳定性、业务钱效。
- 样本回流和复盘：建样本库、关系图、业务路径图，沉淀跨活动、反爬、账号、导流、支付的标签和策略包。

## 8. 禁止行为

- 禁止因为高频、聚集、设备多直接判群控。
- 禁止因为设备/账号批量行为直接判群控；商家/达人/MCN/机构运营可能先走合法矩阵前置判断。
- 禁止把协议攻击、破解包、真人众包、合法矩阵混为群控。
- 禁止证据不足强结论。
- 禁止只输出“加强监控 / 加强治理”。
- 禁止忽略反证和误判边界。
- 禁止忽略业务影响、体验和灰度。
- 禁止把外部案例当内部证据。

## 9. 质量校验

输出前自查：

- 是否说明“统一调度”这一最小区分点？
- 是否识别业务领域和风险类型？
- 是否区分强 / 中 / 弱证据？
- 是否列出合法矩阵、自然热点、协议、真人众包等反证？
- 是否给出设备、账号、行为、关系、收益五侧补证动作？
- 是否给出高准 / 中准 / 低准分层治理？
- 是否有业务联动、误伤控制、指标评估？
- 是否能沉淀为团组图谱、策略包或测试 case？

不合格时必须补齐后再输出。

## 10. 失败处理

- 信息不足：降级为“疑似群控方向”，列五侧最小补证清单。
- 证据冲突：输出群控/协议/真人众包/合法矩阵多分支，不强行合并。
- 超出 Skill 边界：切换或组合 protocol、cracked app、crowdsourcing、activity、anti-crawler Skill。
- 工具 / API 不可用：说明无法完成哪类 join，改用可替代的账号/设备/收益侧证据。
- 无法判断：明确说“当前不足以判断群控”，并说明缺少调度证据还是收益闭环证据。
