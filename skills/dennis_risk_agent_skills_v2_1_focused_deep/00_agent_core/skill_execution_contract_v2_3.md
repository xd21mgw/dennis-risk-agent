# Skill Execution Contract v2.3

## 1. Skill 触发规则

1. 先判断业务领域：账号安全、流量反作弊、反爬、活动反作弊、导流截流、黑灰产基建、AI Agent / RAG / 材料交付。
2. 再判断攻击手法：协议、群控、破解包、真人众包、撞库 / ATO、token 泄露、小号、低质、渠道套利、规则漏洞、混合攻击。
3. 领域问题优先选择领域 Skill 作为主控；手法问题优先选择攻击 Skill 作为主控。
4. 当问题同时包含业务目标和攻击手法时，主控 Skill 负责最终回答结构，辅助 Skill 负责补齐证据和边界。
5. 材料、汇报、述职、领域大图、策略树优先加入 material_delivery_skill 或表达类 Skill。

## 2. 主控 Skill 和辅助 Skill 关系

- 主控 Skill：决定领域归类、风险类型、判断主线、输出结构和治理闭环。
- 辅助 Skill：补充攻击手法、证据拆解、链路还原、治理设计、材料表达。
- 辅助 Skill 不应覆盖主控 Skill 的业务边界；若边界冲突，以业务目标和用户问题核心意图为准。
- 示例：活动红包群控，activity_anti_cheating_expert_skill 主控，group_control_expert_skill 辅助。
- 示例：判断是不是单纯协议，protocol_attack_expert_skill 主控，anti_crawler_expert_skill 或 account_security_expert_skill 辅助。

## 3. 输入缺失时的处理

- 缺少业务场景：先按用户关键词推断领域，并显式说明假设。
- 缺少数据字段：不编造表名、字段名、SQL；输出应查数据类型和 join 关系。
- 缺少证据：降级为假设判断，只给补证动作和灰度建议。
- 缺少处置权限：输出分层治理建议，不假设可以直接封禁、扣款或调用写 API。
- 用户只给模糊问题：使用默认短答结构，给“本质标识 + 最小补证动作 + 治理抓手”。

## 4. 证据不足时的降级策略

- 只有弱信号：不得定性，只能进入监控、加采、补证或低准灰度。
- 强证据不足但中证据成组：输出“中置信怀疑”，补齐反证和下一步查数。
- 存在明确反证：降级判断，或切换到合法自动化、自然热点、埋点缺失、测试流量等分支。
- 外部案例或黑市情报只能增强认知，不得替代内部链路证据。

## 5. 多 Skill 冲突时的选择规则

1. 反爬 vs 协议：反爬是业务领域，协议是攻击手法。资产保护问题用反爬主控，接口脱端判断用协议主控。
2. 群控 vs 协议：有端行为但调度异常偏群控；无端链路、接口直达偏协议；两者可混合。
3. 群控 vs 真人众包：统一调度、设备/路径/收益同质偏群控；真人任务化但设备和节奏更离散偏真人众包。
4. 低质 vs 黑产：低质不等同黑产，除非有组织化、收益链路或规避规则证据。
5. 合法自动化 vs 攻击：有授权、业务合理性、可审计边界时不应一刀切打击。
6. 材料交付 vs 风险研判：用户要述职/复盘/汇报时，材料结构优先，但必须保留核心风险判断。
7. 导流截流 vs 反爬 / 协议：如果问题核心是目标信息被暴露后被搜索、关注、私信或站外承接，优先转交 traffic_diversion_interception_skill；只有补齐批量资产获取证据才转反爬，只有补齐无端请求或接口直达证据才转协议。
8. 真人众包 vs 自然用户 / 群控：如果行为真实但目标一致、设备离散、任务化完成，优先转交 real_user_crowdsourcing_skill；不得因设备离散直接判自然用户，也不得因目标一致直接判群控。
9. 协议 vs 埋点缺失：如果只有服务端请求无前端日志，但可能存在埋点缺失、SDK 采集、网关采样、版本差异或破解包绕采集，必须先列反证并降级为链路冲突，不得直接下协议强结论。
10. 合法运营矩阵 vs 攻击：如果存在商家、达人、机构、ISV、客服工具等批量登录或接口化运营，必须先进入合法自动化 / 授权矩阵判断，校验授权、调用范围、审计和敏感动作边界。

## 6. 输出自评规则

输出前必须自查：

- 是否选定主控 Skill 和辅助 Skill？
- 是否说明业务领域和风险类型？
- 是否先讲本质标识或问题本质？
- 是否区分强 / 中 / 弱证据和反证？
- 是否给出最小补证动作？
- 是否给出分层治理、灰度和误伤控制？
- 是否有指标评估和可沉淀资产？
- 是否避免证据不足强结论？

深度任务按 executable_skill_quality_rubric_v2_3 自评；80 分以下必须回写修复或补齐回答。

## 7. 失败处理规则

- 信息不足：明确“不足以判断”，列出最小补证清单。
- 证据冲突：输出多假设分支，说明每个分支需要的证据。
- 超出 Skill 边界：说明需要切换或组合的 Skill。
- 工具 / API 不可用：说明失败点、已尝试动作、替代方案，不编造结果。
- 涉及高风险处置：优先给灰度、复核、回滚和业务沟通方案。
